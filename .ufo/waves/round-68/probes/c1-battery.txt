== WHAT THE COUNTER IS ==
The frozen predicate is the shape-only grep '^\| RW[0-9]+ \| ' (row C1, counting-command column). It counts
duplicate ids, fenced example rows, prose and empty evidence cells - the round-67 defect
R67-COUNTER-SHAPE-ONLY (corpus/lessons/round-67-verifier-spotcheck.md section 2). The counter keeps the
frozen anchor and adds the clauses the declaration freezes: distinct ids, non-empty evidence cell, no
fenced-block row, no prose row; and it requires the note's 8-column layout
  id | row-kind | fact | v7.2 anchor | v7.3 anchor | verdict | applicability | evidence
Every clause is a rejection, never a repair: a row that fails prints REJECT with its line, id and reason.

Shape rules (the item's text names two shapes; the note's real header decides):
  - exactly 8 data cells, evidence is the LAST cell - the note's own header at drafts/c1/note.md:28 is
    '| id | row-kind | fact | v7.2 anchor | v7.3 anchor | verdict | applicability | evidence |'.
  - 'NF == 9 when split on |' is the same row without its trailing pipe: '| a | ... | h |' splits into 10
    raw fields and '| a | ... | h' into 9. Both are 8 data cells, so the rule is the data-cell count.
  - a NINTH data cell is rejected (reason=SHAPE). The item's parenthetical calls evidence 'the 4th-from-
    last data cell'; in an 8-column table a ninth cell means an unescaped pipe or an extra column, and
    then the 4th-from-last cell is the verdict, not evidence. Accepting it tests the wrong cell and
    admits a row whose evidence is blank - the false accept M1Mutation's probe found on this counter.
  - subset property: the anchor requires the frozen grep's own spacing (space after the second pipe), so
    the strict count can never exceed the frozen count; it can only be smaller (the red fixtures).

== LIMITS OF THE INSTRUMENT (recorded, not smoothed) ==
1. The evidence cell is only checked for presence; the counter cannot tell a sha pair from the word
   'yes'. Binding evidence to bytes is the reviewer's job (the note's rows cite before/src/SHA256SUMS).
2. Any table block with a separator above counts, wherever it sits in the note; the counter does not
   require the table to live under the heading the declaration names.
3. The header row is not validated against the 8 column names: an 8-cell row under a differently worded
   header still counts. The column NAMES are pinned in the counter docstring and in drafts/c1/E2-report.md.
4. The 8-cell rule means a note that genuinely used nine columns (evidence 4th-from-last) would read 0
   with reason=SHAPE on every row; that reading was rejected because it accepts stray-pipe rows with the
   verdict cell standing in for evidence (v-stray-pipe pins the rejection). Docstring R4 states this.
