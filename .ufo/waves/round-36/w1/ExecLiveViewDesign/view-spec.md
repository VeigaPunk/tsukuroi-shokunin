# C1 live-view specification

## Scope and execution envelope

This is the live-entrypoint view at `6d76fb20f6ecbc940e5c8fff36c74060c885e161`, invoked from the real lane checkout `/home/vgpnk/Projects/shokunin/tsukuroi-shokunin` (the checked-out `HEAD` was that revision). It is not the `livefive` probe or a probe receipt. All five tools exited 0 in the captured run; the observation being recorded is whether any child exec inherited any synthetic canary.

The rerunnable harness is `run-live-view.sh REVISION RUN_ID`. Example:

```sh
/usr/bin/bash /home/vgpnk/Projects/shokunin/tsukuroi-shokunin/.ufo/waves/round-36/w1/ExecLiveViewDesign/run-live-view.sh 6d76fb20f6ecbc940e5c8fff36c74060c885e161 base-next
```

Each run makes a fresh `/tmp/tsukuroi-r36-liveview.*` tree and launches tools under `env -i`: private per-tool `HOME`/`TMPDIR`, neutral Git configuration, `PATH=<seat>/wrappers:/usr/bin:/bin`, and ten newly random `TSQ_<8 hex>` variables. The only values in the captured environment are these synthetic canaries and non-secret harness settings; no ambient credential/session values are read or copied. `capture/<RUN_ID>/context.txt` records the generated names. The wrapper scripts `git`, `python3`, `bash`, and `sh` record `/proc/self/environ`, pid/ppid, and argv, then exec the real binary. The Python wrapper uses `exec -a <wrapper-path> /usr/bin/python3` so `sys.executable`-based children remain interposable. `strace -f -v -s 8192 -e trace=execve` supplements the wrappers for direct absolute paths and commands whose child PATH is reset. This was necessary because `check-report-receipts.py` sets child PATH to `/usr/bin:/bin` (source lines 314-322), and other targets call `sys.executable` or `/usr/bin/bash` directly. The trace receives only the controlled environment.

`run-receipt.py` selects `/fast/scratch/hyaku` when it exists (source lines 75-78; it did on this host). The harness masks that path only inside a private mount namespace by bind-mounting a directory inside the mktemp scratch tree, then drops back to the invoking uid before running the tool. Its clone/home and all temporary files therefore stay in mktemp scratch; `--out` stays in this seat's capture directory. The namespace ends with the invocation.

## Evidence and rerun interpretation

`capture/base-final-6d76fb20/dev-run.jsonl` is one JSON object per target with its exit code, top-level wrapper pid, `canary_leaked_to_child`, and child-program groups/counts plus canary names. Raw `execve` logs, stdout/stderr, wrapper `/proc/self/environ` logs, the exact command manifest, and receipt are beside it. The summary excludes the top-level launcher pid; a child is marked leaking only when its exec environment contains one or more of the ten names. On a fixed-dict after state the root launcher still receives the test canaries, but they are not counted as child leakage; `strace` remains able to record direct/non-PATH child execs.

The two tools with intrinsic scratch clone/export behavior above are not represented as direct execution of every nested script from the checkout; their real-lane inputs and scratch-only writes are preserved and their implementation behavior is described in the read-only table. There were no package installs, system updates, production-file edits, or writes to the lane checkout in this view.
