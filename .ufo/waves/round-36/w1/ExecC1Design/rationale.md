# C1 five-tool child-environment patch rationale

Base: `6d76fb20f6ecbc940e5c8fff36c74060c885e161`. The declaration's C1 text requires fixed child dictionaries containing `PATH=/usr/bin:/bin`, `LC_ALL=C`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`, plus settings already fixed by each builder and the private run settings. The proposed unified patch is `c1-five-tools.diff`.

## Per-tool rationale

- **`tools/check-revision-binding.py`** — `clean_env()` becomes a literal fixed dictionary. It preserves the existing `GIT_OPTIONAL_LOCKS=0`, `GIT_PAGER=cat`, `LC_ALL=C`, `GIT_CONFIG_NOSYSTEM=1`, and `GIT_CONFIG_GLOBAL=os.devnull` values while adding the declared PATH. Existing calls through `clean_env()` keep their argv. The embedded stub's Git subprocess inherits the fixed environment of the stub launched with `env=clean_env()`; it does not read `os.environ` itself. The trust-boundary text is corrected to describe fixed child environments rather than GIT-only filtering.
- **`tools/check-report-receipts.py`** — `find_receipts()` builds the dictionary directly instead of copying then updating ambient `os.environ`. It retains `GIT_CONFIG_SYSTEM`, the private `HOME`/`XDG_CONFIG_HOME`, fixed PATH, and the ceiling computed from the scratch directory's parent. The `run_git()` command and stdin/stdout behavior are unchanged.
- **`tools/score-census-handoff-r32.py`** — one `child_env()` supplies the live census processes and the scorer's two direct Git spawns (`git archive` and default-HEAD `git rev-parse`), which previously inherited the launcher's ambient environment. The plain live view starts with the fixed dictionary; the filtered view still adds only its explicit `TSUKUROI_JOURNALCTL` wrapper. The existing fixture-only `census_env()` remains unchanged.
- **`tools/mutants-btrfs-space-r30.py`** — replace the GIT-prefix-filtered copy with the fixed PATH/locale/Git-config dictionary. The interpreter, counter arguments, time limit, and output handling remain unchanged; its opening note now says the counter receives a fixed environment.
- **`tools/run-receipt.py`** — `env()` starts from a fixed dictionary and preserves the existing global/system Git-config values. `env(home)` still adds the existing private `HOME` and `XDG_CONFIG_HOME`; it also sets the declaration-required ceiling to `dirname(abspath(home))`. `root` and `home` are created under the same `parent`, so this is that run's scratch parent.

### Baseline/declaration discrepancy

The frozen source at `tools/run-receipt.py:36-43` does **not** currently set `GIT_CEILING_DIRECTORIES`; it only adds `HOME` and `XDG_CONFIG_HOME` when `home` is passed. The declaration explicitly requires the ceiling for `run-receipt.py`, so the diff includes it as a contract-required addition. That value is not preservable from the baseline, and adding it can change Git's upward repository search. Thus the patch cannot simultaneously satisfy a strict “no behavior change” rule and the declaration's run-receipt ceiling requirement. This is the only identified source/declaration mismatch; L1 should retain the declaration-required setting only with that caveat visible.

## Ambient-read risk table

The frozen-source scan found no direct `os.environ`, `os.getenv`, or `environ[...]` reads outside the five builders, and no environment-backed argparse defaults. The indirect temp-directory variables below are read by Python's `tempfile` when the **parent harness** chooses its own scratch location; the explicit child dictionaries do not forward them.

| Tool | Ambient names read outside builder | Why dropping them from children is bounded / residual risk |
|---|---|---|
| `check-revision-binding.py` | `TMPDIR`, `TEMP`, `TMP`, indirectly through `tempfile.TemporaryDirectory` (three call sites, including self-test fixtures). CLI values and `sys.executable` are not environment-variable reads. | These names choose the parent harness's scratch root; sandbox paths are then passed by argv/`cwd`. Child tools fall back to the platform's normal temp directory. `[unk]` whether every nested tool tolerates a host-specific unwritable default temp directory; no runtime check was run. |
| `check-report-receipts.py` | `TMPDIR`, `TEMP`, `TMP`, indirectly through `tempfile.TemporaryDirectory` in `main`. | They select the parent scratch location; the computed private HOME/XDG and ceiling remain explicit, and Git gets explicit `-C lane`/revision/path arguments. Removing temp variables from Git children can only affect their temporary-file location, not the receipt selection predicate. |
| `score-census-handoff-r32.py` | `TMPDIR`, `TEMP`, `TMP`, indirectly through `tempfile.mkdtemp` when `--scratch` is absent. `--seed` defaults to `os.urandom`, not an environment variable. | Scratch paths are passed explicitly. The live census script's probe overrides remain intentionally absent in the plain view; the filtered view adds its wrapper explicitly. A source scan of `tools/tsukuroi-census.sh` found no `TMPDIR`/`HOME` references; fixture executions continue using their separate explicit `census_env()` with private `TMPDIR`. |
| `mutants-btrfs-space-r30.py` | `TMPDIR`, `TEMP`, `TMP`, indirectly through `tempfile.mkdtemp` in `main`. | The child counter gets explicit `--tree` and `--base-sources` paths and an explicit interpreter. These variables choose the parent battery's work root; the child otherwise uses the platform's default temp location if needed. `[unk]` whether a nested counter operation depends on a custom writable temp path; not runtime-tested here. |
| `run-receipt.py` | `TMPDIR`, `TEMP`, `TMP`, indirectly through `tempfile.mkdtemp` only when `/fast/scratch/hyaku` is absent (otherwise the explicit parent is used). CLI arguments and `sys.executable` are not environment-variable reads. | The launcher still chooses its own scratch parent; child HOME/XDG and the ceiling are explicitly derived from private paths. A child that creates unrelated temporary files may use the platform default instead of the launcher's custom temp directory; this is a scratch-location risk, not a revision/tool input. |

The source-level safety argument is limited to these input boundaries; child scratch-path behavior was not executed. No builds, tests, linters, or formatters were run. The only check requested/performed was the archive-based `patch --dry-run` recorded in `patch-dry-run.txt`.

LSP was unavailable in the provided tool inventory; no empty/cold LSP response was treated as absence. No tools were installed or updated.
