# C1 falsification item 3/8 — S4 `os.get_exec_path()` PATH invisibility

Axes: operability; C1:S4. Independent counter attack, scoped only to ambient-PATH copying via `os.get_exec_path()`.

## Finding

**Counter survives as an invocation-coverage vulnerability; no new experiment was run in this seat.** The round-36 evidence already supplies both an observed counterexample shape and its specific blind spot. In `.ufo/waves/round-36/w2/W2RevCounter/W2RevCounter.md:164-187`, variant `zzv-gpexec.py` copies PATH using `os.pathsep.join(os.get_exec_path())`, then invokes `/usr/bin/git --version` by absolute path. The recorded table says untraced: zero records/no leak; source: zero findings/no leak; names/quiet: leak. The report attributes these blind channels to the absolute-path exec bypassing wrappers and `os.get_exec_path` being absent from `OS_AMBIENT`.

The committed probe observation is repeated in `W2RevCounter.md:263` (variant 6). This demonstrates channel blindness, but **does not itself falsify the all-channel set-level predicate**: names and quiet catch this exact variant, so it reads 2 leaks, not 0. A falsifying variant must also avoid those dynamic observations, e.g. have the leaked PATH carried only to an absolute-path child while avoid any-name matches and quiet channel path observability; evidence currently does not establish that the frozen claim predicate can be met that way.

Related frozen counter catalogue `.ufo/waves/round-36/w2/W2MutPathCopy/W2MutPathCopy.md:61-71` records a concrete coverage mechanism: the `measure-update-recheck.py --selftest` invocation does not exercise the mutated live-mode builder; its child gets fixed `/usr/bin:/bin`, hence `os.get_exec_path()` sees no injected PATH. Its frozen claim reading is all channels clean (`:49-59`), while the live-mode surrogate exercises the builder and records PATH leakage (`:73-94`). This is strong testable prediction for the analogous target shape, but is a distinct target and not proof that S4 target-set predicate is satisfied.

## Minimal discriminating test / falsifier

Use the frozen probe bytes and target invocation (not selftest if that bypasses the relevant builder). Construct a mutant that sets child `PATH = os.pathsep.join(os.get_exec_path())`, passes that value only to an absolute-path child (so no PATH lookup wrapper is involved), and otherwise preserves successful control behavior. Ensure injected names/value tokens are not independently carried in any other observable child environment. Record all four channel rows plus final summary and exit status.

- **Counterexample confirmed** only if control is successful, mutant reaches the absolute-path child with PATH containing the injected directory/token, yet the exact frozen predicate outputs `leaking_pairs: []`, `harness_errors: []`, exit 0. Include child env evidence proving the leak and probe hash/version/revision/argv.
- **S4 ruled out for this predicate** if the relevant builder is demonstrably exercised and the mutant’s PATH leak yields a nonempty `leaking_pairs` (or a harness error/nonzero exit), with the leaking channel and evidence identified. A zero untraced record alone is not a falsifier or proof of cleanliness.

Prior direct receipt `W2RevCounter/variants.json` lines 2-53 records the original gpexec variant as two leaks (names+quiet); `variant-skip.json:1-50` is the separate skip-work mutation and must not be conflated with this PATH attack.
