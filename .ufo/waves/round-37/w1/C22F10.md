## Verdict

The correction's direction is grounded, but the declaration is not yet precise enough to test on its own. SCORECARD.md:1910-1914 asks for a “third-state (`-n`) row distinguishing `-F` truncation from unchanged `-N` output.” It does not state the behavior that constitutes truncation, its comparison baseline, or safeguards against depending on journal-specific order/content. The note's present row at `corpus/knowledge/journalctl-v262-field-filter-r36.md:41` classifies `-n` with other non-limiters and says only that `-F`/`-N` “WORK”; line 48 says `-F -n 1` succeeds but does not document what output is emitted or compare `-N` output. The verifier re-ran exactly that distinction: `journalctl -F PRIORITY -n 1` prints one value, while `journalctl -N -n 1` prints the complete field-name list unchanged (round-36-verifier-spotcheck.md:59-65). Thus this is a real uncovered observation, not a correction to the scope-rejection predicate.

### Evidence and strongest counterexample

- `corpus/lessons/round-36-verifier-spotcheck.md:63` records live commands `journalctl -F PRIORITY -n 1` → WORK (prints `5`) and `journalctl -N PRIORITY` → extraneous-argument error. The `-N PRIORITY` command is misuse, not a valid output-comparison control; the note also distinguishes this misuse at `journalctl-v262-field-filter-r36.md:17,46`. The correction should compare bare `-N` with valid `-N -n 1`, not use `-N FIELD`.
- Reproduced read-only on `/usr/bin/journalctl` reporting `systemd 262 (262-1-arch)`, 2026-10-25: `--no-pager -F PRIORITY` returned rc 0, six newline-delimited values; adding `-n 1` returned rc 0 and one value (`2` on this capture). `--no-pager -N` and `--no-pager -n 1 -N` both returned rc 0 and identical stdout: 160 lines, 2735 bytes, SHA-256 `7991f1df402d9d9a4c405e43f348c14c2b173cbf6335071fa828e3b8414de6c9`. ## Test vectors for a correction/checker

Use a fixture journal with at least three distinct values for a chosen field and a separately enumerated field-name list; preserve the fixture's base output and compare outputs rather than pinning ordering or a host's values.

**Should pass (corrected note/checker accepts):**

1. Unbounded control: `journalctl --directory=<fixture> --no-pager -F PRIORITY` emits the fixture's full distinct-value set. Record rc/stdout/stderr.
2. Truncation: same command plus `-n 1` emits exactly one listed value, which is a member of the unbounded result; plus `-n 2` emits at most two values. Assert rc 0 and no scope-rejection diagnostic. This describes output count, not a promise about value order.
3. `-N` unchanged: compare complete stdout bytes from `journalctl --directory=<fixture> --no-pager -N` and `journalctl --directory=<fixture> --no-pager -n 1 -N`; assert equality (and rc 0 for both). Include a fixture with >1 field name so the test would detect accidental truncation.
4. Scope control: `-b 0 -F PRIORITY` continues to exit 1 with the exact scope-rejection diagnostic, while `-n 1 -F PRIORITY` succeeds. This ensures documenting `-n` does not wrongly reclassify it as a scope limiter.

**Should fail (corrected note/checker rejects):**

1. A purported correction/checker accepts `-F -n 1` while its captured result contains the full three-plus-value fixture output, or fails to compare it to unbounded `-F`.
2. It claims `-N -n 1` is truncated, or accepts a fixture where that stdout differs from bare `-N` (such as only one field name being emitted).
3. It treats `-n` as a scope filter, expects the 84-byte scope diagnostic for `-n 1 -F`, or accepts successful `-b 0 -F` as normal operation.
4. It hard-codes a live host's first field value/order (e.g. expects the first `PRIORITY` to be `2` universally), or uses invalid `-N PRIORITY` as the comparison case.

## Smallest safe correction

Replace the vague third-state wording with an explicit paired observation: with `-F FIELD`, `-n N` caps the number of distinct values printed (rc 0; no scope-rejection error), while with `-N`, `-n N` leaves the complete field-name output unchanged. Cite both command receipts, including valid bare `-N` controls; define comparison/count assertions using a fixture with multiple known values/names and avoid order- or host-specific literals. Keep this strictly separate from the 15-term scope predicate and the action-override correction.
