## 2. Verdict: target is real, but the requirement as recorded is under-precise

**It is real and testable.** Fresh read-only probes on this host today prove both halves:

| # | Command (LC_ALL=C, --no-pager) | Result |
|---|---|---|
| P1 | `-F PRIORITY` | exit 0; 6 lines: `2 4 5 6 7 3` |
| P2 | `-n 1 -F PRIORITY` | exit 0; stderr empty; 1 line: `2` (stable ×3) |
| P3 | `-n 1 -o json --output-fields=PRIORITY` (newest entry) | PRIORITY `6` at first run, `4` at rerun — **never `2`** |
| P4 | `-F _BOOT_ID` | exit 0; `0a3785aac7104585a914f6cda41795a7`, `7ab69ee4149c4811a3faf6c08c9d119b` |
| P5 | `-n 1 -F _BOOT_ID` | exit 0; **`0a3785…` only — the OLDER boot id, not the newest (`7ab69e…`)** |
| P6 | `-n 2 -F _BOOT_ID` | exit 0; both ids, same order as P4 |
| P7 | `-n 2 -F PRIORITY` | exit 0; `2 4` = first two lines of P1 |
| P8 | `-n 0 -F PRIORITY` | exit 0; empty stdout |
| P9 | `-N -n 1` vs `-N` | both sha256 `7991f1df402d9d9a4c405e43f348c14c2b173cbf6335071fa828e3b8414de6c9` — byte-identical |

P2/P5/P6/P7 prove the mechanism: `-n N` with `-F` prints the **first N lines of the full unique-value enumeration** (prefix truncation), independent of entry recency. P5 is decisive: an old-boot id cannot be "the values of the newest entry", so any reading of "truncated" as "subset of the newest entries" is false.

Source-confirmed (`journalctl-misc.c`, systemd v262 tag, opened 2026-10-25 via `https://raw.githubusercontent.com/systemd/systemd/v262/src/journal/journalctl-misc.c`):
- `action_list_fields()` `:189-229`: `sd_journal_query_unique(j, arg_field)` `:207` over the whole journal, then the print loop breaks at `:216`: `if (arg_lines >= 0 && n_shown >= arg_lines) break;` — literal line truncation of the enumeration output.
- `action_list_field_names()` `:231-246`: `SD_JOURNAL_FOREACH_FIELD` `:242` — **no `arg_lines` reference at all**; `-N` ignores `-n`. Matches P9.
- Guard stays `journalctl.v262.c:958-960`; `-n` (`arg_lines`) is absent from the 15-operand predicate `journalctl-filter.v262.c:26-43` (already cited by the note).

**Precision gaps to attack (what makes the recorded requirement under-precise):**

1. **"Truncated" is ambiguous.** The recorded phrasing doesn't say *what* is truncated. The correct, source- and probe-proven property is: output = first N lines of the unbound `-F FIELD` enumeration (prefix), not "values of the newest N entries", not "a random subset". A correction that says only "value list truncated" would leave the wrong mental model (newest-entry subset) unfalsified.
2. **The stale note already half-states it.** `:48` says "-n limits how much is printed" — correct — yet the table `:41` still reports plain WORK. The correction's testable deliverable is a distinct table row + falsifier entry, not new prose.
3. **"Unchanged -N" must be a within-run pair equality, not a fixed digest.** R36's saved `-N` sha256 was `3480f2aa…` (2882 bytes); today's is `7991f1df…` — the field universe evolves. The invariant is `sha256(-N -n 1) == sha256(-N)` in the same run; any pinned constant would rot.

## 4. Proposed test vectors

### Should-pass (after the correction lands — on systemd 262)
- **V-P1 acceptance:** `LC_ALL=C journalctl --no-pager -n 1 -F PRIORITY` exits 0, stderr empty, no 84-byte rejection sentence. *[observed]*
- **V-P2 truncation:** stdout(V-P1) < stdout(`-F PRIORITY`) measured in the same invocation pair (byte counts may change across journal states; compare within pair). *[observed]*
- **V-P3 prefix (the discriminator):** `-n 1 -F _BOOT_ID` equals the **first line** of `-F _BOOT_ID` and is **not** the newest boot id. *[observed; P4/P5]*
- **V-P4 N-generality:** `-n 2 -F _BOOT_ID` equals the first two lines of `-F _BOOT_ID`. *[observed]*
- **V-P5 edge:** `-n 0 -F PRIORITY` exits 0, empty stdout. *[observed]*
- **V-P6 -N within-run invariance:** `sha256sum` of `-N -n 1` equals that of `-N` in the same run. *[observed]*

### Should-fail (would falsify the corrected claim)
- **V-F1:** `-n 1 -F PRIORITY` exits 1 or prints the scope-rejection sentence (i.e. `-n` becomes a scope option).
- **V-F2:** stdout(`-n 1 -F PRIORITY`) byte count ≥ stdout(`-F PRIORITY`) (no truncation).
- **V-F3:** `-n 1 -F _BOOT_ID` prints the newest boot id while the full list begins with another id — would falsify the prefix reading (entry-window semantics instead) and must fail if the corrected claim asserts P3.
- **V-F4:** `-n 2 -F _BOOT_ID` prints anything other than the first two lines of the full enumeration.
- **V-F5:** `-n 0 -F PRIORITY` prints anything.
- **V-F6:** `-N -n 1` sha256 ≠ `-N` sha256 in the same run.
- **V-F7 (version drift):** any of V-P1–V-P6 on a systemd major other than 262 (recheck trigger "on-release" already exists in the note `:5`).
