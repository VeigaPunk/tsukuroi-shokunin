## The five named questions
1. **Does `path :` (blank before colon) fail config_get_value? YES.** config.c:799-801 requires the colon *directly* after the key: `if (!strncasecmp(&config[i], key, key_len) && config[i + key_len] == ':')` plus `if (i && config[i - 1] != SEPARATOR) continue;` with `#define SEPARATOR '\n'` (config.c:25). `path :` matches the 4 chars but `config[i+4]` is `' '`, not `':'` — no match, and no later offset matches. Same for `module_path\t:`; `kernel-path:`/`path2:` fail the char class. KEY-SPACING is source-supported. Gate `split_key` (check-limine-pins.py:58-68) encodes the same predicate.
2. **Does `hdd()`/`guid()` with empty root fail resolution? YES.** `hdd()`/`odd()` → `parse_bios_partition("")` hits `if (loc[i] == 0) return false;` (uri.c:108-110 region) → NULL; `guid()`/`uuid()` → `string_to_guid_mixed/be("")` fail → NULL (uri.c:197-215); `fslabel()` → `volume_get_by_fslabel("")` → NULL. EMPTY-ROOT-RESOURCE is supported, with one caveat (finding F1: `bootx()`/`Boot2()` are `URI_ERROR("Resource `%s` not valid.")` → `panic(true, …)` — Limine halts; the gate models it as LP-UNRESOLVED, a safe under-approximation, frozen R4).
3. **Is a hash-format error checked before resource dispatch? YES.** The 128-hex validation is *inside* `uri_resolve` (uri.c:88-104: `if (strlen(uri + i) != 128) URI_ERROR(...)` + per-char range check), and `uri_open` only dispatches after `if (!uri_resolve(uri, ...)) return NULL;` (uri.c:344-347). FORMAT-BEFORE-RESOLVE draws only resources that have `(` and `):/`, so the hash check is genuinely reached first. Supported.
4. **Is a `--conf` directory CANNOT-EVALUATE in the gate contract? YES.** R7 (frozen): "An unreadable --conf (absent, a directory, or unreadable for any OS reason) -> CANNOT-EVALUATE rc 2 with an empty pin list"; gate check() catches `OSError` from `open()` (IsADirectoryError) → rc 2, pins []. This is gate contract, not a Limine rule — the battery docstring says so. CONF-UNREADABLE matches the contract.
5. **Does `hash_mismatch_panic` match case-insensitively? YES, key and value.** menu.c:1711-1712: `config_get_value(NULL, 0, "HASH_MISMATCH_PANIC")` (strncasecmp inside config_get_value) then `hash_mismatch_panic = hash_mismatch_panic_str == NULL || strcasecmp(hash_mismatch_panic_str, "no") != 0;` — value must equal `no` case-insensitively; any other value (`off`, `false`, `0`, `nope`, …) stays panic. `index 0` = FIRST occurrence (config_get_value skips with `if (index--) continue;`). Secure Boot override: menu.c:1713-1715 `if (secure_boot_active) hash_mismatch_panic = true;`. PANIC-KEY-CASE, PANIC-NON-NO, PANIC-FIRST, PANIC-METADATA, SECUREBOOT, SB-FLAG-ZERO all supported.

## Code review of the new machinery — findings

**F1 (LOW, docstring fidelity; frozen rule, no re-scope):** ROOT-ON-BOOT/EMPTY-ROOT-RESOURCE docstrings state the LP-UNRESOLVED outcomes as Limine rules, but Limine is more permissive/brutal: `uri_boot_dispatch` with non-empty `s_part` does `strtoui` (only >256 errors) and `volume_get_by_coord(boot_volume->is_optical, boot_volume->index, partition)` — `boot(2):/x` *resolves* whenever partition 2 exists on the boot disk (uri.c:249-270); `tftp()` with empty root proceeds to `tftp_open` (uri.c:234-246); unknown resources `bootx()`/`Boot2()` reach `URI_ERROR("Resource `%s` not valid.")` which for a non-optional resource is `panic(true, …)` — a halt (uri.c:19-25, 355-360). The gate's blanket LP-UNRESOLVED/CANNOT-EVALUATE is the honest "cannot evaluate this pin here" and is frozen R4; the deviation is only in the family docstrings presenting it as Limine behaviour. Proposed patch (docstring-only, candidate or successor): reword the two docstrings to "R4 (gate contract): any resource/root the gate cannot resolve to --esp is LP-UNRESOLVED; Limine itself may resolve boot(N) on a real partition and panics on unknown resources".

**F2 (LOW, evidence gap, frozen citations honest):** the optional-key mechanism is real in the pin set (uri.c:18-26 `optional_resource`, `URI_ERROR` prints instead of panics when optional; uri.c:693-710 `uri_open_optional`), and CONFIG.md:152-156 documents skip-for-wallpaper/font — but **no pinned source calls `uri_open_optional`** (menu.c contains no `wallpaper`/`term_font` reference at all; the callers live in unpinned Limine files, e.g. terminal/gfx code). OPTIONAL-HASH-FORMAT and OPTIONAL-SKIP therefore rest on CONFIG.md + mechanism, not a pinned call path. Proposed fix for a future freeze: add the caller file to `before/src/`; nothing to change in the battery.

**F3 (LOW, frozen r87 R2 modelling, named by NO-PAREN):** the gate ignores non-URI values ("not a pin and is ignored"), but in Limine `uri_resolve` returning false makes `uri_open` return NULL, i.e. the *entry* fails to load — a conf whose only kernel paths are URI-less would still boot-report HEALTHY from the gate. The pinned set does not contain the menu/protocol failure path, so the "ignored" reading is an unpinned extrapolation frozen into R2. Report-only; if the lane ever re-opens R2, a `LP-INVALID`-style status is the candidate shape.

**F4 (INFO, dead code):** `Case.panic_value` / `set_panic`'s `if c.panic_value is None` bookkeeping (limine-pin-battery-r88.py:216-220) is write-only — `mismatch_consequence` and `r8_ok` read `r1_panic()` exclusively. Harmless; safe to delete in a successor.

**F5 (INFO, negligible flake margin):** `build()` (limine-pin-battery-r88.py:709-731) draws the ESP dir name and the conf file name from the same rng; a coincidental equal draw would crash `os.makedirs(esp)` and void a run as counter-error. Probability ≈1e-8 per case (≥37^5 space, one draw each). No action needed; a `assert esp_name != conf_name` loop would remove it.

**Verified non-defects (explicitly checked):**
- `r1_panic()` (battery:130-143) ≡ gate `split_key` (gate:58-68): both strip CR + leading/trailing blanks, skip `#`-first lines, take `[A-Za-z_]+` (ASCII-guarded) then a direct `:`, lstrip blanks from the value; first-match semantics identical. Gate additionally `sanitize()`s for output only.
- `r8_entries()` (battery:145-153) ≡ gate entry tracking (gate:131-133): same `lstrip("/").lstrip("+").strip()` label, same `label or cur` empty-label retention, same None before the first entry line; `r8_ok` checks optional-field *when present* and passes when the gate omits `entry`/`hash_mismatch_panic` (R8 "MAY").
- `run_gate` (battery:749-770): passes `--secure-boot-enforced` only for `sb` ("1") or explicit `sbflag` ("0" from SB-FLAG-ZERO or the 30% build() draw — semantically identical to absent per R7, and `mismatch_consequence` keys off `c.sb`, not the flag, so the random draw cannot change an expectation); requires gate *exit code* AND JSON `rc` field to both equal the expected rc, plus verdict, sorted (line,status,consequence), and r8_ok — the eight one-field lie wrappers are each deterministically caught by specific families (MISSING, SB-FLAG-ZERO/HOST-SHAPE prompt, UNRESOLVED/EMPTY-ROOT verdict, PANIC-METADATA/HOST-SHAPE panic-line, etc.).
- CASES_PER_FAMILY=4 accounting: `met` requires every roster family 4/4 passed AND `len(log) == 38*4`; `FAMILIES != FAMILY_ROSTER` exits 2 before any run (r87-R1 lesson closed); the plan is shuffled per run from the literal roster.
- LP-MISSING via `files.pop` before build() writes; LP-HASH-FORMAT lengths {127,129,64,0} and non-hex chars {g,x,z,G,space,-,_} all validated as bad by uri.c:88-104; `hashfmt` on a non-HASH-FORMAT status is only ever the case-preserving `upper()` transform (HASH-UPPER), consistent with case-insensitive comparison (gate `got == h.lower()`; uri.c:100-104 range check + byte-wise `memcmp` after `digit_to_int`).
- FIRST-URI-SEP/PAREN-PATH filenames (`N1):/N2.efi`, `N(n).efi`) parse to the intended paths under both `parse_uri` (first `(`, first `):/`, last `#`) and uri.c:45-100; fixtures and gate agree on the POSIX spelling.
