    20	## Description
    21	
    22	**Limine-Snapper-Sync** integrates **[Limine](https://github.com/limine-bootloader/limine)** bootloader with **[Snapper](https://github.com/openSUSE/snapper)**,
    23	synchronizing snapshot boot entries with Btrfs snapshots and updating the bootloader configuration accordingly.
    24	
    25	<details>
    26	<summary>What it does</summary>
    27	
    28	* **Adding Snapshots:**<br>
    29	When a Snapper snapshot is created, a snapshot boot entry with its matching kernel versions is added to Limine.
    30	
    31	* **Deleting Snapshots:**<br>
    32	Deleting a Snapper snapshot also removes the related snapshot boot entry and kernel files.
    33	
    34	* **Restoring Snapshot:**<br>
    35	The tool provides `rsync`, `replace` or `snapper` (`opensuse`) to restore a selected snapshot with matching kernel versions.
    36	
    37	* **Backup Entry:**<br>
    38	After restoring, a "backup" snapshot entry is added to Limine, allowing you to revert or remove it later.
    39	
    40	* **Boot Files Repair:**<br>
    41	Automatically detects and repairs a corrupted bootable snapshot file by replacing it with a matching healthy file
    42	during new snapshot creation.
    43	Additionally, it logs hardware issues if two hashes of the same bootable file don’t match.
    44	
    45	**Note:**
    46	- Does **not** generate kernel boot entries for newly installed kernels. Use [Entry Automation for Limine bootloader](https://gitlab.com/Zesko/limine-entry-tool) for that functionality.
    47	</details>
    48	
    49	<details>
    50	<summary>Why it was created</summary>
    51	
    52	**Limine-Snapper-Sync** was created to provide a faster, more efficient, and easier-to-manage snapshot boot solution for Limine:
    53	
    54	* **Faster encrypted snapshot boot:**
    55	    - Bootable files (kernel, initramfs/initrd, or UKI) are stored outside a fully encrypted partition,
    56	      allowing faster decryption and boot times.
    57	    - Allows Plymouth graphical password prompts during boot for a more polished user experience.
    58	* **Multiple boot support:**
    59	    - Each mutable Linux distro can have its own snapshot entries in separate boot submenus,
    60	      making it easier to select OS or snapshot entry.
    61	    - Allows switching between A/B systems by creating a new subvolume with its own machine-ID and `subvol=` boot parameter.
    62	* **Flexible and efficient design:**
    63	    - Avoids reliance on third-party drivers (e.g., filesystems, LUKS2, different encryption algorithms, LVM, etc.);
    64	      all of this is handled by kernel, initramfs, or UKI, improving compatibility, performance and reliability.
    65	* **Instant snapshot updates:**
    66	    - Automatically updates snapshot boot entries in real time without scanning all subvolumes or snapshots.
    67	* **Rollback and "Backup" snapshot support:**
    68	    - Allows quick system restore and adds a "backup" snapshot boot entry.
    69	* **Checksum correction & faulty RAM detection:**
    70	    - Detects faulty RAM or CPU cache by comparing two independently generated hashes.
    71	    - Automatically corrects checksum errors by rechecking up to 3 times on mismatch.
    72	    - If mismatches occur more than 3 times, Btrfs root and home are set to read-only to prevent further corruption.
    73	</details>
    74	
    75	<details>
    76	<summary>Limitations</summary>
    77	
    78	* **Old snapshots before installing the tool**:
    79	    - Older snapshots will not be added to Limine because the required kernel files are not included in the Btrfs snapshots.
    80	* **Limited Btrfs layout support:**
    81	    - Supports any Snapper-managed Btrfs layout, but not arbitrary Btrfs layouts without Snapper.
    82	
    83	</details>
    84	
    85	#### 5 commands, each without options:
    86	
    87	* `limine-snapper-sync` updates Limine snapshot entries with current Snapper snapshots.
    88	* `limine-snapper-list` displays all available snapshots in Limine's boot menu.
    89	* `limine-snapper-info` shows details about versions, total bootable snapshots, kernel verification status.
    90	* `limine-snapper-restore` restores a selected snapshot to your system.
    91	* `limine-snapper-remove <ID 1>..<ID 2>` removes snapshot boot entries to free up space on the boot partition.

   135	## Requirements
   136	
   137	* A FAT32 boot partition of at least **4 GiB** is recommended, depending on how many snapshots and kernel versions you keep.
   138	  - **Note:** NVIDIA drivers and DKMS modules can use over 300 MiB per kernel version. Your boot partition should be large enough for future kernels and snapshots without resizing.
   139	* Limine version **8 or newer**
   140	* `snapper` and `btrfs-progs`
   141	* Standard coreutils: `cp`, `mv`, `rm`, `sha256sum`
   142	* Standard util-linux: `logger`, `mount`, `umount` and `flock`
   143	* `gradle` and GraalVM 25 (build-time only)

   148	## Installation:
   149	
   150	### Arch Linux:
   151	
   152	**🔄 Switching from GRUB, systemd-boot, or rEFInd to Limine?**<br>
   153	**Tip:**
   154	Limine setup allows you to keep your existing EFI bootloader as a fallback.<br>
   155	It won’t overwrite your existing EFI bootloader unless you explicitly choose to replace it.<br>
   156	Just follow the **easy setup with `limine-entry-tool`** below if you are unsure.
   157	
   158	<details>
   159	<summary>🚀 Easy setup with limine-entry-tool</summary>
   160	
   161	1. Choose one of the two initramfs integration packages for [limine-entry-tool](https://gitlab.com/Zesko/limine-entry-tool):
   162	   * For **Dracut** users: Install [limine-dracut-support](https://aur.archlinux.org/packages/limine-dracut-support/)
   163	   * For **mkinitcpio** users: Install [limine-mkinitcpio-hook](https://aur.archlinux.org/packages/limine-mkinitcpio-hook/)
   164	     1. Manually add `btrfs-overlayfs` after `filesystems` in `HOOKS=(...)` in `/etc/mkinitcpio.conf`<br>
   165	        (**Note:** For systemd hooks, use `sd-btrfs-overlayfs`, since `btrfs-overlayfs` is incompatible.)
   166	     2. Run `limine-update` to rebuild the initramfs.
   167	2. Install [limine-snapper-sync](https://aur.archlinux.org/packages/limine-snapper-sync/) from AUR.
   168	3. Enable automatic syncing:
   169	```bash
   170	systemctl enable --now limine-snapper-sync.service
   171	```
   172	4. (Optional) Install `snap-pac` to trigger Snapper to create snapshots during system updates.
   173	
   174	**Tip:** After changing your config in `/etc/default/limine`, just run `limine-update` to apply the changes.
   175	It will rebuild your initramfs or UKI, similar to reinstalling the kernel.
   176	
   177	</details>

   246	## Boot Configuration:
   247	
   248	**Note:**<br>
   249	This automation generates only the default at `$ESP_PATH/limine.conf` and does not touch any other Limine config locations.
   250	If you plan to use `$ESP_PATH/limine.conf` as the default Limine boot config,
   251	remove any other alternative Limine config files to prevent them from overriding the default in the Limine boot menu.
   252	
   253	**Tip:**<br>
   254	Boot configuration is automated by some `limine-entry-tool`-based package.
   255	This allows you to skip the manual configuration below unless custom options are needed.
   256	
   257	<details>
   258	
   259	<summary>Manual Limine configuration</summary>
   260	
   261	Create or edit *$ESP_PATH*/limine.conf:
   262	
   263	1. **Add a kernel entry:**
   264	
   265	  You **must** add at least one kernel entry in the format `//<Kernel name>` <br>
   266	  within an OS entry block `/<OS name>`.
   267	
   268	2. **Choose one snapshot layout:** (Optional)
   269	
   270	  * Default: Add `//Snapshots` inside the OS entry block.
   271	  <br>**or**<br>
   272	  * Alternative: Add `/Snapshots` outside the OS entry block.
   273	
   274	The keyword (`//Snapshots` or `/Snapshots`) tells the tool where snapshot entries should be placed.
   275	
   276	#### Example 1:
   277	
   278	If bootable kernel files are stored in `/efi/`, `/boot/`, `/boot/efi/`, or any other path used as your boot partition:
   279	
   280	```
   281	/Arch Linux
   282	
   283	  //Kernel LTS
   284	  protocol: linux
   285	  module_path: boot():/initramfs-linux-lts.img
   286	  kernel_path: boot():/vmlinuz-linux-lts
   287	  kernel_cmdline: rw rootflags=subvol=/@ root=UUID=068589c1-d9be-407c-ad86-101aa0912825
   288	  
   289	  //Kernel
   290	  protocol: linux
   291	  module_path: boot():/initramfs-linux.img
   292	  kernel_path: boot():/vmlinuz-linux
   293	  kernel_cmdline: rw rootflags=subvol=/@ root=UUID=068589c1-d9be-407c-ad86-101aa0912825
   294	
   295	  //Snapshots
   296	```
   297	
   298	#### Example 2:
   299	
   300	If bootable kernel files are stored in `/efi/d647abee5e264f469d7a38b751d9d1db/kernel-version/`
   301	like where systemd-boot (`kernel-install`) stores them:
   302	
   303	```
   304	/+Arch Linux
   305	comment: Any comment
   306	comment: machine-id=d647abee5e264f469d7a38b751d9d1db
   307	
   308	  //Mainline kernel
   309	  protocol: linux
   310	  module_path: boot():/d647abee5e264f469d7a38b751d9d1db/kernel-version/initrd
   311	  kernel_path: boot():/d647abee5e264f469d7a38b751d9d1db/kernel-version/linux
   312	  kernel_cmdline: rw rootflags=subvol=/@ root=UUID=068589c1-d9be-407c-ad86-101aa0912825
   313	
   314	  //Mainline kernel fallback
   315	  protocol: linux
   316	  module_path: boot():/d647abee5e264f469d7a38b751d9d1db/kernel-version/initrd-fallback
   317	  kernel_path: boot():/d647abee5e264f469d7a38b751d9d1db/kernel-version/linux
   318	  kernel_cmdline: rw rootflags=subvol=/@ root=UUID=068589c1-d9be-407c-ad86-101aa0912825
   319	
   320	/Snapshots
   321	```
   322	**Note:** Bootable files must be placed in the boot partition alongside `limine.conf`.
   323	Only `boot():` or `$boot():` function is supported.
   324	
   325	</details>

   329	## Tool Configuration
   330	
   331	The config file is located at `/etc/default/limine` (**Recommend**) or alternatively at `/etc/limine-snapper-sync.conf`
   332	
   333	**Note:**
   334	
   335	- `/etc/default/limine` takes precedence over `/etc/limine-snapper-sync.conf`.
   336	- When booting into a read-only snapshot where `/etc/*` cannot be configured,
   337	`/etc/default/limine` is automatically copied to the temporary location `/tmp/limine-snapper-sync.conf`,
   338	allowing temporary configuration.
   339	
   340	Copy this to `/etc/default/limine` and adjust the settings as needed.
   341	
   342	```properties
   343	### OS Entry Targeting
   344	### This tool does not automatically know the custom OS name used in $ESP_PATH/limine.conf.
   345	### Set the OS name here to match the entry name in $ESP_PATH/limine.conf.
   346	###
   347	### Tips:
   348	### * Alternatively, add "comment: machine-id=<machine-id>" under your OS entry name in $ESP_PATH/limine.conf.
   349	###   The machine-id allows the tool to automatically target the correct entry. Changing the OS name does not matter.
   350	### * If unset, it reads PRETTY_NAME or NAME from /etc/os-release, with a fallback to /etc/lsb-release.
   351	###
   352	#TARGET_OS_NAME="Arch Linux"
   353	
   354	
   355	### Boot Partition Path
   356	### If not set, it is found automatically by checking /efi, /boot, /boot/efi, and /limine.
   357	### Set this to skip the automatic search or if your boot partition uses a different mount path.
   358	#ESP_PATH="/boot"
   359	
   360	
   361	### Boot Partition Usage Limit
   362	### Sets the maximum usage (in percent) for your FAT32 boot partition. Value must be between 1 and 99. Default: 85.
   363	### No new snapshot entries will be added to Limine if this limit is reached.
   364	### A larger FAT32 boot partition allows for more snapshot entries.
   365	###
   366	### Tips:
   367	### * You will be alerted when ENABLE_NOTIFICATION is set to "yes" and the limit is reached during snapshot creation.
   368	### * Do not increase the limit to 95% or higher on a small boot partition, as restoration will be blocked due to insufficient free space.
   369	###
   370	LIMIT_USAGE_PERCENT=85
   371	
   372	
   373	### Max Snapshot Entries
   374	### Limits how many snapshot entries appear in the "Snapshots" boot menu.
   375	### This depends on the size of your FAT32 boot partition and how many different kernel and module versions you want to keep.
   376	### A larger FAT32 boot partition allows more snapshot entries.
   377	###
   378	### Value: Number or "auto"
   379	###
   380	### What is "auto":
   381	### It is flexible and automatically removes older snapshot boot entries based on LIMIT_USAGE_PERCENT without warning.
   382	### A warning is only triggered if no snapshot boot entries are left and usage still exceeds LIMIT_USAGE_PERCENT.
   383	###
   384	### WARNING:
   385	### If LIMIT_USAGE_PERCENT is set very low (e.g. 1%) and the boot partition still has no free space,
   386	### "auto" will delete all snapshot boot entries, including all kernel versions.
   387	###
   388	### Default: "auto" if unset
   389	#MAX_SNAPSHOT_ENTRIES=auto
   390	
   391	
   392	### Exclude Snapshot Types
   393	### If a snapshot has a matching type, it will not be added into Limine.
   394	###
   395	### Example:
   396	###   EXCLUDE_SNAPSHOT_TYPES="pre, post"
   397	###
   398	#EXCLUDE_SNAPSHOT_TYPES=""
   399	
   400	
   401	### Exclude Entries from Snapshots
   402	### Matching kernels or entries are excluded from Limine snapshots. This helps reduce boot partition space usage.
   403	###
   404	### WARNING:
   405	### - Restoring an old snapshot may use outdated config and exclude unintended entries from the current "backup" snapshot.
   406	### - Excluded entries are preserved after restore, but may not match an old system version. They should be removed or updated manually.
   407	###
   408	### Note:
   409	### - "backup*" and "*snapshot*" entries are always excluded by default, regardless of any configuration.
   410	###
   411	### Wildcards:
   412	###  "*" matches any sequence of characters
   413	###
   414	### Example: excluding all fallback kernel entries
   415	#EXCLUDE_SNAPSHOT_ENTRIES="*fallback"
   416	EXCLUDE_SNAPSHOT_ENTRIES="Windows*, windows*"
   417	
   418	
   419	### Snapshot Kernel Parameters
   420	### Add or remove kernel parameters for new snapshot boot entries.
   421	###
   422	### - SNAPSHOT_KERNEL_PARAMETERS+ : Add extra kernel parameters
   423	### - SNAPSHOT_KERNEL_PARAMETERS- : Remove specific kernel parameters
   424	### - SNAPSHOT_KERNEL_PARAMETERS= : Replace the entire kernel command line (note: for multiple-profile UKIs only)
   425	###
   426	### Tips:
   427	### - No quotes are needed at the start or end of command lines, since quotes inside are not escaped.
   428	### - Do not add `#` as a comment at the end of command lines.
   429	###
   430	### Examples:
   431	#SNAPSHOT_KERNEL_PARAMETERS-=quiet splash
   432	#SNAPSHOT_KERNEL_PARAMETERS+=systemd.volatile=overlay
   433	
   434	
   435	### Make Snapshots Writable
   436	### Set to 'yes' to make created snapshots writable. (yes|no)
   437	### This may be required by some programs or display managers (e.g. GDM) that need write access at boot when overlayfs is not used.
   438	###
   439	### WARNING:
   440	### Writable snapshots can be modified and will no longer reflect the original 1:1 state.
   441	### Enable only if absolutely necessary.
   442	###
   443	### IMPORTANT:
   444	### If you boot into a writable snapshot, you should immediately click "Restore now" to avoid making unintended changes.
   445	#SNAPSHOT_WRITABLE=no
   446	
   447	
   448	### Snapper Configuration Name
   449	### Specify the Snapper configuration name. If not set, the tool will automatically detect it from "snapper list-configs".
   450	### Specifying it manually improves performance by avoiding automatic detection overhead.
   451	#SNAPPER_CONFIG_NAME="root"
   452	
   453	
   454	### Root Subvolume Path
   455	### If not set, the path is automatically detected during snapshot creation.
   456	### Override this value only if the detected path is incorrect.
   457	#ROOT_SUBVOLUME_PATH="/@"
   458	
   459	
   460	### Root Snapshot Path
   461	### If not set, the path is automatically detected during snapshot creation.
   462	### Override this value only if the detected path is incorrect.
   463	#ROOT_SNAPSHOTS_PATH="/@/.snapshots"
   464	
   465	
   466	### Restore Method Selection
   467	### Choose a restore method depending on your Btrfs layout and boot configuration.
   468	### Indicators: (+) Advantage, (-) Disadvantage, (o) Neutral/Special note
   469	###
   470	### rsync:
   471	### + Works on a system running on a root partition without a root subvolume.
   472	### + Supports multiple Linux installations on the same Btrfs filesystem.
   473	### + No issues with overlayfs used as a temporary writable layer on top of a read-only snapshot.
   474	### o Keeps the original subvolume ID after restore.
   475	### - Slower because all data is copied 1:1 from a selected snapshot to the root subvolume.
   476	### - Does not track which snapshot the restored data originally came from.
   477	###
   478	### replace:
   479	### + Very fast, creates a new subvolume from a selected snapshot and replaces the old one.
   480	### + Supports multiple root subvolumes (e.g., multiple distros) on the same Btrfs filesystem.
   481	### + No issues with overlayfs used as a temporary writable layer on top of a read-only snapshot.
   482	### o Changes the subvolume ID after restore.
   483	### - Restored subvolumes lose tracking of their relationship to older snapshots in the Snapper list.
   484	### - Cannot restore when system runs on a root partition without a root subvolume.
   485	###
   486	### opensuse (alias of "snapper"):
   487	### + Supports native snapper rollback.
   488	### + Very fast, 'snapper rollback' creates two snapshots (read-only and writable).
   489	### + Tracks snapshot relationships in the Snapper list, unlike "rsync" and "replace".
   490	### o Requires an OpenSUSE-style layout compatible with snapper rollback.
   491	### o Keeps the original main subvolume unchanged as the oldest base.
   492	### - Does not support multiple Linux distros on the same Btrfs (only one default subvolume for booting).
   493	### - Refuses to work when overlayfs is used as a temporary writable layer for testing changes on an immutable system.
   494	### - Some init services (e.g., display managers) require write access and may fail when booting a read-only snapshot.
   495	### (Info: In major v2, new 4th restore method would remove these last two disadvantages)
   496	###
   497	### Recommendation: Choosing a safe restore method if unsure:
   498	### * If your system normally runs on a root subvolume, use "replace" or "rsync". (typical for most Arch-based installations)
   499	### * If your system normally runs on a root Btrfs partition without a root subvolume, use "rsync".
   500	### * If your system normally runs on a writable snapshot, use "snapper". (For OpenSUSE or an OpenSUSE-like layout).
   501	###
   502	### Available restore methods: "replace", "rsync" or "snapper"
   503	RESTORE_METHOD=replace
   504	
   505	
   506	### Set Snapshot as Default
   507	### After restoring a snapshot, you can choose whether its new subvolume should automatically become the default (yes|no).
   508	###
   509	### What is a "default subvolume"?
   510	### It is the subvolume your system boots into if no subvolume is specified in the kernel command line.
   511	### On OpenSUSE, it is also required for 'snapper rollback'.
   512	###
   513	### yes: A newly created snapshot will automatically become the default subvolume after restoration.
   514	###       WARNING: This may cause problems or conflicts if multiple Linux distributions (e.g. OpenSUSE) share the same Btrfs partition.
   515	###       Recommendation: Set to yes only if your distro is the only one on the Btrfs partition.

   517	### no:  The original subvolume remains the default.

   613	## Translations
   614	
   615	The messages are translatable. The tool itself reads its text from
   616	`src/main/resources/messages.properties`; a language is added by putting
   617	`messages_<lang>.properties` next to it, for example `messages_de.properties`, and by
   618	listing the language in `-H:IncludeLocales` in `build.gradle.kts`. Russian
   619	(`messages_ru.properties`, `po/ru.po`) is shipped. Keys that a
   620	translation does not carry fall back to the English file, so a partial translation is
   621	harmless.
   622	
   623	The shell scripts use the gettext catalog `limine-snapper-sync`. `po/limine-snapper-sync.pot`
   624	holds the strings, refreshed with `bash --dump-po-strings`, and a language is added as
   625	`po/<lang>.po`, compiled with
   626	`msgfmt po/<lang>.po -o /usr/share/locale/<lang>/LC_MESSAGES/limine-snapper-sync.mo`.
   627	
   628	The build does that step itself: `gradle build` and `gradle nativeCompile` compile every
   629	`po/*.po` into `install/arch-linux/usr/share/locale/<lang>/LC_MESSAGES/`, which is part of
   630	the tree packaging already installs, so a package picks the catalogs up without any extra
   631	step. It needs `msgfmt` (the `gettext` package) at build time; without it the build still
   632	succeeds and only warns, and the scripts keep speaking English.
   633	
   634	The language comes from the environment, so `LANG=C limine-snapper-list` always gives
   635	the English text.

   639	## Troubleshooting
   640	
   641	<details>
   642	<summary>Why does my boot partition usage grow too fast?</summary>
   643	
   644	This can happen for several reasons:
   645	
   646	- **Heavy modules and DKMS drivers in early boot**
   647	    - **Nvidia, Plymouth, and some DKMS drivers** are often included in each initramfs and can increase usage by more than 200 MiB per kernel.
   648	        - **Fix:** Review and configure your initramfs and remove modules that are not required for early boot.
   649	            * Example: Is network access required during early boot on an unencrypted boot partition? If not, move network driver out of the initramfs so it is loaded later from the root filesystem.
   650	
   651	- **Excessive automatic snapshots created during rolling updates**
   652	    - **Fix:** Limit or disable automatic hooks, for example: uninstall `snap-pac` package on Arch Linux.
   653	    - **Fix:** Edit `/etc/default/limine` and add `EXCLUDE_SNAPSHOT_TYPES="post"` to ignore matching snapshots.
   654	    - **Fix:** Instead of relying on automatic hooks, create a few snapshots manually or configure time-based snapshot creation.
   655	
   656	- **`sbctl` produces a different non-reproducible hash on each run**, even for identical files, causing unnecessary duplication.
   657	    - **Fix:** Request that the `sbctl` maintainer add support for reproducible hashing.<br>
   658	    - Alternatively, use Limine `protocol: linux` to boot reproducible initramfs and vmlinuz, bypassing Secure Boot (no signing required).
   659	
   660	- **Some initramfs tools generate non-reproducible initramfs images**, even when modules and configuration have not changed, causing unnecessary duplication.
   661	    * **For mkinitcpio:**
   662	        - **Fix:** Edit `/etc/mkinitcpio.conf` and set `COMPRESSION="zstd"` to make initramfs builds reproducible.
   663	
   664	    * **For Dracut:**
   665	        - **Fix:** Add `reproducible=yes` and `compress="zstd"` to any dracut drop-in configuration file.
   666	
   667	- **Fallback initramfs is huge and includes every module**, which consumes a lot of space and may expose sensitive information on an unencrypted boot partition.
   668	    - **Fix:** Disable fallback initramfs generation if you do not plan to use the same disk on **multiple different devices**.
   669	
   670	- **Too many kernels installed per snapshot.**<br>(Note: Using multiple kernel versions increase the risk of breaking filesystem when frequently switching between them.)
   671	    - **Fix:** Keep only one kernel that works on your system.
   672	
   673	- **Too many snapshots without real benefit.**
   674	    - **Fix:** Limit the number of snapshots.
   675	    - **Fix:** Avoid creating new snapshots when rebuilding non-reproducible initramfs or UKI, unless system changes were made.
   676	
   677	- **The boot partition is too small.**
   678	    - **Fix:** Resize it or move to a larger FAT32 partition. Larger disks are cheaper this year than before.
   679	    - **Example:** If you have plenty of free disk space and want to create a larger boot partition:
   680	        1. Back up your important data first.
   681	        2. Be careful to shrink your root partition **from the end (right to left)**.
   682	        3. Create a new larger FAT32 partition (e.g. 16 GiB or 32 GiB, similar to swap size).
   683	        4. Back up the current boot folder:
   684	        ```sh
   685	        sudo cp -r /<boot_or_efi_path>/$(cat /etc/machine-id)  /boot_bak
   686	        sudo cp /<boot_or_efi_path>/limine.conf  /limine.conf_bak
   687	        ```
   688	        5. Update `/etc/fstab` with **the new UUID** for `/boot`. **This step is important. Do not skip it.**
   689	        6. Unmount and remount `/boot` after updating `/etc/fstab`
   690	        ```sh
   691	        sudo umount /<boot_or_efi_path>
   692	        sudo mount /<boot_or_efi_path>
   693	        ```
   694	        7. Restore the boot folder:
   695	        ```sh
   696	        sudo cp -r /boot_bak  /<boot_or_efi_path>/$(cat /etc/machine-id)
   697	        sudo cp /limine.conf_bak  /<boot_or_efi_path>/limine.conf
   698	        ```
   699	        8. Reinstall Limine and update:
   700	        ```
   701	        sudo limine-install --fallback  # command from limine-entry-tool package
   702	        sudo limine-update              # command from limine-dracut/mkinitcpio-hook package
   703	        sudo limine-snapper-sync
   704	        ```
   705	</details>
   706	
   707	<details>
   708	<summary>Why is restore blocked?</summary>
   709	
   710	The restore function includes several built-in safeguards to prevent user mistakes.
   711	
   712	- **The boot partition does not have enough free space for restoring kernel files**
   713	    - **Fix:** Run `limine-snapper-remove <ID 1>..<ID 2>` to remove older snapshot boot entries and free up space on the boot partition.
   714	
   715	- **Different configuration errors**, such as:
   716	    - Using incompatible Btrfs layout
   717	    - Invalid value of `ESP_PATH`
   718	    - Outdated `FS_UUID` value used for mounting Btrfs
   719	    - etc...
   720	
   721	</details>
   722	
   723	<details>
   724	<summary>Why am I seeing the "Broken manifest detected" message?</summary>
   725	
   726	A broken manifest *snapshots.json* can be caused by:
   727	* FAT32 corruption (e.g., power loss)
   728	* Hardware issues (disk, RAM, or CPU)
   729	
   730	**How to fix:**
   731	
   732	* `limine-snapper-sync` automatically recovers the backup `/var/cache/boot/<machine-id>/lss/snapshots.json` if the hardware is fine.
   733	* If the hardware is faulty, back up your data and replace or repair the hardware.
   734	
   735	</details>
   736	
   737	<details>
   738	<summary>Why are fewer snapshots shown in Limine than in Snapper?</summary>
   739	
   740	The Limine Snapshot menu only shows up to the number of snapshots set by **MAX_SNAPSHOT_ENTRIES**.<br>
   741	This limit helps prevent your boot partition from filling up with too many snapshots or kernel versions.
   742	
   743	**How to fix:**
   744	
   745	- Edit `/etc/default/limine` and set `MAX_SNAPSHOT_ENTRIES=` to a higher number.
   746	</details>
   747	
   748	<details>
   749	<summary>Some display managers fail to boot into read-only snapshots</summary>
   750	
   751	This can happen if your system expects a **writable** root filesystem.<br>
   752	
   753	**How to fix:**
   754	
   755	1. Reboot and go to the Limine boot menu
   756	2. Select a snapshot (don't boot it). Press <kbd>E</kbd> to edit the `kernel_cmdline: ...` to add `1` for enabling rescue mode.
   757	3. Press <kbd>F10</kbd> to boot. Log in as root user in text mode.
   758	4. Run `limine-snapper-restore` to restore the snapshot.
   759	
   760	Once the snapshot is restored and the system boots normally, here are two ways to prevent this issue in the future:
   761	
   762	#### ✅ Option 1: Use OverlayFS to simulate a writable layer
   763	
   764	This is the recommended solution for two restore methods: `replace` or `rsync`.<br>
   765	**Note:** Using an openSUSE-style layout with the restore method `opensuse` (`snapper`) does not support OverlayFS.
   766	
   767	* **With Dracut** (on Arch Linux):<br>
   768	Install [`limine-dracut-support`](https://aur.archlinux.org/packages/limine-dracut-support/),
   769	then create a new snapshot.<br>
   770	OverlayFS support is enabled automatically.
   771	<br>**or**</br>
   772	* **With mkinitcpio** (on Arch Linux):<br>
   773	    1. Install [`limine-mkinitcpio-hook`](https://aur.archlinux.org/packages/limine-mkinitcpio-hook/).
   774	    2. Edit `/etc/mkinitcpio.conf` and add `btrfs-overlayfs` after `filesystems` in `HOOKS=(...)` when using busybox hooks.<br>
   775	       (**Note:** For systemd hooks, use `sd-btrfs-overlayfs`, since `btrfs-overlayfs` is incompatible.)
   776	    3. Run `sudo limine-update`
   777	    4. Create a new snapshot (older ones won’t work).
   778	
   779	#### ⚠️ Option 2: Force snapshots to be writable (not recommended)
   780	
   781	If you don’t want to use OverlayFS, you can force newly created snapshots to be writable:
   782	
   783	Edit `/etc/default/limine` and set this line:
   784	```bash
   785	SNAPSHOT_WRITABLE=yes
   786	```
   787	**Important:**
   788	If you boot into a writable snapshot, restore it immediately and avoid making changes to the snapshot itself. Modifying a snapshot directly can break consistency.
   789	
   790	</details>
   791	
   792	<details>
   793	<summary>Boot entries missing in Limine</summary>
   794	
   795	This happens when `limine.conf` is missing or empty on FAT32 boot partition.<br>
   796	**Possible causes:**
   797	- FAT32 has no journaling: power loss or hard reset during a write may leave `limine.conf` empty.
   798	- Some text editors fail to safely overwrite `limine.conf` on FAT32.
   799	
   800	**How to fix:**
   801	1. Boot another OS.
   802	2. Mount the FAT32 boot partition where Limine is installed.
   803	3. If `limine.conf.old` exists, restore it by copying it to `limine.conf`
   804	4. Add `hash_mismatch_panic: no` to the header of `limine.conf` to avoid a panic on checksum mismatches (Limine will only warn instead).
   805	
   806	</details>
   807	
   808	<details>
   809	<summary>No restore notification appears after booting a snapshot</summary>
   810	
   811	Some window managers (e.g., Hyprland) do not use the standard XDG autostart mechanism by default.
   812	
   813	**How to fix:**
   814	
   815	* Add `limine-snapper-restore --notify` to your window manager’s autostart as a regular user.
   816	* Make sure a package providing the standard `notify-send` is installed, as `limine-snapper-restore --notify` relies on it (e.g., `swaync` supports this).
   817	* If your environment does not support `notify-send`, ask its developers to add support rather than requesting it here.
   818	
   819	</details>
   820	
   821	<details>
   822	<summary>What happens after moving boot files and Btrfs to another disk?</summary>
   823	
   824	The stored UUID may become outdated after moving your boot files and Btrfs to another disk.<br>
   825	As a result, the system might fail to boot until the UUID is updated.
   826	
   827	**How to fix:**
   828	
   829	1. Boot into a live chroot environment.
   830	2. Find the current UUID of your Btrfs partition:
   831	   ```bash
   832	   lsblk -o NAME,FSTYPE,UUID,SIZE,LABEL,MOUNTPOINT,PTTYPE
   833	   ```
   834	3. Edit `/etc/default/limine` and update `FS_UUID=` to your current Btrfs UUID.
   835	4. If you are using `limine-entry-tool`, make sure to update the kernel command line:
   836	   ```
   837	   KERNEL_CMDLINE[default]=... root=UUID=...
   838	   ```
   839	5. Update Limine boot configuration by running `limine-update` and `limine-snapper-sync`
   840	
   841	</details>

   845	## Features
   846	
   847	### Core sync system
   848	
   849	* Snapper plugin integration for snapshot create, modify, delete, and rollback events
   850	* Parse Snapper metadata, limine.conf, history manifest and configs
   851	* Atomic mutex to prevent concurrent processes from accessing the same boot partition
   852	* Debounce mechanism to group multiple snapshot deletions/modifications into a single sync
   853	* Multithreaded readers and writers for parallel execution and faster processing
   854	* Boot entries from limine.conf are converted into a tree structure for simplified management
   855	* Verify configuration before processing
   856	* Identify a custom OS entry via machine-id based identification
   857	* Generate a snapshot boot entry from the identified OS entry
   858	* Support for multiple nested boot entries
   859	* Support for multiple hash functions without restrictions
   860	* Scalable manifest without structural limits, including automatic upgrade from old to new manifest format
   861	* Remove snapshot boot entries when Snapper snapshots are deleted
   862	* Atomic file writes on FAT32 to reduce the risk of corruption during power outages, crashes, or hard resets
   863	* Deduplicate kernel files to avoid copies by re-using existing files on the boot partition
   864	
   865	### Backup & restore
   866	
   867	* Automatic backup of limine.conf before modifications
   868	* Automatic backup of manifest in 2 different locations: boot partition and Linux partition
   869	* Automatic recovery of manifest when corrupted or lost
   870	* Automatic snapshot kernel repair by restoring a valid kernel when corruption is detected
   871	* Support for 3 different restore methods: replace, rsync and snapper
   872	* Restore original boot entry from manifest back into OS section of limine.conf
   873	* Restore all snapshot entries from manifest when they are lost in limine.conf
   874	* Backup boot entry with kernels added to Limine during restore
   875	
   876	### Snapshot & kernel management
   877	
   878	* `SNAPSHOT_KERNEL_PARAMETERS` to manage kernel parameters for newly created snapshots
   879	* `EXCLUDE_SNAPSHOT_ENTRIES` to skip kernel entries (e.g. fallback kernels) in newly created snapshots
   880	* `EXCLUDE_SNAPSHOT_TYPES` to exclude specific snapshot types
   881	* `SNAPSHOT_WRITABLE` to make snapshots writable for boot when needed
   882	* `MAX_SNAPSHOT_ENTRIES=auto` to auto-remove older snapshot boot entries based on boot partition usage limit
   883	* `limine-snapper-remove` to remove selected snapshot boot entries to reduce boot partition usage
   884	* `limine-snapper-restore` to restore a snapshot from the boot menu
   885	
   886	### Detection & monitoring
   887	
   888	* Two ways to monitor snapshot changes: `limine-snapper-watcher` or Snapper plugin integration
   889	* Hardware issue detection (e.g. non-ECC RAM or disk problems) by comparing file hashes
   890	* Detection of boot partition usage limits with detailed reporting
   891	* `limine-snapper-info` shows snapshot IDs affected by missing or corrupted kernel files
   892	* `limine-snapper-info` can prompt cleanup of unused files when detected
   893	
   894	### System integration & UX
   895	
   896	* Extensive safeguards to reduce breakages from user errors
   897	* Ensure /etc/machine-id exists, generate if missing
   898	* Automatic detection of default OS name from /etc/os-release
   899	* Almost zero configuration thanks to automatic system detection.
   900	* Desktop notifications for hardware issues, misconfigurations, or boot partition limit warnings
   901	* Authentication helper to avoid typing `sudo` or other auth methods every time
   902	* Pre- and post-hooks for running custom scripts before or after snapshot updates
   903	* Pacman hook integration to wait for sync completion before package updates
   904	* Pacman lock cleanup after restore on Pacman-based systems
   905	* Sync support in chroot environment across multiple offline subvolumes/partitions
   906	* Atomic-like update: Switch between A/B systems after system update in offline subvolume/partition
   907	* Support for booting different mutable or immutable system versions
   908	* Choice of snapshot naming formats shown in the boot menu, plus two different boot menu layouts
   909	* `limine-snapper-list` displays snapshot boot entries on the boot partition
   910	* Terminal input support with arrow-key navigation (Up, Down, Left, Right)
   911	
   912	### CoW-like behavior on FAT32 boot partition
   913	
   914	Combining **limine-snapper-sync** and **limine-entry-tool** turns a FAT32 boot partition into a CoW-like system for kernel boot management.
   915	
   916	**Here is why:**
   917	* **Copy-on-write-like behavior**: Different kernel versions are preserved when snapshots are created.
   918	* **Deduplication**: Kernel files are re-used based on hashing to avoid unnecessary duplication.
   919	* **Integrity checks**: Each kernel version has an automatically generated checksum.
   920	* **Boot verification**: Limine verifies kernel integrity using stored checksums during boot.
   921	* **Compression**: Kernel files (vmlinuz, initramfs, UKI) are stored in compressed form by default.
   922	* **Self-healing**: Broken kernel files are automatically replaced when a valid version exists.
   923	* **Metadata recovery**: If snapshots.json is lost or corrupted, it can be restored automatically.
   924	* **Hardware issue detection**: Hash comparisons help detect faulty storage or memory behavior.
   925	* **Scrubbing and repair**: detects missing or corrupted boot files and restores them from backups (planned).
   926	* **RAID 1 support**: planned
   927	
   928	Together, these features make FAT32 behave like a CoW-inspired boot filesystem.

371:### UEFI Boot Order
372:### Choose where 'limine-install' places the Limine UEFI boot entry in the UEFI boot order when it creates the entry. (first|last|keep)
373:### It has no effect while the entry exists; it only applies when the entry is missing, e.g. after a firmware or Windows update removed it.
374:###
375:### Options:
376:### * "first" or commented out -> Put Limine first, so it becomes the default boot option.
377:### * "last"                   -> Put Limine at the end; the current default boot option stays unchanged.
378:### * "keep"                   -> Put Limine where an older Limine entry for the same EFI file still is in the boot order, otherwise like "last".
379:###
380:### Note:
381:### "last" and "keep" set the boot order with 'efibootmgr --bootorder'. Some UEFI firmware ignores or rewrites a boot order set this way,
382:### or creates duplicate boot entries after a reboot. 'limine-install' reports a boot order that differs from the requested one, but does not retry.
383:### If your firmware does this, use "first" and adjust the boot order in the BIOS/UEFI setup instead.
387:### Kernel Command Line Configuration
388:### Define one or more kernel command lines (parameters) for specific kernel entries.
389:### If unset, the tool will try to read them from '/etc/kernel/cmdline' or '/proc/cmdline'.
390:###
391:### Rules:
392:### * KERNEL_CMDLINE[default] applies to any kernel entries without specific configuration.
393:### * KERNEL_CMDLINE[fallback] applies to kernel entries with names containing *fallback*
394:### * KERNEL_CMDLINE[kernel name] applies to a specific kernel entry.
395:###
396:### Operators:
397:### * `+=` appends parameters to an existing cmdline for the same KERNEL_CMDLINE[<key>]
398:###    Commonly used in drop-in configs: /etc/limine-entry-tool.d/*.conf
399:###    Ignores /etc/kernel/cmdline and /proc/cmdline
400:### * `=` replaces an existing cmdline for the same KERNEL_CMDLINE[<key>]
401:###    Note: /etc/default/limine overrides any drop-in configs, so `+=` is recommended there.
402:###
403:### Tips:
404:### - If unsure which parameters to use, copy them from `/proc/cmdline` into KERNEL_CMDLINE[default],
405:###   but make sure your system is not a live ISO, temporary environment, or snapshot.
406:### - Multiple `initrd=` parameters are automatically converted into Limine module paths for non-UKI entries.
407:### - No quotes are needed at the start or end of command lines, since quotes inside are not escaped.
408:### - Do not add `#` as a comment at the end of command lines.
409:###
410:### Examples:
411:#KERNEL_CMDLINE[default]+=rw root=UUID=...
412:#KERNEL_CMDLINE[default]+=quiet splash acpi_osi="..."
