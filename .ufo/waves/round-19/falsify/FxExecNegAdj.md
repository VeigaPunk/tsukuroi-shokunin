## Attack

C1 adjacency gate negative validation: independently corrupt (1) an outbound anchor's quote to empty, (2) an inbound classification to a value outside the allowed vocabulary, and (3) an inbound `target_ranges` interval so it lies beyond the committed target file. Each should be falsifiable by the gate. The third case was kept consistent between the registry and captured pointer census so that a mismatch finding could not mask whether the gate bounds ranges against actual target-file length.

## Method

- Read the committed gate at revision `8e5916360f2dfe7bc4eb4ba144081af555900116`; created isolated non-hardlink clones, detached at that revision, pointed each clone's `refs/heads/master` at the target tip, and removed `origin`.
- Wrote three independent external fixtures under `/tmp`: `/tmp/fx-adj-outbound-empty-quote.json` (`quote` empty), `/tmp/fx-adj-inbound-bad-classification.json` (`classification` empty), and `/tmp/fx-adj-target-range-outside.json` (`target_ranges` `[[999999,999999]]`).
- Tried documented registry mode on each clone using `--revision 8e5916360f2dfe7bc4eb4ba144081af555900116 --registry /tmp/<fixture>.json`. All three were refused with `E-REGISTRY-PATH`, exit 2. This is consistent with `tools/check-adjacency-anchors.py:588-589,621-624`: `--registry` is lane-relative and rejects absolute paths. Fell back to the requested committed-fixture route.
- In three separate clones, committed one fixture mutation each (`git -c user.name=fixture -c user.email=fixture@local commit -am mutant`), updated `refs/heads/master` to that mutation commit, and ran the gate against that exact revision. For the range case, changed IN-001 `target_ranges` in both the registry and census to `[[999999,999999]]`, preserving their identity; the target `PROVINCE.md` remained unmodified.
- Measured `PROVINCE.md` in the range clone with `wc -l PROVINCE.md`; output was `132`.

## Verdict

**REFUTE — C1 (gate-level adjacency assurance).** The empty outbound quote and invalid inbound classification were red, but the gate returned PASS with zero findings when both committed range records pointed to line 999999 in a 132-line target. This does not independently disprove the unmutated registry's reported 114/97/17 totals; it exposes that C1's gate can certify an impossible inbound target range.
