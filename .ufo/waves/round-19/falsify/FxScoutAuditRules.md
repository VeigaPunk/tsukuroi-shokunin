## Attack
Falsify the `tools/boot-chain-audit.sh` contract at target revision `8e5916360f2dfe7bc4eb4ba144081af555900116`: map the documented six verdict rules to implementation; check that unevaluable entries force `UNKNOWN`; and run the hermetic selftest. The attack focused on code paths that might classify an unparseable image as an ordinary non-kernel entry and thereby bypass the unknown counter.

## Method
- Read the target script and source ranges covering the rule table, identity detection, audit-state handling, verdict function, summary, and selftest.
- Confirmed target and working-tree script blobs match: both `git rev-parse <revision>:tools/boot-chain-audit.sh` and `git rev-parse HEAD:tools/boot-chain-audit.sh` returned `60a3ef2e31c7f9bc508264d5f056afe930a30821`; working-tree SHA-256 was `495750fbced6218f1c137af3aef1232e59305ebf2f5ce9ab47dbd4546fe72ab1`.
- Ran `cd /home/vgpnk/Projects/shokunin/tsukuroi-shokunin && bash tools/boot-chain-audit.sh --selftest; printf 'EXIT=%s\n' "$?"`.
- Ran a temporary `/tmp` fixture probe (`bash /tmp/fxprobe-bootchain.sh`) for missing init, missing VERSION, unreadable image, zero-kernel fallback, missing b2sum, rule-3 UNTESTED, and the live-branch `.uname` identity primitive on arbitrary non-PE bytes. The first probe invocation had an unset `WORK` fixture directory and was discarded; after correcting that setup, the probe produced the results below. It never invoked `--live`, `sudo`, or accessed `/boot`.
- No LSP device was available in the tool routes; source claims below are based on the directly read shell code, not grep output as semantic proof. No tool was installed or updated.

## Verdict
**REFUTE — FxScoutAuditRules (boot-chain-audit.sh rule/unknown contract).** The six ordinary verdict branches map as documented and `--selftest` passes, but the supporting rule-2 input inventory is incomplete and `objcopy` failure is classified as `NOT-A-KERNEL-ENTRY`, not `EVALUATION-ERROR`. That live-only classification bypasses the unknown counter; the possible end-to-end summary impact is an inference because live mode was prohibited.

## Evidence
- The documented rules are at `/home/vgpnk/Projects/shokunin/tsukuroi-shokunin/tools/boot-chain-audit.sh:19-31`. The ordinary branch mapping is: rule 1 `NOT-A-KERNEL-ENTRY` at `:608-610`; rule 2's booted predicate is assembled at `:751-754` and emitted at `:612-614`; rule 3 at `:616-618`; rule 4 at `:620-624`; rule 5 at `:625-628`; and rule 6's default `UNTESTED` at `:630`. These normal conditions match.
- **Rule-2 documentation mismatch:** the documented `/etc`+/`/usr` input list at `:58-59` omits `/etc/limine-snapper-sync.conf`; the `find` command at `:470-473` includes it. This is a conservative deviation (it can prevent a `BOOTED-OBSERVED` verdict, not create one), but the enumerated list does not exactly match implementation.
- **Unevaluable image classification gap:** `image_identity()` documents that successful `objcopy` with an empty `.uname` means the section is absent (`:311-312`), but its `else` also maps a nonzero `objcopy` status to `not-kernel` (`:313-316`). The corrected fixture probe observed `objcopy-on-garbage exit=1` and `image_identity(garbage)=not-kernel` with `/usr/bin/objcopy`.
- The audit marks an entry erroneous only when `ident` is literally `error` (`:678-681`); otherwise it remains eligible for normal verdict handling. `verdict_for()` then returns `NOT-A-KERNEL-ENTRY` when `kernel != 1` (`:608-610`), which the audit counts as `notkernel_n` (`:763-768`). The summary subtracts `notkernel_n` from `kernel_eval` and can emit `CONSISTENT` when an unknown was not counted and another kernel remains (`:784-790`). **[INFERENCE]** Thus a corrupt/truncated kernel image whose `.uname` extraction makes `objcopy` fail could be omitted from the checked kernel population and coexist with a `CONSISTENT` summary. No live `/boot` case was run.
- Corrected fixture probe output: missing VERSION, missing init, and unreadable image each yielded `EVALUATION-ERROR`, `UNKNOWN`, exit 2; fallback-only yielded `NOT-A-KERNEL-ENTRY`, `UNKNOWN`, exit 2. A rule-3 non-snapshot, non-selected entry yielded `UNTESTED`, `CONSISTENT`, exit 0, as the documented rules/exit map allow. Missing b2sum with a pinned hash yielded `b2_ok=MISMATCH`; b2 is documented report-only and this did not change the entry verdict.
- Selftest output was exactly `TSUKUROI_BOOTCHAIN_SELFTEST: PASS total=45 failed=0` and `EXIT=0`. The script’s final selftest assertion is at `:1206-1210`; its end-to-end fixture expects a normal fallback `NOT-A-KERNEL-ENTRY` alongside a `CONSISTENT` summary at `:1054-1062`.
- Target-blob identity is the same at the attack revision and current `HEAD` (`60a3ef2e31c7f9bc508264d5f056afe930a30821`), so the selftest was run against byte-identical script content.

## Residual
Live mode and `/boot` were not exercised, as required by host-safety bounds. Therefore the `.uname` `objcopy` failure behavior is directly observed at the identity primitive; its live audit-row and summary consequence is traced through source and marked `[INFERENCE]`. The incomplete input-list discrepancy is conservative. The selftest is green but does not cover `objcopy` nonzero status, missing init, or missing VERSION as end-to-end error cases; the missing-init/VERSION paths were separately exercised through the fixture audit function.
