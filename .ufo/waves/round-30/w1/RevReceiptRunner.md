Verdict: partly holds — the runner really executes committed bytes of the named tool revision and binds revision, tool revision and digest honestly, but it has five medium defects (no timeout; unvalidated tool path that can mislabel receipts with host bytes; non-UTF-8 output loses the receipt entirely; `--out` may write into the lane; child env violates the round-30 child env contract) plus lower-severity gaps, one of which (unverified lane working-copy state) lets a receipt name a revision the lane is not at.

## Answers to the review questions

1. Does it run the tool bytes of the named tool revision, not the working copy? YES [obs]. `git -C lane archive trev` (line 66) is extracted to a private `tempfile.mkdtemp` under `/fast/scratch/hyaku` (63-64, 67-68) and the tool is executed from there (69, 76); the working copy is never touched. Verified: receipt out2.jsonl header `tool_sha256` 5e9ff59696c28f76f42b78bb585a71cf24304f07a212cd6366f06b3a26bfc82f equals `git show 65b7f95:tools/check-kernel-taint.py | sha256sum` exactly, and a probe tool that exists only at 65b7f95 was executed while `--revision` was 8976ca9 [obs].
2. Header binding: `revision` and `tool_revision` are full hashes pinned through `rev-parse --verify <rev>^{commit}` (40-43, 57-58); `tool_sha256` is taken from the extracted file before execution (73-74); `argv` and timestamps present (77-78). Correct and honest — `--tool-revision` cannot forge a receipt: out5.jsonl header names `tool_revision` 65b7f95 while `revision` stays 8976ca9, and the digest matches that revision's bytes [obs]. Two binding gaps remain: only the single entry file is digested, not the rest of the tree it may import (finding L3); and `revision` is a label for the args — nothing asserts the `--lane` working copy is clean at that revision (finding M6).
3. `{rev}` substitution: SAFE [obs]. Plain `str.replace` into a list-form `argv` (75), no shell, and the substituted value is the 40-hex resolved hash; `{lane}` likewise a filesystem path handled as one argv element.
4. Tool needing the lane as a git repository: FAILS HONESTLY BUT USELESSLY [obs]. cwd is the export root, which has no `.git`; `tools/check-self-assessment.py --selftest` under the runner produced exit 2 `"error": "not a git repository", "repo": "/fast/scratch/hyaku/run-receipt-y_0pd17m"` (out1.jsonl) — the same failure the C2 before-receipt records as the harness error. A gate that passes in the lane is mislabelled as failing. Exact fix belongs to the gate (dispatch `--selftest` before the `.git` check — the C2 fix owned elsewhere); the runner could add a `--cwd <dir>` option for callers that want to point cwd at a clone, and should say in the docstring that gates must be export-safe.
5. Tool writing into its cwd: CONTAINED [obs]. cwd is the private export; `finally: shutil.rmtree(root, ignore_errors=True)` (87-88) discards it. Writes to absolute paths outside cwd are not contained (info only — the runner's job is faithful execution, but callers should know receipts do not sandbox the tool).
6. Non-UTF-8 output: DEFECT (M3). `text=True` (79) raises UnicodeDecodeError at completion; the receipt is never written and the tool's exit code is lost (out4 run: traceback `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xff in position 0`, rc=1, `out4.jsonl` absent).
7. Timeout: DEFECT (M1). `subprocess.run` at line 79 has no `timeout=`; a hung gate hangs the receipt run forever, writes nothing. The C2 probe itself freezes `TIMEOUT = 900` (probe-git-env-residual-r30.py:70), so the omission is inconsistent with round-30 practice.
8. `--out` into the lane: DEFECT (M4). `os.makedirs` + open (82-85) with no guard; demo wrote `out-in-lane.jsonl` as an untracked file inside the lane clone (`git status --porcelain` shows `?? out-in-lane.jsonl`).

## Findings by severity

### Medium

- M1 — No timeout; a hung gate hangs the wave with no receipt. Evidence: line 79 (`subprocess.run(argv, cwd=root, capture_output=True, text=True, env=env())`, no `timeout=`); contrast `TIMEOUT = 900` in tools/probe-git-env-residual-r30.py:70 [obs]. Fix: add `--timeout` (default 900), pass `timeout=t` to `subprocess.run`, catch `subprocess.TimeoutExpired`, emit footer `{'receipt_end': 1, 'exit_code': None, 'timed_out': True, 'stderr_tail': <decoded partial, errors='replace'>, ...}` and return 124.
- M2 — Unvalidated tool path: absolute or `..` paths execute and digest host bytes while the receipt claims `tool`/`tool_revision` provenance from the tree. Evidence: line 69 `tool = os.path.join(root, cmd[0])` accepts absolute paths (`os.path.join` returns the second operand unchanged) and unresolved `..`; run with `-- /usr/bin/echo forged-bytes-from-host-echo` produced out3.jsonl header `{"tool": "/usr/bin/echo", "tool_revision": "8976ca92…", "tool_sha256": "7ce74551…"}` — a receipt naming a revision for bytes that are not in that tree (the bash fallback refused the ELF, rc 126; a host `.py` would have executed) [obs]. This is the one real mislabel vector; the digest alone does not save a gate that only checks `revision`/`exit_code`. Fix: after the `tarfile.open` at 67, take `names = set(t.getnames())`; reject `os.path.isabs(cmd[0])` or any `..` part; require the normalized `cmd[0]` to be a member of `names` (error exit 2, same JSON error shape as lines 70-72) before hashing/executing.
- M3 — Non-UTF-8 stdout destroys the receipt. Evidence: out4 run — `UnicodeDecodeError … byte 0xff in position 0` from `_translate_newlines`, rc=1, no `out4.jsonl` [obs]. Fix: run with `text=False`; decode stdout/stderr with `errors='replace'` (`p.stdout.decode('utf-8', 'replace')`) for the receipt body and `stderr_tail`; keep the tool's exit code in the footer even on garbled output.
- M4 — `--out` may write into the lane; no seat-containment guard. Evidence: lines 82-85; demo run left untracked `out-in-lane.jsonl` inside the sandbox lane clone [obs]. Given the round-28 seat-containment incident this is the wrong default posture. Fix: after line 56 compute `out_real = os.path.realpath(a.out)` and refuse with exit 2 when `out_real == lane or out_real.startswith(lane + os.sep)` (message naming `--out`).
- M5 — Child environment does not meet the round-30 GIT CHILD ENV CONTRACT. Evidence: `env()` (31-34) only strips `GIT_*` and sets `GIT_CONFIG_NOSYSTEM=1`; children keep the caller's real `HOME`/`XDG_CONFIG_HOME`, global git config, and `PATH`, and get no `GIT_CEILING_DIRECTORIES` [obs]. NOSYSTEM does not disable user-level config, so a user `core.hooksPath` or an enclosing repository above the export would change gate behavior and receipt content (the C2 channels 2 and 3; no repo exists above `/fast/scratch/hyaku` today — `git rev-parse --show-toplevel` from there stops at the filesystem boundary, rc 128 [obs] — but that is luck, not a guarantee). Fix: implement the six-step contract verbatim in `env()`/main: drop `GIT_*`; set `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=os.devnull`, `GIT_CONFIG_SYSTEM=os.devnull`; `HOME` = a private empty dir inside `root`, `XDG_CONFIG_HOME = HOME + '/.config'`; `PATH='/usr/bin:/bin'`; `GIT_CEILING_DIRECTORIES = os.path.dirname(root)`; identity via explicit `-c` where the child commits.
- M6 — `revision` is not verified against the lane the tool reads. The header's `revision` field comes from `--revision`, but gates read the `--lane` working copy, which the runner never checks; a dirty lane or a lane at another commit yields a receipt that names a revision the tool never saw — the exact "Gates at <rev>" defect class this tool exists to close. Evidence: lines 56-58 and 77 record the labels only; no `rev-parse HEAD`/`status --porcelain` comparison anywhere in the file [obs]. Fix: before execution, run `git -C lane rev-parse HEAD` and `git -C lane status --porcelain` (read-only, `env=env()`); refuse (exit 2) unless HEAD == `rev` and porcelain is empty, unless a new `--allow-dirty` flag is passed; record `lane_head` and `lane_dirty` in the header either way.

### Low

- L1 — Gates needing a repo at cwd can never pass under the runner (out1: exit 2, `"not a git repository"`, repo = export root) [obs]. Receipt is honest; the fix is export-safe gates (C2's fix for check-self-assessment) plus optionally a `--cwd` option and a docstring sentence requiring `--lane {lane}` in argv for lane-reading gates.
- L2 — Header `argv` omits the interpreter and non-`.py` entries run as `bash <tool>` (76): the `/usr/bin/echo` run failed rc 126 because bash treated the ELF as a script (out3 stderr_tail `/usr/bin/echo: cannot execute binary file`) [obs]. All current lane gates are `.py` [inf], so impact is nil today. Fix: record the executed argv `[sys.executable, tool] + args` (or `['bash', tool] + args`) in the header.
- L3 — Digest covers only the entry file; sibling modules the gate imports from the export tree are undigested. Provenance is still sound (all bytes come from `git archive trev`), but the receipt cannot prove which `common` code ran [obs]. Fix: add `tree_sha256` = sha256 of `git -C lane archive trev` bytes (one line), or a per-file manifest line.
- L4 — Stdout is interpolated raw between header and footer (83), so a tool printing a line like `{"receipt_end": 1, …}` injects a parseable fake footer; downstream JSONL parsers must anchor on the first line and the LAST `receipt_end` line, or the runner must JSON-encode stdout into the footer (e.g. `"stdout"` field, one line) [obs from code; not demonstrated].
- L5 — `stderr_tail` caps at 400 chars (81): earlier diagnostics of a failing gate are lost from the receipt [obs]. Acceptable if intentional; consider recording `stderr_sha256` plus a sidecar file for long tails.

## Residual risk and verification gaps

- Receipts of lane-reading gates remain only as trustworthy as the `--lane` working copy until M6 lands; I did not test a dirty-lane run (read-only constraint on writing lane content in my own clone was satisfied by the clone's cleanliness — gap acknowledged).
- Timeout behavior (M1) is asserted from code, not exercised — no lane tool hangs deterministically; I did not stage one to avoid burning the time box [unk: exact partial-stdout behavior under TimeoutExpired].
- M5's concrete leak (hooksPath canary, user config) was not demonstrated end-to-end; evidence is code-level plus the C2 channel definitions [obs + inf].
- Whether any round-30 gate verifier compares `tool_revision` to `revision` is outside this review; until one exists, M2 is exploitable by any caller [unk: downstream consumers].
- `/fast/scratch/hyaku` had 218 entries and no repo above it at review time; scratch is shared, so the no-enclosing-repo condition may change under C2 runs [obs, transient].
