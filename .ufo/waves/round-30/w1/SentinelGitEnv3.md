# SentinelGitEnv3 — residual git-environment channels after the round-30 GIT CHILD ENV CONTRACT

Verdict: fails. The contract closes the three frozen channels but a git child built exactly as the contract specifies is still steerable four ways — LD_PRELOAD/PYTHONPATH (arbitrary code, proven inside a real lane tool), a `.git` pointer file dropped into a tool sandbox (`git init` follows it silently), repository-local `include`/`core.fsmonitor`/`core.hooksPath` (commands executed by `git status` and `git commit`), and a ceiling boundary at `cwd == GIT_CEILING_DIRECTORIES`. EDITOR/PAGER/SSH_ASKPASS reach the child but no frozen lane tool exercises them; `/etc/gitconfig`, the template directory and `safe.directory` are closed or fail-closed.

Every test built the child environment with the contract verbatim (`contract_env()` in each harness: drop `GIT_*`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=GIT_CONFIG_SYSTEM=/dev/null`, private `HOME`/`XDG_CONFIG_HOME`, `PATH=/usr/bin:/bin`, `GIT_CEILING_DIRECTORIES`), on git 2.56.0, entirely under `/fast/scratch/hyaku/tsukuroi-r30/SentinelGitEnv3/lab*`. No lane file was read for writing, no lane tool was run against the lane, and no `GIT_*` variable was set to a lane path.

1. **HIGH — loader and interpreter search paths pass straight through the contract's blacklist.** Rule (1) drops only names starting with `GIT_`; `LD_PRELOAD`, `LD_AUDIT`, `LD_LIBRARY_PATH` and `PYTHONPATH` survive, and rule (4)'s `PATH=/usr/bin:/bin` has no effect on any of them because the dynamic loader resolves `LD_PRELOAD` by path. [obs] A `gcc -shared` constructor .so preloaded into a real lane tool's git children loaded 934 times: `env ... LD_PRELOAD=/fast/scratch/hyaku/tsukuroi-r30/SentinelGitEnv3/lab7/x.so CANARY_LOG=.../pre.log python3 tools/check-kernel-taint.py --selftest` exits 0 with 56 of 56 selftest cases passing and `preload_lines=934`, i.e. every git child ran attacker code while the tool saw a clean run. [obs] `PYTHONPATH` pointing at a directory holding `canarymod.py` imported it in a `sys.executable` child (`python_rc=0`, `pythonpath_imported=true`, `.ufo/waves/round-30/w1/SentinelGitEnv3/probe-beyond-contract.py` T7 record in `/fast/scratch/hyaku/tsukuroi-r30/SentinelGitEnv3/lab/results.jsonl`). [inf] This is strictly stronger than every `GIT_*` channel the contract closes, because it needs no git feature at all; C2's "leaking 0 of 33" is compatible with a fully compromised tool. Smallest close: invert rule (1) into a whitelist — build the child env from a fixed key set (`PATH`, `LC_ALL`, `TMPDIR`, `HOME`, `XDG_CONFIG_HOME`, `GIT_CONFIG_NOSYSTEM`, `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_SYSTEM`, `GIT_CEILING_DIRECTORIES`, `GIT_OPTIONAL_LOCKS`, `GIT_PAGER`, explicit identity) — and pass the same `env=` to every `sys.executable` child. If a blacklist must stay, add `LD_PRELOAD LD_AUDIT LD_LIBRARY_PATH PYTHONPATH PYTHONHOME PYTHONSTARTUP`.

2. **HIGH (sandbox-side) — a `.git` pointer file is followed, including by `git init`.** [obs] With a `.git` file containing `gitdir: <lab3>/attacker-repo/.git` in a fresh sandbox directory, `git -C work rev-parse --git-dir` returns the attacker path (rc 0); `git -C work add -A` (rc 0) and `git -C work commit -qm pwn` (rc 0) write the attacker's index and HEAD — the commit subject lands in the attacker repo and its `pre-commit` hook runs (log `['pre-commit']`), while `git -C attacker-repo status --porcelain` shows the sandbox's files (`["D","payload","??","F"]`). [obs] Worse, `git init -q work2` over an existing hostile pointer exits 0, leaves `.git` a pointer (`dot_git_still_a_pointer=true`), and the next commit through it lands in the attacker repo (`attacker_commit_count=3`, subject `pwn2`, hook log `['pre-commit']`) — the tool believes it initialised its own sandbox. Evidence: `.ufo/waves/round-30/w1/SentinelGitEnv3/probe-beyond-contract-3.py` cases 3 and 4, lab `/fast/scratch/hyaku/tsukuroi-r30/SentinelGitEnv3/lab3`. Reachability: every target that builds a fixture repo inside `tempfile.mkdtemp` then runs `git init` is exposed (`tools/_revision.py:220`, `tools/check-kernel-taint.py:985`, `tools/check-adjacency-overlap.py:261,379`, `tools/mutants-kernel-taint.py:94`, `tools/mutants-adjacency-overlap.py:88`, `tools/check-memory-pressure.py:871`, `tools/check-storage-health.py:968`); the write needs a same-uid process to drop the entry between `mkdtemp` and `init` (mkdtemp gives a fresh 0700 directory, so there is no deterministic pre-creation, but an inotify watcher on the parent that `TMPDIR` names wins the race trivially). [inf] Nothing in the contract inspects the sandbox before the first git child and `GIT_CEILING_DIRECTORIES` does not cover a pointer inside the ceiling. Smallest close: after each `git init` (and before any other git command in a sandbox), require `os.path.isdir(<sandbox>/.git)` and `git -C <sandbox> rev-parse --absolute-git-dir == os.path.realpath(<sandbox>/.git)`; refuse the run otherwise — one `lexists` plus one `rev-parse` per sandbox.

3. **MEDIUM — repository-local config is an execution channel and `GIT_CONFIG_GLOBAL=/dev/null` does not narrow it.** [obs] A `[include] path = <hostile>` and an `[includeIf "gitdir:<repo>/"] path = <hostile>` appended to `.git/config` pull in a file that sets `core.fsmonitor`; `git -C repo status --porcelain` runs the fsmonitor program (canary log written) with the contract in force. [obs] `core.hooksPath` set directly in `.git/config` (commit rc 0, hook log `['pre-commit']`) and set through the same `includeIf` (log `['pre-commit']`) both execute on `git commit`. [obs] `-c core.fsmonitor=false` suppresses the fsmonitor (log absent) and `-c core.hooksPath=/nonexistent` suppresses the hook (log empty), and command-line `-c` beats the included value. [obs] The lane clone's own `.git/config` contains no `include`, `hooksPath`, `fsmonitor` or `filter` entry (`grep -nE` → none), and lane read verbs (`ls-tree`, `show`, `rev-parse`) do not trigger fsmonitor, so a trusted `--lane` is not currently a live exploit. [inf] The risk is a hostile or third-party `--lane` (or a lane whose `.git` another process edited) combined with `git status`-class commands; `include.path` also lets the repository config read any absolute path on the host. Smallest close: on every git call against a repo the tool did not create, pass `-c core.fsmonitor=false -c core.hooksPath=/nonexistent` (and `-c core.pager=cat`), and refuse a `--lane` whose config names `include`, `includeIf`, `fsmonitor`, `hooksPath` or `filter.*` (one `git config --file <lane>/.git/config --list --name-only`).

4. **MEDIUM-LOW — rule (5) is not enforced when the working directory is the ceiling.** [obs] With `GIT_CEILING_DIRECTORIES=<canary>/a`: cwd `<canary>/a/b/c` → rc 128 "not a git repository" (enforced); cwd `<canary>/a/b` → rc 128 (enforced); cwd `<canary>/a` (the ceiling itself) → rc 0, `--git-dir` returns `<canary>/.git` (escapes); cwd `<canary>/a` with ceiling `<canary>/a:<canary>` → rc 128 (enforced). Evidence: `probe-beyond-contract-3.py` case 5 and the follow-up ladder run, lab3. [inf] The contract's wording ("the tool's temporary directory's parent") is safe as long as every git call runs in a strict descendant of the parent, but a tool that runs `git -C <that parent>` — the shape `tools/probe-git-env-residual-r30.py` itself uses for its scratch-root check (`git(base_env, '-C', root, 'rev-parse', '--git-dir')`) — would escape. Smallest close: set the ceiling to the sandbox directory *and* its parent joined by `:`, or make the ceiling a strict ancestor and never run git with `cwd` equal to it; add one assertion that discovery from the sandbox fails.

5. **LOW — ambient `EDITOR`/`PAGER`/`LESS`/`VISUAL`/`SSH_ASKPASS` reach the git child, but no frozen lane tool exercises them.** [obs] Under the contract, `git commit` with an explicit identity and no `-m` invoked a hostile `EDITOR` (log shows the `COMMIT_EDITMSG` path, commit succeeded with the editor's subject "message from the editor"); a hostile `PAGER` was invoked when `git log` ran on a pty (`pager_on_tty=true`) and was not invoked with a pipe (`pager_on_pipe=false`), which is how every lane tool runs git. [obs] Every git commit in the lane tools passes `-m`/`-qm`/`-qam` (`grep` over `tools/*.py` finds no message-less commit), and `tools/_revision.py:62-67` already forces `GIT_PAGER=cat`; `SSH_ASKPASS` was not reached in a `git ls-remote ssh://localhost:1/` probe (git → `/usr/bin/ssh` failed with "Connection refused"; rule (4) also prevents planting a fake `ssh` on `PATH`) and no target uses a remote URL. [inf] Residual risk is a future commit-without-`-m`; the same whitelist as finding 1 removes it at no cost, and dropping `PAGER EDITOR VISUAL LESS SSH_ASKPASS SSH_ASKPASS_REQUIRE` is the two-line version.

6. **NONE — `/etc/gitconfig` and the system scope.** [obs] `/etc/gitconfig` does not exist on this host (`ls: cannot access`), and `GIT_CONFIG_NOSYSTEM=1` removes the system scope even when `GIT_CONFIG_SYSTEM` names a readable file: with a fake system config containing `canary.marker`, `git config --list --show-scope` shows no system entry. [obs] The one exception is the explicit `git config --system --get` scope, which reads the `GIT_CONFIG_SYSTEM` file regardless of `GIT_CONFIG_NOSYSTEM` (returned `system`, rc 0) — harmless because the contract points that variable at `/dev/null`. No close needed.

7. **NONE — the template directory is inert.** [obs] `GIT_TEMPLATE_DIR` placed in the ambient environment before the contract is dropped (`dropped=true`, hook not copied); `init.templateDir` reached through the system scope is ignored; the compiled-in default `/usr/share/git-core/templates` is `root root 0755` and `git init` copies only `*.sample` hooks, so a commit in the fresh repo fires nothing (`default_template_fired=""`). No close needed.

8. **NONE as steering — `safe.directory` and ownership.** [obs] An ambient attempt to pre-authorise every repository is erased by rule (1): with `GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=safe.directory GIT_CONFIG_VALUE_0=*` in the ambient env, the child env contains only the contract's own keys and `git rev-parse HEAD` succeeds on a same-owner repo; a repository-local `safe.directory=*` is visible but is not needed by the owner. [unk] The dubious-ownership refusal itself could not be provoked: changing a repository's owner needs root, which this lane forbids, and no root-owned git repository exists under `/usr/share` or `/opt` (find returned none). [inf] The behaviour is fail-closed (git refuses the repo rather than trusting it), so the residual is availability, not steering: a lane repo owned by a different uid (a CI runner) would now fail instead of being read, and no ambient config can lift that. Worth one sentence in the tool docstrings so a future uid change is not misread as a defect.

9. **LOW — `TMPDIR` pointing into a repository.** [obs] With `TMPDIR` inside a canary repository and the contract's ceiling set to the sandbox's parent, discovery from the sandbox fails (rc 128, "not a git repository"); without the ceiling it returns `<canary>/.git` (rc 0). [obs] A `git init` under such a `TMPDIR` succeeds and leaves the canary work tree with `?? tmp/` — transient tool files and a nested repository land inside another repository, which a later wildcard `git add` there would absorb. [inf] Low because the ceiling holds; the close is to create the sandbox with `mkdtemp` under a private root (`/fast/scratch`, `/dev/shm`) rather than honouring an inherited `TMPDIR`.

10. **Gap in the frozen counting command.** [obs] The three frozen channels are `path-wrapper`, `user-files`, `enclosing-repo` (`tools/probe-git-env-residual-r30.py:69`) and its env builder drops only `GIT_*` (`:74`); none of the eight shapes above is measured, so the declared `leaking 0 of 33` cannot be read as "no residual git-environment channel". [inf] Smallest honest counter move: add one channel per shape that a target can actually exercise — `sandbox-dotgit` (drop a `gitdir:` pointer into the target's temporary directory) and `ambient-helpers` (`EDITOR`/`PAGER`/`LD_PRELOAD` pointing at canaries) — and keep the contract's own close (findings 1–2) as the fix rather than widening the claim.
