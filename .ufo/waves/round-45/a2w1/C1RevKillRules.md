## Actionable gaps / wording

1. **“shape” is not a stable contract.** Current C1ExecPlaneDiff operationalizes it with line count, prefix, and ordered key names and also compares values for cross-revision differences, exempting only values that recur within a revision (`C1ExecPlaneDiff.md` §§3-4). A future check that only enforces shape could permit a harmful value change without changing keys. Prefer an explicit byte/value rule or a defined schema plus semantic invariants.
2. **Counter universe ambiguity.** The rule says “any predecessor census counter” but parenthesizes six names. C1ExecOtherCounters runs four additional counters only for no-harm; no item tests `score-pacnew-arm-r35.py` v1. If the six are exhaustive, change “any predecessor census counter” to “any of the six listed counters.” If not exhaustive, include the missing counter(s) in kill-bound comparison receipts. `score-pacnew-arm-r35.py` is explicitly superseded by r35b (`tools/score-pacnew-arm-r35b.py` docstring lines 1-3), so excluding v1 is reasonable only if the declaration identifies active counters.
3. **PASS→FAIL semantics are narrow by design.** It does not kill a counter already FAIL at base that worsens at implementation, nor does it flag field regressions while verdict remains the same. The r38 report gives a concrete same-verdict case that is stale at both ends; that is not a new harm, but the predicate should compare only meaningful regression fields, not silently treat every FAIL→FAIL as harmless. Current measured field comparisons found no new regression.
4. **Header is excluded.** The plane-diff item explicitly drops line 1, so changes to the census header/version are not detected by this rule. It is unchanged now; if the header is part of the observable contract, include it in the comparison or state the exclusion.
