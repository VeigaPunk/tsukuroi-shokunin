== P1: era selection under two rules ==
  EXPLICIT_VERSION_META v=12.9.4           whole=False -> pre-12.9.5  | X-only=True  -> 12.9.5+     | Y-only=True  -> 12.9.5+     | max-only=True
  EXPLICIT_VERSION_META v=12.9.5           whole=True  -> 12.9.5+     | X-only=True  -> 12.9.5+     | Y-only=True  -> 12.9.5+     | max-only=True
  EXPLICIT_VERSION_META v=12.9.6           whole=True  -> 12.9.5+     | X-only=True  -> 12.9.5+     | Y-only=True  -> 12.9.5+     | max-only=True
  EXPLICIT_VERSION_META v=999999999.9.9    whole=True  -> 12.9.5+     | X-only=True  -> 12.9.5+     | Y-only=True  -> 12.9.5+     | max-only=True
  Y_DIGIT9             v=12.999999999.4   whole=True  -> 12.9.5+     | X-only=True  -> 12.9.5+     | Y-only=True  -> 12.9.5+     | max-only=True
  Y_DIGIT9             v=0.999999999.0    whole=False -> pre-12.9.5  | X-only=False -> pre-12.9.5  | Y-only=True  -> 12.9.5+     | max-only=True
  note: battery code uses the whole tuple (Case.era_b: tuple(int(p) for p in version.split('.')) >= (12,9,5))
  note: gate code uses the whole tuple (check(): era_b = version >= VISIBILITY_ERA_SPLIT, version = parse_limine_version(flag))
  verdict: a rule reading ONLY the first component gives the SAME label as the whole tuple for
           every META version and for every Y version, so the Y family's docstring sentence
           ('reads the era from X alone answers era B for 0.999999999.0') is not satisfiable
           by a first-component-only rule (X=0 cannot yield era B); the rule that yields era B
           for 0.999999999.0 is a second-component(Y)-only or max-component rule.
