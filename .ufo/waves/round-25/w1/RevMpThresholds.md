# C2 MP5 cross-check — oomd defaults: capture versus man page versus shipped file

Verdict: PASS — `/etc/systemd/oomd.conf` on this host is the package's shipped default, unmodified; the commented defaults in the frozen capture (`SwapUsedLimit=90%`, `DefaultMemoryPressureLimit=60%`, `DefaultMemoryPressureDurationSec=30s`) match the installed file byte for byte, the upstream systemd v262 source byte for byte, and all three statements of the systemd 262 `oomd.conf(5)` man page. I recommend the MP5 row premise stand as drafted; this verdict is a recommendation, never an admission.

## Findings

1. The capture I reviewed is the frozen capture. [obs] `sha256sum` of `/home/vgpnk/Projects/shokunin/tsukuroi-shokunin/.ufo/waves/round-25/capture/capture.txt` returns `e60f1bbc1feb8f251c8b276f70342da5385d07b9ad747305e1f016e0df447136`, identical to the hash declared for this round's capture.

2. The capture shows an all-defaults-commented oomd configuration. [obs] In `capture.txt`, the section `### oomd-config` (line 81) counts active lines with `systemd-analyze cat-config systemd/oomd.conf | grep -vcE "^(#|;|$)"` and records `1` (lines 82 to 84, exit 0) — the single active line is the `[OOM]` section header. The full dump (lines 85 to 109) shows exactly one file header, `# /etc/systemd/oomd.conf` (line 86), then `[OOM]` with the three commented keys: `#SwapUsedLimit=90%` (line 106), `#DefaultMemoryPressureLimit=60%` (line 107), `#DefaultMemoryPressureDurationSec=30s` (line 108). No drop-in file headers appear.

3. An independent live rerun reproduces the capture. [obs] `systemd-analyze cat-config systemd/oomd.conf` (exit 0) printed the same single file header and the same three commented keys as `capture.txt:86-108`. `systemctl is-active systemd-oomd.service` returned `inactive` (exit 3) and `systemctl is-enabled systemd-oomd.service` and `systemd-oomd.socket` both returned `disabled` (exit 1), matching `capture.txt:71-80`. This is supporting context for the MP4 row, not my row.

4. The file is package-owned, and on Arch it is the only copy. [obs] `pacman -Qo /etc/systemd/oomd.conf` answers `owned by systemd 262-1`. `pacman -Ql systemd` lists the oomd-related package files as `/etc/systemd/oomd.conf`, the binary `/usr/lib/systemd/systemd-oomd`, the service and socket units, and the man pages — there is no `/usr/lib/systemd/oomd.conf` in the package. `stat` confirms `/usr/lib/systemd/oomd.conf`, `/run/systemd/oomd.conf` and `/usr/local/lib/systemd/oomd.conf` do not exist, and neither `/etc/systemd/oomd.conf.d/` nor `/usr/lib/systemd/oomd.conf.d/` exists, so there are no drop-ins that could override the defaults.

5. Package integrity flags two altered files, and oomd.conf is not one of them. [obs] `pacman -Qkk systemd` exits 1 with this complete per-file output: `warning: systemd: /etc/cryptsetup-keys.d (No such file or directory)`, `warning: systemd: /var/log/journal (GID mismatch)`, then three lines for `backup file: systemd: /etc/systemd/logind.conf (Modification time mismatch)`, `(Size mismatch)`, `(SHA256 checksum mismatch)`, and the summary `systemd: 1995 total files, 2 altered files`. There is no oomd.conf line at all, so the file passed the mtime, size and SHA256 checks. The presence of a genuinely modified backup file (`logind.conf`) on the same host shows `pacman -Qkk` does catch modified backup files here, so its silence on oomd.conf is informative, not vacuous. [obs] I report the `logind.conf` modification as a host fact; it belongs to the login plane, not the oomd plane, and I do not absorb it.

6. The installed file is byte-identical to the upstream v262 shipped default. [obs] `sha256sum /etc/systemd/oomd.conf` gives `c4aafc5d01251d260a578a4a2bbf345a12aff281902bcfe77413f41e93f6a93c`, and `curl` of `https://raw.githubusercontent.com/systemd/systemd/v262/src/oom/oomd.conf` piped to `sha256sum` gives the same value. The file's mtime is `2026-09-22 10:13:41 -0300` while the package install date is `Tue 20 Oct 2026 09:16:28 AM -03` (`pacman -Qi systemd`); pacman preserves archive mtimes, and a post-install edit would have moved the mtime into October and tripped the Qkk mtime check as it did for `logind.conf`. [inf] There is no `/etc/systemd/oomd.conf.pacnew`.

7. The systemd 262 man page states the same three defaults. [obs] I opened `https://man.archlinux.org/man/oomd.conf.5?format=plain` on 2026-10-22; the bare page URL failed twice this session (read tool `ECONNRESET`, then curl TLS error 35) while the plain variant of the same page succeeded; raw bytes sha256 `fd948dd4b671a43d618cc4d4205759b0586e3596ff0dfd2f564e4b445851914f`. Located quotes: under the `[OOM]` section options, for `SwapUsedLimit=`: "0% and 100%, inclusive. Defaults to 90%." (marked "Added in version 247"); for `DefaultMemoryPressureLimit=`: "Takes a fraction specified in the same way as SwapUsedLimit= above. Defaults to 60%." (added in version 247); for `DefaultMemoryPressureDurationSec=`: "Defaults to 30 seconds when unset or 0." (added in version 248). The upstream v262 source `https://raw.githubusercontent.com/systemd/systemd/v262/man/oomd.conf.xml` (sha256 `36ae3e474a6e5632a4d61ae91b4d930bc9c3657ebf9f9081db5b7ba4cc926617`) carries the identical statements. The installed package man page agrees: I decompressed `/usr/share/man/man5/oomd.conf.5.gz` (package-owned per `pacman -Ql`) to a scratch copy, and it reads "Defaults to 90%" for `SwapUsedLimit=`, "Defaults to 60%" for `DefaultMemoryPressureLimit=`, and "Defaults to 30 seconds when unset or 0" for `DefaultMemoryPressureDurationSec=`.

8. Version-freshness footnote for the entry. [obs] The v262 documentation adds keys beyond the three in the shipped file: `PrekillHookTimeoutSec=` (defaults to 0, added in version 260) and the OOM Rulesets `MemoryPressureAbove=`, `SwapUsageMax=`, `Action=`, `LastingSec=` mechanism (added in version 261, configured through separate `.oomrule` files, not `oomd.conf`). Their absence from the shipped `oomd.conf` is expected, since that file lists only the classic three keys; the entry should not claim the three commented keys are the complete v262 option set.

9. Conclusion for MP5. [obs] For the installed systemd 262, the memory-pressure default limit is 60 percent, the default duration is 30 seconds, and the default swap-use limit is 90 percent; the capture, the installed `/etc/systemd/oomd.conf`, the upstream v262 source file and the systemd 262 man page all agree on these three values, and no configuration source on the host overrides them. [unk] None — no mismatch and no open question remains within the MP5 scope.
