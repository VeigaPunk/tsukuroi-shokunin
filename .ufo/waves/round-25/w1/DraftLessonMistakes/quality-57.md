## Draft clarification (optional, to follow the criterion, as the R24 clarifications do)

R25 clarification to 57: the criterion binds the lane's own self-assessment surfaces — the axes table under the last `## Axes — ` heading, the capability table and `SHONEN.md` — and the counting commands those surfaces name. It is not a general detector for stale numbers in arbitrary prose: a row whose count is re-measured at the revision it is read from satisfies it. The check set is fixed before the run (K01 to K23, `SCORECARD.md:795`) and the command is `python3 tools/check-self-assessment.py --revision <REV>`, field `mismatches`; a run against a revision that does not contain the tool is a refusal, not a pass. The checker reads the repository only through `git show` and `git ls-tree` at the named revision, never through the working tree, so a run against an old revision measures that revision's bytes and not the current checkout. The cited before-state was measured with the same checker run against `b9046016` from the executor's clone, because at that revision (and at the declaration commit `6c580b15`) the lane holds no such path; the L1 integrates the tool. The before-state at the base is evidence of the defect, not a residual failure to repair: the base revision is immutable history and is not edited.
