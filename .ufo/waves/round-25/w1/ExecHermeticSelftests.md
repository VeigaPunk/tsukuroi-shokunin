## 4. Boot-chain-audit selftest

15. [obs] `bash tools/boot-chain-audit.sh --selftest` run from the extracted tree exited 0 and printed `TSUKUROI_BOOTCHAIN_SELFTEST: PASS total=45 failed=0`. Three runs at three revisions (`6c580b15`, `0cd9b28`, `master` `d5e6481`) printed the identical line. Evidence: `bootchain-selftest.out`, `bootchain-selftest-0cd9b28.out`.
16. [obs] The selftest is hermetic: it builds fake limine configuration files and fake extracted-initramfs trees under a private mktemp directory and never touches `/boot` or any UKI. The script's own header says "No sudo, no /boot, no host read", and the `sudo` calls in the source are confined to the live path (`tools/boot-chain-audit.sh:260`, `:261`, `:262`, `:1287`).
17. [obs] Proven empirically rather than by reading only. I put a stub `sudo` earlier on `PATH` that prints a marker and exits 111, and re-ran both selftests. Neither selftest invoked it: the marker count is 0 in stderr, the census still printed 97 of 97 passed, and the boot-chain selftest still printed `PASS total=45 failed=0`. Both exited 0.
18. [obs] One hygiene defect: the boot-chain selftest leaves its private mktemp tree behind on exit. With `TMPDIR` pointed at an empty scratch directory, one `tsukuroi-bootchain-selftest.XXXXXX` directory remained after the run. The cause is visible in the source: `run_selftest` sets `trap 'guarded_rm "${T:-}"' EXIT` at `tools/boot-chain-audit.sh:882` before `SELFTEST_TMP` is assigned at `:883`, and `guarded_rm` only removes paths under `${WORK}` or `${SELFTEST_TMP}`, so the cleanup refuses its own tree. The census selftest does not have this problem: its fixture tree is removed on exit. This is a residue leak under `/tmp` only, no host surface and no privilege involved.
19. [obs] Pre-existing residue from earlier sessions was already present under `/tmp` before this seat ran; I removed only the two directories my own runs created and left the rest alone.
