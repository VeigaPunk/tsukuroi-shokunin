4. [obs] No code path adds child totals. The only write to group->total is psi.c:409-411, inside collect_percpu_times, which reads only that group's own per-CPU state (psi.c:385-393). Each task updates every ancestor group through for_each_group in psi_task_change (psi.c:793-794, 909-922), and each cgroup's psi group points at its parent's group (psi.c:1127). A search of psi.c for child lists finds only trigger lists (psi.c:483, 617, 1473). So the mechanism reading holds: a parent total is never computed as the sum of its children.

5. [obs] A parent total is a nonidle-weighted average over CPUs. Each sampling period adds the sum over CPUs of (stall time times nonidle time), divided by the sum of nonidle time (psi.c:385-393, 409-411). The per-CPU states come from the group's own task counts (test_states at psi.c:243-269; record_times at psi.c:764-791; psi_group_change at psi.c:796-883). This host has 32 online CPUs (cat /sys/devices/system/cpu/online printed 0-31), so the weighting applies here.

6. [inf] Derived from psi.c:385-411, not measured on this host, and using some totals only: a parent total can be lower than, equal to, or higher than the sum of its children's totals at one instant.
   - Lower: two children each stalled on a different CPU for the same second. Each gains 1 s, so the sum is 2 s. The parent gains (1 x 1 + 1 x 1) / (1 + 1) = 1 s.
   - Child above parent: a child stalled on CPU0 for 1 s, while the parent also has a running task on CPU1 for that second. The child gains 1 s and the parent gains (1 x 1 + 0 x 1) / (1 + 1) = 0.5 s. So the MP3 action's line "a child can legitimately exceed its parent" is true, but its stated reason ("time passes between the reads") is incomplete, because it can happen at a single instant.
   - Higher: the parent has its own task stalled on CPU1 for 1 s, and its only child runs on CPU0 without stalling. The parent gains 0.5 s and the sum of children is 0.

7. [inf] Equality holds in two special cases. (a) A parent whose only child carries all of its tasks: the parent's per-CPU state is then the child's, so the parent gains exactly what the child gains and equals the child's total plus whatever offset the parent accumulated earlier; with no earlier history it equals the sum. (b) Several children whose stalls never overlap and all sit on one CPU: the parent equals the sum, up to the jiffy rounding of the nonidle weight at psi.c:389.

8. [obs] Live check of case (a). /sys/fs/cgroup/user.slice/cgroup.procs is empty (exit 0), and the only child directory of user.slice is user-1000.slice (directory listing). Over six seconds, four samples gave some totals of 5363754 (user.slice) and 5352644 (user-1000.slice), then 5363760 and 5352650, then 5363803 and 5352693, then 5363817 and 5352707. The gap stayed at 11110 µs, and both totals gained the same increments each time (+6, +43, +14 µs). The increments follow the single-child rule. The gap is a fixed offset from earlier history [inf]. On this host the inequality holds because of that history, not because of the rule the sentence states.

10. [obs] [inf] Judgement of "a parent total is not the sum of its children." The sentence appears in the entry statement (memory-pressure-r25.md:150-151), the JSON statement (memory-pressure-r25.json:182) and the SKILL decision row (SKILL.md:2315), all at the measured revision. No cited source says it. The lane's S117 row claims that psi.h lines 37-40 show the root file is "not a sum of child cgroups" (SOURCES.md:123), but those lines only define the mapping. As a mechanism claim it holds (finding 4). As a claim about values it is false (findings 6 and 7), and it is unsourced. For the root, the live cgroup.procs file lists 2525 PIDs, so the root's own tasks are part of its total and it is not expected to equal the sum of its top-level children [inf]. Suggested wording: "A parent's total is accumulated from its own per-CPU state over its whole subtree (psi.c:385-411). It is never computed by adding child totals, so it need not equal their sum: it can be lower when child stalls overlap across CPUs and higher when the parent has its own stalled tasks."
