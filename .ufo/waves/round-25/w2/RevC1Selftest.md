# RevC1Selftest — selftest review of tools/check-self-assessment.py (round 25, wave 2)

Verdict: the selftest holds on expectation independence and lane hermeticity, and every rule K01 to K23 plus every declared setup error does fire when broken (7 suite cases plus 22 of my own probes), but it is not a clean hold: the selftest is not hermetic against the host's global git config (demonstrated crash under `commit.gpgsign=true`), it checks only the first four SHONEN boxes so a broken fifth box passes silently (demonstrated), and its own kill power covers only 6 of 23 rules, leaving 17 rules guarded against false positives but not against silent always-match regressions. ## Findings

1. [obs] `--selftest` passes at the measured revision. Command `python3 tools/check-self-assessment.py --selftest` from the lane root: exit 0, JSON `"selftest": "PASS"`, 7 cases, 0 failures; per case results clean=exit 0 ids=[], stale-ordinal=1 `['K02']`, stale-count=1 `['K07']`, unstated-fact=1 `['K12']`, missing-capability-path=1 `['K16']`, shonen-x-without-verifier=1 `['K20']`, missing-axes-table=exit 2.

2. [obs] Expected finding ids are literals in the source and independent of the computation. The ids are hard-coded per case in `fixture_files` at `/home/vgpnk/Projects/shokunin/tsukuroi-shokunin/tools/check-self-assessment.py:742-762` (for example `"expected_mismatch_ids": ["K02"]` at line 747). `build_fixture` serializes them into each fixture repo as `expected-findings.json` and commits them (lines 771-787); `run_selftest` reads the expectation back out of the commit through Git (`show_blob(repo, "HEAD", "expected-findings.json")`, line 798) and compares with exact exit-code equality and exact id-list equality (lines 807-812). Nothing derived from `evaluate` feeds the expectation, so the computation cannot pass by construction. [inf] Two residual limits: both the expectation read-back and the check inputs flow through the same git read layer (`show_blob`), so a defect in that shared layer could not be caught by this selftest; and the ids are maintained in the same file as the implementation, so a wholesale renumbering would require lockstep edits — but any real divergence between ids and behavior fails loudly (exact list compare), never silently.

3. [obs] Fixtures are hermetic toward the lane and the network. Both temp roots come from `tempfile.mkdtemp` (`self-assessment-selftest-` line 790, `self-assessment-census-` line 138); the census check runs `git archive` of the fixture repo into its own temp dir and extracts with `tarfile.extractall(..., filter="data")` (line 141); cleanup is `shutil.rmtree(root, ignore_errors=True)` in a `finally` (lines 819-822). No socket or network call exists anywhere in the file; the only subprocesses are `git` and `bash` on fixture content. During `--selftest` the census script that executes is the fixture's own 2-line echo script, never the lane's real census. Lane cleanliness verified: `git status --porcelain | wc -l` was 38 before and after the selftest and all probe runs (pre-existing working-copy state, unchanged).

4. [obs] Finding: the fixtures are not hermetic against the host's global git config. `git init` runs with the fully ambient environment (line 776, no `env=`), and `git_env()` (lines 60-67) only strips `GIT_*` variables and sets `GIT_CONFIG_NOSYSTEM=1`; global `~/.gitconfig`, `core.hooksPath`, `init.templateDir` and `commit.gpgsign` all stay live for init, add and commit. Demonstrated: with `HOME` pointed at a directory holding a `.gitconfig` with `[commit] gpgsign = true`, the same selftest command crashes with an unhandled traceback and no JSON: exit 1, ending in `subprocess.CalledProcessError: Command '['git', '-C', '/tmp/self-assessment-selftest-tp3dks3m/clean', '-c', 'user.name=fixture', ..., 'commit', '-q', '-m', 'fixture: clean']' returned non-zero exit status 128.` (capture `r25-revc1-gpg.err`). Two consequences: on a host with signing or hooking config the selftest cannot run at all, and a crash exits 1, which is the same code the tool returns for a failing selftest (`EXIT_MISMATCH`), so an exit-code-only consumer cannot distinguish crash from FAIL. [inf] Not a false-pass: the crash is loud, and a content-mutating global pre-commit hook would have to deliberately forge fixtures to flip a case. A `GIT_CONFIG_GLOBAL=/dev/null` (or isolated `HOME`) in `git_env()` would close the class.

5. [obs] Finding: only the first four SHONEN boxes are checked; a broken fifth box passes. The K20-K23 loop is `for number in range(4): lo, hi = boxes[number]` (lines 603-605). Demonstrated: appending a fifth box marked `[x]` whose evidence names `corpus/definitely-missing.md` (absent at the revision, and `[x]` with no non-author verifier) yields exit 0 and zero mismatches (probe `fifth-box-broken-unchecked`). The declared grammar at `SCORECARD.md:803` section says "A row or box that names no path is a mismatch. A box marked `[x]` must contain `non-author verifier:` and a name" without limiting which boxes; the tool and its selftest codify exactly four. A lane could append a broken fifth promotion box and still pass C1 with exit 0.

6. [obs] Kill power per rule, closed by probe. The committed suite proves 6 rules (K02, K07, K12, K16, K20) and 1 of 4 setup errors (missing axes table). My 22-probe harness (`probe_rules.py`, same module imported read-only, fixture repos in scratch) shows the remaining 17 rules and 3 setup errors all fire with exit 1 and exactly the expected single id: K01, K03, K04, K05, K06 (score overrides), K08, K09, K10, K11 (stated count overrides), K13 plus K17 together (census script echo changed from 3 to 5 cases — the shared measurement fires both), K14 (`--identity` wording flipped against a census script arm), K15 (overlap-table wording flipped against PROVINCE.md), K17 (capability row path made absent), K18, K19 (capability row paths made absent), K21 (box 2 `[x]` without verifier), K22 (box 3 absent path), K23 (box 4 names no path), and setup exits 2 for a missing axis row, a missing capability row and fewer than four boxes. Result: `probes=22 failed=0`, so no dead rule exists today. [inf] The gap is durability, not correctness: the committed selftest would not catch a future regression that turns one of the 17 uncovered rules into an always-match check, because the clean fixture only proves those rules do not fire spuriously.

7. [obs] Adjacent calibration defect the selftest cannot see: the depth row's quoted command is wrong in the real SCORECARD. `SCORECARD.md:828` (the current round-25 axes table) states "297 table lines (`grep -c '^\|' SKILL.md`)". Under GNU grep's BRE, `^\|` is alternation (`^` or empty), so the pattern matches every line: verified on a 3-line file with 2 pipe-prefixed lines, `grep -c '^\|'` returns 3 while `grep -c '^|'` returns 2. At the measured revision: SKILL.md has 2355 lines, `grep -c '^\|' SKILL.md` returns 2355, `grep -c '^|' SKILL.md` returns 297. So re-running the quoted command, which the table's closing text declares "the only source of the quoted counts", reproduces 2355, not the quoted 297. The checker's K09 (lines 475-480) never runs the quoted command; it re-implements the declared semantic ("SKILL.md lines that start with `|`", `SCORECARD.md:795`) in Python, so K09 passes while the row's own evidence pointer is unreproducible. Note the fixture template quotes the correct form `grep -c '^|' SKILL.md` (line 690), which is why no fixture case can ever exercise this divergence class.

8. [inf] Minor robustness notes, no current defect. `census_case_count` takes the first `(\d+) cases` match in the output (line 148) rather than the summary line, so an intermediate "(N cases" string in a future census script would be miscounted. `tarfile.extractall(..., filter="data")` needs the backported filter API (host Python 3.14.8, fine). In the K01-K06 scan the last match by line order wins and, within one line, the last `finditer` match wins; the declaration fixes line order only, so the within-line tie is undefined but consistent.
