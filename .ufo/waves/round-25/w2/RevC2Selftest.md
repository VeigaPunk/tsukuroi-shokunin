## Findings, most serious first

1. [obs] The non-empty `statement` requirement is not in the declaration. SCORECARD.md line 797 says a row counts "only if it carries a verdict and action". The refinements at SCORECARD.md lines 805-813 add no statement rule, and no other lane text in SKILL.md, the lesson or the entry rules declares one. The tool adds it in its docstring (/home/vgpnk/Projects/shokunin/tsukuroi-shokunin/tools/check-memory-pressure.py line 7) and in code (lines 540-545). Test: I blanked only the statement of MP3 and kept verdict and action. The tool returned exit 1, verified 5, finding MP-STATEMENT-EMPTY. Under the declared text that row counts. All six committed rows carry non-empty statements, so the measured count is unaffected. [unk] The git history shows one commit for this tool, so I cannot tell whether the requirement was added after the refinements were fixed.

2. [obs] "At least one" is implemented as "every" for sources and for pointers. The declaration (SCORECARD.md line 797) requires at least one qualifying source and at least one valid pointer. The tool attaches a blocking finding to every bad source (check-memory-pressure.py lines 553-576) and to every bad pointer (lines 617-624), and a row is verified only when no finding in it is blocking (line 634). The docstring contradicts itself: line 8 says "every source" and line 14 says "at least one capture pointer". Test B: MP1 with one extra header pointer gave exit 1, verified 5, MP-CAPTURE-POINTER-HEADER. Test C: MP4 with one extra unknown source gave exit 1, verified 5, MP-SOURCE-MISSING. The direction is fail-safe, and the measured result is unchanged, because every source and pointer of every committed row qualifies.

3. [obs] The "updated in place this round" route is not checked against the claim base. check-memory-pressure.py lines 563-564 compare only the logged new value with the current `recheck` cell, and require old to differ from new. The tool never reads b9046016 or any earlier commit. Test D: I changed S121's opened date to 2026-10-19 in corpus/SOURCES.md and appended the line "S121 recheck: off-release -> on-release" to the lesson. The tool returned exit 0, verified 6. The committed lesson says the opposite: /home/vgpnk/Projects/shokunin/tsukuroi-shokunin/corpus/lessons/round-25.md line 38 reads "Registry recheck log (old -> new): none." The measured count does not use this route, because every listed source is opened 2026-10-22 (corpus/SOURCES.md lines 121-131). The route can still pass a false log line for a pre-existing source.

4. [obs] The SKILL row rule (R5) accepts any table line that names the id. The declaration requires "a SKILL.md decision-table row, appended this round, that names the row id" (SCORECARD.md line 797). The tool accepts any line that starts with "|" and mentions the id (check-memory-pressure.py lines 626-629 and 394-395). Test I: I removed the MP1 and MP6 decision rows (SKILL.md lines 2313 and 2318) and kept the registry gate row at SKILL.md line 2355, which says "0 six rows MP1 to MP6 verified". The tool returned exit 0, verified 6. This is not exercised at 5e7c04ec, where the decision rows exist and the base revision has no MP lines in SKILL.md.

5. [obs] A malformed row's finding is dropped from the output. For a row that is not an object, the tool records MP-ROW-SHAPE in a local list and continues (check-memory-pressure.py lines 530-533), so the finding never reaches the top-level findings list, which is filled at line 664. Test F: appending a non-object element to the rows gave exit 0, verified 6, and an empty findings list. The count is honest (six valid rows), but the defect is invisible. The malformed-row cases are also inconsistent. A broken second copy of MP1 (Test E) leaves exit 0 with verified 6. An unknown id (Test G, MP7) forces exit 1 and verified 0 (lines 666-668). Neither difference is declared.

6. [obs] Entry-level quotes are non-blocking. check-memory-pressure.py lines 599-605 mark MP-QUOTE-MISMATCH and MP-QUOTE-SOURCE-UNKNOWN as non-blocking. Test H: I replaced MP2's published quote with a sentence the lesson does not contain. The result was exit 0, verified 6, and a non-blocking MP-QUOTE-MISMATCH. The counted quote is the lesson's Gate quote, so the declared rule is met, but the published entry can display text that is not in the lesson.

7. [obs] R3 can count prose as a "located quote". The function gate_quotes (lines 338-346) reads any non-table line of the Gate section that contains a quote mark, and takes the first backticked span. On the real lesson it returns the one-word string `mined` (corpus/lessons/round-25.md line 9) as a quote for S115. The committed rows are not affected, because each also has real table quotes. The tool also cannot check that a quote is verbatim from its source. It checks only the lesson text and a word count of at most 25.

Hermetic: run_fixture (lines 781-804) commits each fixture into a temporary git repository and reads it only through git show at that commit, so no lane byte is touched. Expectations: each of the 32 cases commits an exact list of blocking ids, an exit code and a verified count (lines 842-943), and the sandbox run passed all 32 with exit 0. Of the 29 failing-input cases, R1 has 3, R2 has 5, R3 has 2, R4 has 8, R5 has 1, and the remaining 10 cover entry and capture level errors. Gaps: the comparison keeps only blocking ids (line 798), so MP-QUOTE-MISMATCH, MP-QUOTE-SOURCE-UNKNOWN and MP-SUPERSEDES-SHAPE are never asserted. Eleven emitted ids have no case at all: MP-CAPTURE-PATH-MISMATCH, MP-CAPTURE-POINTER-MISSING, MP-CAPTURE-POINTER-PATH, MP-CAPTURE-POINTER-SHAPE, MP-QUOTE-MISMATCH, MP-QUOTE-SOURCE-UNKNOWN, MP-QUOTES-SHAPE, MP-ROW-ID-DUPLICATE, MP-ROW-SHAPE, MP-SOURCE-DUPLICATE and MP-SUPERSEDES-SHAPE. No case covers a multi-source or multi-pointer row with one bad member, the base-comparison gap, the registry-row loophole, duplicate or non-object rows, or the command-line path (main, lines 961-986).
