# systemd 262 credentials_boot_policy — this host's applicability (round 66)

Reading plane: what the systemd v262 `systemd.credentials_boot_policy=` kernel
command line option actually decides, and whether any of it binds THIS host's
boot chain (limine, UKI-stub boots, no TPM2, SecureBoot disabled). Detection and
report only; nothing is built, signed, configured or re-bootable from this note.

Scope (cited to S283 only — the row id, its anchor section and the bullet that
carries it). The systemd v262 release body, section "Changes in the system and
service manager:", documents a new kernel command line option
`systemd.credentials_boot_policy=` that controls WHEN boot credentials encrypted
with the "null" key are ACCEPTED. It accepts four values: "strict" (never),
"tofu" (first boot or no TPM2), "relaxed" (SecureBoot disabled or no TPM2 — the
default and the previous behaviour) and "off" (always). Its scope is exactly the
null-key credentials: the same bullet states it does not affect credentials
encrypted with host or TPM2 keys. This note measures the option's applicability
on this host; it does not extend the documented semantics.
