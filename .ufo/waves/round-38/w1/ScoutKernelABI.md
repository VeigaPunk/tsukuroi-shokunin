## 4. Could the five names change?
- No kernel doc promises they won't. The only stronger anchor is the uapi enum `include/uapi/linux/btrfs.h:735-752` `BTRFS_DEV_STAT_WRITE_ERRS, READ_ERRS, FLUSH_ERRS, CORRUPTION_ERRS, GENERATION_ERRS, VALUES_MAX`, which feeds the ioctl (a uapi, stable-in-practice contract) and which the sysfs printer's comment ties order to. Renaming the sysfs keys would be a user-visible break and is [INFERENCE] unlikely; adding a sixth key is plausible (VALUES_MAX is the extension point) — a census parser should therefore match the five names by key, tolerate extra lines, and treat the word `invalid` as a distinct state (sysfs.c ~2080). I did not search lkml history for any proposed rename; unrun.
- Discrepancy worth a line in the lane's notes: the commit message says names "are the same as used in other device stat outputs", but btrfs-progs `btrfs device stats` prints `write_io_errs`, `read_io_errs`, `flush_io_errs` (btrfs-device.rst lines 239-243) whereas sysfs prints `write_errs`, `read_errs`, `flush_errs` (sysfs.c 2086-2090; ch-sysfs.rst 286-290). A parser must not assume the CLI spellings in sysfs, or the converse.
