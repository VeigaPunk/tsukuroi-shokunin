20|## Core
21|
22|- **Watchdog liveness** — census `SURFACE watchdog`: watchdog pid/start and log freshness, plus `.ufo/state/*.round` values against each lane's latest launch-ledger entry.
23|- **Wave settlement** — `SURFACE waves`: registry/dispatch/results presence and per-wave age; report settled, unsettled, or empty without calling an aged wave failed.
24|- **Kill/OOM classes** — structured, MESSAGE-free journal records carrying catalog IDs for kernel-OOM unit notices, oomd notices, coredumps, unit-process SIGKILL results and unit failures, plus a distinct numeric signal-11 coredump count; independently labeled user/system scopes, never summed. Positive OOM notices and observed `UNIT_RESULT=oom-kill` retain critical `OOM_KILL_JOURNAL`/DRIFT alarms. Failed-unit subject metadata preserves fleet-only `UNIT_FAILURE_JOURNAL` versus non-fleet `UNIT_FAILURE_OUT_OF_SCOPE` with tsukuroi triage routing; absent or unsafe subject metadata remains unknown. `SURFACE cgroup` retains selected-scope kernel memory-event counters, not a replacement for all journal alarms. Journal labels are client-set, not authenticated producer identity; records are not unique victims or fleet-cause attribution. Other structured signals are unimplemented; arbitrary signals without retained records remain unmeasured. See `corpus/knowledge/journal-alarm-routing-r14.md`.
25|- **Same-boot journal window since anchor** — explicit read-only probe `tools/mori-journal-window.py --anchor PATH --scope user|system` (round-16 build; admitted round 16 — `corpus/lessons/round-16-verifier-spotcheck.md:11`). Reads one journal scope from an operator-retained `mori-journal-anchor-v1` cursor using MESSAGE-free output fields. The first record must match the anchor cursor and boot exactly and is dropped; every later record must be a scalar-cursor object in that same boot. Reports `records_after_anchor` and four separate `positive_*` subset counts (kernel OOM, unit OOM, unit signal, process SIGKILL) using the r15 predicates; no total, victim, emitter or completeness claim. Missing or vacuumed anchor, boot mismatch, malformed, duplicate or truncated capture, nonzero rc, stderr, timeout and overflow return `MORI_JOURNAL_WINDOW_UNAVAILABLE` with no positive totals. Byte equality is conservative: libsystemd documents that one entry may carry several cursor strings, so a mismatch refuses without proving deletion and no dedup is claimed. The anchor is never advanced, stored or written by the probe.
26|- **Resource runway** — `SURFACE disk` and `SURFACE cgroup`: default `df -P` targets `$ROOT` and `/tmp`, since-boot device-write average, memory PSI/fill/avail, and scope high-watermark.
27|- **tmux relevance** — `SURFACE tmux`: classify sessions by pane path; bound the freshness probe for each relevant session.
28|- **Lane silence** — `SURFACE lane.<id>` rows: launch-anchored authorship grading as silent, progressing, progressing-weak, young, not-open, or unavailable.
