## Axes
- **C3 / adjacency evidence:** the main lane counter passes a contradictory published sibling locator and accepts a quote that does not establish the linked proposition.
- **Provenance / identity binding:** the displayed sibling path and abbreviated commit are not bound to the registry entry.
- **Counter robustness:** caller-supplied fixture overrides can make fabricated evidence score as PASS; the hard-coded stub self-test is not a general anti-stub guarantee.

## Counterexamples and evidence

1. **The visible sibling/commit locator can be false and the counted counter still PASSes (strongest default-path defect).** I cloned the frozen lane into scratch, committed a mutation on `master` and advanced the fixture's `origin/master` to that commit so the revision-binding checker could evaluate it. The mutation changed the OUT-009 table cell from `revenger-shokunin/PROVINCE.md @ cf02419276e5` to `kagi-shokunin/PROVINCE.md @ deadbeefcafe`, leaving the registry, portable digest appendix, and actual pinned revenger bytes unchanged. The counter returned `PASS`, `anchors_checker_rc=0`, and `quote_at_pin_ok=9`: receipt `R50CritCheatC3/z3-clone-false-pin-cells.json` (counter JSON); the baseline clone also PASSed in `z0-clone-baseline.json`. Source: `tools/check-adjacency-table-r50.py:127-131` takes the repo and commit from the registry, not the published cell; `tools/check-adjacency-anchors.py:419-430` tests id+quote, id+commit, digest, and heading with separate `any(...)` searches over the entire section. The appendix supplies the real full commit/digest while the table cell can claim a different sibling and commit. **This is a real default-path provenance/identity defect**, not just a fixture override.

2. **A different in-blob sentence can replace the ownership quote, and even a one-word quote can pass the full counted counter when the registry is changed consistently.** In a landed fixture-clone revision, I replaced OUT-009's quote in both the table and registry with the sibling's refusal sentence (`Refuses: live-target execution beyond the declared target and lifecycle`), and set registry `quote_line=19`; the counter PASSed with checker rc 0 and all 9 pin/live matches: `z4-clone-quote-and-registry-moved.json`. A second mutation used only `the` in the table and registry at line 5; it also PASSed: `z6-clone-single-word-both-sides.json`. In contrast, changing only the province quote cell to another sentence while leaving the registry alone was caught on the default path (`z1-clone-table-quote-elsewhere.json`, checker rc 1), and the quote-line mismatch was rejected (`z5-clone-registry-quote-line-mismatch.json`). Sources: counter content leg checks substring membership in the whole pinned/tip text (`check-adjacency-table-r50.py:143-159`); the separate checker enforces the registry's quote as a substring of `quote_line` (`check-adjacency-anchors.py:609-629`) but accepts a one-word quote and, for this sibling's sole title heading, a quote on another line within that heading's section. The quoted refusal does not support the adjacent ownership proposition; the single token `the` is not meaningful ownership evidence. The counter verifies byte presence, not proposition support.

3. **The exact requested stub/fabricated-sibling cases and the override cheat.** The counter's own `stub_province()` has only 7 distinct IDs in ADJ ownership cells (source `check-adjacency-table-r50.py:170-190`). With the stub and empty scratch siblings, shape legs all pass (7 rows/links, 0 bare ranges, 7 anchors and registry rows), but it FAILs: `quote_at_pin_ok=0`, `live_quote_ok=0`, `stub_fails=1` (`a2-stub-noskip.json`). A scratch `stub-shokunin` repo containing the stub heading/quote but the stub registry's placeholder 40-zero commit still fails to resolve that commit (`b1-stub-with-stub-sibling.json`). I then updated the stub registry with the fabricated repo's real commit and digest: it still FAILs because only 7 distinct IDs can pass, while the scored predicate hard-codes `quote_at_pin_ok == 9` and `live_quote_ok >= 8` (`b1b-stub-true-digest.json`; predicate source `check-adjacency-table-r50.py:366-368`). Thus the literal stub does not PASS; the decisive leg is the exact 9-count threshold, not the stub's own shape.

   However, a fabricated province with 9 distinct OUT references, a matching fabricated registry, and a committed scratch sibling named `fake` **does PASS** when supplied through `--province-file`, `--registry-file`, and `--siblings-root`: `b2-adapted-stub-fake-sibling.json` records exit 0, all shape/content counts satisfied, `anchors_checker_rc=0`, and `stub_fails=1`. The checker rc is from the real frozen lane because `run()` invokes the checker only with `--revision` and lane path; the overrides are not passed to it (`check-adjacency-table-r50.py:350-357`), while the two content legs do consume `a.siblings_root` (`:331`, `:347-349`). A variant using sibling name `stub` but omitting the built-in stub's literal quote also PASSed (`b4-stub-named-sibling-no-stub-quote.json`): `stub_fails` only tests that hard-coded quote against the supplied root, so the probe can be dodged by a different name or content (`:347-349`). Therefore `--siblings-root` can satisfy the new content legs with caller-fabricated bytes when the fixture province/registry are also caller-supplied; checker rc 0 is unrelated to those overrides. `--skip-anchors-check` is not a bypass: it sets checker rc to -1 and the predicate requires 0, so it forces FAIL (`01-skip-anchors-check.json`; source `:350-355`, `:366-368`).

4. **Digest mutation correctly fails.** Flipping one hex character in the real OUT-005 registry digest yields `quote_at_pin_ok=8`, `live_quote_ok=9`, verdict FAIL, with detail `registry blob sha256 does not match the pinned blob`: `c1-real-prov-digest-mutated.json`. 5. **Exact count is brittle.** Adding a tenth fully pinned anchor/reference to a fixture province yields `quote_at_pin_ok=10`, `live_quote_ok=10`, but FAIL solely because the predicate requires exactly 9: `g1-tenth-verified-anchor.json`; predicate at `check-adjacency-table-r50.py:366-368`. This rejects a valid additional anchor rather than asserting that all referenced anchors verify.

## Which leg guarantees content?
For the actual lane revision, the `anchors_checker_rc == 0` leg is the effective published-content guarantee: it verifies the committed registry snapshot's digest, line-specific quote, heading section and publication (`check-adjacency-anchors.py:598-629`, `:632-637`). The new `quote_at_pin_ok` / `live_quote_ok` legs are weaker: they use caller-selected `--siblings-root`, search quote/heading anywhere in the blob, and do not bind the displayed sibling/commit cell (`check-adjacency-table-r50.py:127-159`). Moreover, checker input is not wired to `--province-file`/`--registry-file`/`--siblings-root` (`:350-355`), so its PASS cannot certify override inputs. The default-path locator mismatch in item 1 shows the checker still has a same-section, cross-line binding gap.

## Smallest safe correction
- Parse each published OUT row and bind its **own** sibling path, abbreviated commit, heading and quote to that ID's registry record; require the displayed path to equal the registry sibling/path and the displayed commit to be a prefix of that record's full commit. Do not let different section lines independently satisfy id/quote/commit/digest/heading. Keep the digest appendix check, but make it supplemental to the row-level binding.
- For semantic evidence, require the registry quote to be a meaningful excerpt tied to its declared source line and require the proposition/ownership scope to be explicitly supported; at minimum, reject token-length quotes (e.g. `the`). A byte-substring test cannot establish entailment.
- Make the numeric content predicate all-referenced-anchors-valid (and, if needed, separately assert the expected OUT ID set) instead of hard-coding `== 9`. Ensure fixture overrides are either non-scoring test inputs or that the checker validates the same overridden province, registry, and sibling root; never report the lane checker’s independent rc as validation of override data.
