## Findings

**D1 (medium) — self-contradiction guard over-matches across rows.** `bind()` scans body lines for `ROW GR\d VERDICT: \w+` and forces the seat to `partly` whenever `r != row` — even if the inner verdict *agrees* in word. Reproduced: a GR2 `holds` report whose body recaps "ROW GR1 VERDICT: holds" is coerced to `partly` on the current hash and BLOCKS GR2 (fixture F10b → FAIL, `blocking=['R48RevGR2b']`). A reviewer quoting another row's outcome, or the corpus gate-status wording, thus produces a false block of an otherwise unanimous row. Fails closed (cannot launder a PASS), but it's a real false-negative mechanism: same-row same-word restatement is the only case that survives. Fix: compare `w != m.group(2)` only when `r == row`; a different-row token should be ignored or at most noted.

**D2 (medium) — negative-grammar gaps: malformed negatives vanish instead of blocking.** A line-1 verdict word outside `holds|partly|fails` makes the seat unbound (fixture F7: `ROW GR1 VERDICT: bogus` → PASS, seat invisible, no block). Same vanishing for a trailing space, uppercase-hash line, or a non-binding line-1 (F16/F17). So only a *grammatically perfect* negative counts as a negative; a dissenting seat that fumbles the format is silently dropped from both credit and blocking. Partial mitigation: an in-body `ROW GR<n> VERDICT: fails|partly` token still coerces-and-blocks even when line 1 is malformed (the `ANY_VERDICT_RE` pass runs on lines[1:] regardless of line-0 parse). But a dissenting seat with a clean body and a broken header line disappears. With ≥3 clean `holds` seats remaining the row still passes — dissent is erased, not counted.

**D3 (medium) — `any_fails` hash-scope asymmetry vs docstring.** Docstring/amendment: negatives block "on the CURRENT row hash". Code: `blocking` honors the hash, but `any_fails` ignores it — a `fails` on a *stale/wrong* hash blocks the row (F6: FAIL, GR1 `any_fails`), while a `partly` on the same stale hash is ignored (F6b: PASS). Either both should be hash-scoped (a stale-hash `fails` is mis-binding evidence, not a current-row negative) or the asymmetry should be documented. As-is, a seat reading wrong-old bytes and honestly saying `fails` vetoes the current row; saying `partly` does not.

**D4 (medium) — README mark negation regex is phrase-list.** `NEGATE_RE = unadmitted|not admitted|never admitted|stay pending|stays pending`. Reproduced: README line `- btrfs-scrub-grounding-r45.md not yet admitted round 48` (fixture F19) contains both required substrings, matches none of the negation phrases, and the mark counts → PASS with marks_ok 3. Other evasions: "still pending", "admission withheld", "not admitted this round". The marks leg is additive (still needs verdicts+quotes+structural), so this only counts a *misleading* mark, but the F2 negation-proof intent is unmet beyond its literal word list.

**D5 (low) — seat citation resolution is basename-union and bounds-only.** (a) `verify_citation` resolves `fname:lineno` against *any* pinned file of that basename: progs `scrub.c` (S237, 2231 lines) vs kernel `scrub.c` (S242, 3337 lines) share the map, so `scrub.c:2500` — outside the 2231-line progs file — resolves via the kernel file (F18: PASS). (b) Only the line NUMBER is checked, never content: `systemd.kill.xml:30` resolves although line 30 is blank. (c) Every pinned snapshot ends in `\n`, so `split('\n')` yields one phantom empty line: `capture.txt:10` (a 9-line file) and `btrfs-scrub@.service:11` resolve. (d) Range citations verify only the start (`dev-replace.c:1171-1199` checks 1171); `scrub.c:3222, :3336` verifies only 3222. Seat-side K22 is therefore a coarse sanity gate, not fidelity — consistent with design (the Quote legs carry the content check) but worth recording.
