          <div id="question">
          <p>I have a script that needs to create temporary files for its work, and clean up after itself. My question is about finding the right base directory for the temporary files.</p>
<p>The script needs to work on multiple platforms: Git Bash (Windows), Solaris, Linux, OSX.
On each platform, the preferred temp directory is expressed differently:</p>
<ul>
<li>Windows: <code>%TMP%</code> (and possibly <code>%TEMP%</code>)</li>
<li>OSX: <code>$TMPDIR</code></li>
<li>Linux, UNIX: supposed to be <code>$TMPDIR</code> but appears to be unset on multiple systems I tried</li>
</ul>
<p>So in my script I added this boilerplate:</p>
<pre><code>if test -d "$TMPDIR"; then
    :
elif test -d "$TMP"; then
    TMPDIR=$TMP
elif test -d /var/tmp; then
    TMPDIR=/var/tmp
else
    TMPDIR=/tmp
fi
</code></pre>
<p>This seems too tedious. Is there a better way?</p>

              <div class="answer">
                <p>A slightly more portable way to handle temporary files is to use <code>mktemp</code>. It'll create temporary files and return their paths for you. For instance:</p>
<pre><code>$ mktemp
/tmp/tmp.zVNygt4o7P
$ ls /tmp/tmp.zVNygt4o7P
/tmp/tmp.zVNygt4o7P
</code></pre>
<p>You could use it in a script quite easily:</p>
<pre><code>tmpfile=$(mktemp)
echo "Some temp. data..." &gt; $tmpfile
rm $tmpfile
</code></pre>
<p>Reading the man page, you should be able to set options according to your needs. For instance:</p>
<ul>
<li><code>-d</code> creates a directory instead of a file.</li>
<li><code>-u</code> generates a name, but does not create anything.</li>
</ul>
<p>Using <code>-u</code> you could retrieve the temporary directory quite easily with...</p>
<pre><code>$ tmpdir=$(dirname $(mktemp -u))
</code></pre>
<p><a href="http://www.mktemp.org/manual.html">
More information about
<code>
 mktemp
</code>
is available here
</a>
<sup style="font-size:9px">[1]</sup>.</p>
<p><em>Edit regarding Mac OS X:</em> I have never used a Mac OSX system, but according to a comment by Tyilo below, <a href="https://developer.apple.com/library/mac/documentation/Darwin/Reference/ManPages/man1/mktemp.1.html">
it seems like Mac OSX's
<code>
 mktemp
</code>
requires you to provide a template
</a>
<sup style="font-size:9px">[2]</sup> (which is an optional argument on Linux). Quoting:</p>
<blockquote>
<p>The template may be any file name with some number of "Xs" appended to it, for example <code>/tmp/temp.XXXX</code>.  The trailing "Xs" are replaced with the current process number and/or a unique letter combination.  The number of unique file names mktemp can return depends on the number of "Xs" provided; six "Xs" will result in mktemp selecting 1 of 56800235584 (62 ** 6) possible file names.</p>
</blockquote>
<p><em>The man page also says that this implementation is inspired by the OpenBSD man page for <code>mktemp</code>. A similar divergence might therefore be observed by OpenBSD and FreeBSD users as well (see the <strong>History</strong> section).</em></p>
<p>Now, as you probably noticed, this requires you to specify a complete file path, including the temporary directory you are looking for in your question. This little problem can be handled using the <code>-t</code> switch. While this option seems to require an argument (<code>prefix</code>), it would appear that <code>mktemp</code> relies on <code>$TMPDIR</code> when necessary.</p>
<p>All in all, you should be able to get the same result as above using...</p>
<pre><code>$ tmpdir=$(dirname $(mktemp tmp.XXXXXXXXXX -ut))
</code></pre>
<p><sub>Any feedback from Mac OS X users would be greatly appreciated, as I am unable to test this solution myself.</sub></p>

              <div class="answer">
                <p>If you're looking for the same thing in fewer lines...</p>
<pre><code>for TMPDIR in "$TMPDIR" "$TMP" /var/tmp /tmp
do
    test -d "$TMPDIR" &amp;&amp; break
done
</code></pre>
<p>You could write this in one.</p>

              <div class="answer">
                <p>You might do:</p>
<pre><code>: "${TMPDIR:=${TMP:-$(CDPATH=/var:/; cd -P tmp)}}"
cd -- "${TMPDIR:?NO TEMP DIRECTORY FOUND!}" || exit
</code></pre>
<p>The shell should either find an executable directory in one of the 4 alternatives or exit with a meaningful error. Still, POSIX defines the <code>$TMPDIR</code> variable <em>(for XCU systems)</em>:</p>
<blockquote>
<p><code>TMPDIR</code> This variable shall represent a pathname of a directory made
  available for programs that need a place to create temporary files.</p>
</blockquote>
<p>It also requires the <code>/tmp</code> path.</p>
