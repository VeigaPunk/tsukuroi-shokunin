# SrcMkinitcpioFunctions — upstream provenance of the `/new_root` symlink in mkinitcpio 42.2 `functions`

Verdict: the `new_root` symlink that the host records at `/usr/lib/initcpio/functions:1213` is upstream mkinitcpio code, byte-identical to the tagged v42.2 file, and it was added by upstream commit `00392d94` (merge request !482, milestone v42) whose stated purpose is to keep `/new_root` usable as a symlink to the new `/sysroot` root mountpoint, because that change "will affect third-party hooks that interact with /new_root" — which is exactly the class the host's `btrfs-overlayfs` and `plymouth` hooks belong to.

## Findings

1. [obs] The upstream v42.2 file contains the line in `initialize_buildroot`, immediately after the creation of the `sysroot` directory. Upstream `functions` line 1212 is `install -dm755 "$buildroot/sysroot"` and line 1213 is `ln -s "sysroot" "$buildroot/new_root"`. Evidence: https://gitlab.archlinux.org/archlinux/mkinitcpio/mkinitcpio/-/raw/v42.2/functions (opened 2026-10-22; the same two lines appear at lines 1212 and 1213 of the fetched blob).

2. [obs] The installed file on this host is byte-identical to the upstream v42.2 file, at the same line numbers. `/usr/lib/initcpio/functions:1212` is `install -dm755 "$buildroot/sysroot"` and `/usr/lib/initcpio/functions:1213` is `ln -s "sysroot" "$buildroot/new_root"`. Evidence: `cmp /usr/lib/initcpio/functions /tmp/upstream-functions-v42.2.sh` exited 0 with the message "IDENTICAL", and `sha256sum` of both files returned `8ccfad0212fe808c409d43c90dd3d2566baffee502909b0d778b41fff0fb777d`. `pacman -Qo /usr/lib/initcpio/functions` reports "is owned by mkinitcpio 42.2-1" and `pacman -Q mkinitcpio` reports `42.2-1`.

3. [obs] The line was added by upstream commit `00392d94225a11420ad41654bb1bf29854beab71`, titled "Use /sysroot as the root mountpoint", authored 2024-03-11 by nl6720 and committed 2026-08-11, merged as merge request !482 into `master` with milestone v42. Evidence: https://gitlab.archlinux.org/api/v4/projects/archlinux%2Fmkinitcpio%2Fmkinitcpio/repository/commits/00392d94225a11420ad41654bb1bf29854beab71 and https://gitlab.archlinux.org/archlinux/mkinitcpio/mkinitcpio/-/merge_requests/482 (both opened 2026-10-22). The commit diff removes `new_root` from the `install -dm755 "$root"/{...}` brace expansion and adds the two lines above; the same commit also changes `init` to mount the root at `/sysroot` and to `switch_root /sysroot`, and changes `hooks/usr` to use `/sysroot`.

4. [obs] The upstream stated purpose of keeping `/new_root` is quoted in the commit message and in the merge request description. Exact quotes: "This way both busybox and systemd based initramfs will use the same mountpoint."; "The change is mostly cosmetical, but it will affect third-party hooks that interact with /new_root."; "To avoid issues (or to at least try to avoid them), /new_root will be kept as a symlink to /sysroot." Evidence: https://gitlab.archlinux.org/archlinux/mkinitcpio/mkinitcpio/-/merge_requests/482 (opened 2026-10-22).

5. [obs] The same change was proposed earlier as merge request !331 on 2024-03-11 and was closed without merging on 2025-02-21; !482 describes itself as a continuation of !331. The root-mountpoint switch therefore first shipped in the v42 series, not in v41.x. Evidence: https://gitlab.archlinux.org/api/v4/projects/archlinux%2Fmkinitcpio%2Fmkinitcpio/merge_requests?search=sysroot&state=all (opened 2026-10-22), which reports !482 `state: merged`, `merged_at: 2026-08-11`, `milestone.title: v42`, and !331 `state: closed`, `merged_at: null`, `closed_at: 2025-02-21`.

6. [obs] The v42 release notes announce the root-mountpoint change but do not mention the `/new_root` compatibility symlink. Exact quote: "Busybox-based init now uses /sysroot as the root mountpoint just like the systemd-based one." The v42 release was published 2026-09-02 (release commit `11e3db210891b2d89a8d01ef33baa684beca1dbe`); v42.2 was published 2026-10-01 and its notes cover only the systemd hook changes. Evidence: https://gitlab.archlinux.org/api/v4/projects/archlinux%2Fmkinitcpio%2Fmkinitcpio/releases?per_page=20 (opened 2026-10-22). Consequence for the lane: the only upstream statement of the symlink's purpose is the commit and merge-request text quoted in finding 4, not the release notes.

7. [obs] The symlink is created inside the initramfs build root at image build time, not on the host root filesystem. The command writes `$buildroot/sysroot` and links `$buildroot/new_root` to it, so inside the generated initramfs `/new_root` resolves to `/sysroot`. The host's own busybox init already mounts the root there: `/usr/lib/initcpio/init:66-67` reads "# Mount root at /sysroot" and `"$mount_handler" /sysroot`. Evidence: `/usr/lib/initcpio/init` lines 60-70 and the upstream commit diff for `init` in finding 3.

8. [obs] Two hooks on this host still name `/new_root`, and both are the third-party-hook case upstream warns about. `/usr/lib/initcpio/hooks/btrfs-overlayfs:4` is `root_mnt="/new_root"` (owned by limine-mkinitcpio-hook 1.40.0-2), and `/usr/lib/initcpio/hooks/plymouth:11` is `plymouth update-root-fs --new-root-dir=/new_root` (owned by plymouth 26.134.222-3). Evidence: `grep -rn 'new_root' /usr/lib/initcpio/` (exit 0, four lines) and `pacman -Qo` on both hook files.

9. [inf] Upstream's own wording ("to at least try to avoid them") does not guarantee that a hook resolves `/new_root` the way it expects. The `btrfs-overlayfs` hook derives a mount point from the literal string `/new_root` and then queries the mount table; whether that query succeeds depends on how the path is resolved at runtime, and upstream does not claim it does. This is an inference from the upstream wording, not an observed runtime failure; no boot or image rebuild was performed under this assignment.

10. [obs] The round-24 L1 capture already contains the host-side line that premise P3 needs, so the upstream provenance can be attached to a committed capture line. `.ufo/waves/round-24/capture/l1/capture.txt:117` reads `/usr/lib/initcpio/functions:1213:    ln -s "sysroot" "$buildroot/new_root"`, lines 93 and 94 record the two `/new_root` hooks, lines 99 and 100 record the HOOKS lists, and lines 106 and 107 record the busybox init mounting at `/sysroot`. The HOOKS lists in capture lines 99 and 100 contain no `systemd` entry, so this host boots the busybox init, which is the flavor upstream changed. Evidence: `grep -n 'new_root\|sysroot\|mkinitcpio\|btrfs-overlayfs\|plymouth' .ufo/waves/round-24/capture/l1/capture.txt`.

11. [unk] The review discussion on the 2024 proposal (merge request !331) could not be read in this session: the GitLab notes endpoint for that merge request returned HTTP 401 when requested. The reviewer objections behind the 2025 closure are therefore unverified here, and no claim about them is made.
