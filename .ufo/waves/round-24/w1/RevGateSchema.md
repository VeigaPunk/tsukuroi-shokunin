## Findings

HIGH — a premise with verdict `unverified` counts toward `premises_verified`. `VERDICTS` includes `unverified` (`tools/check-pause-gate.py:34`) and verification is only `'verified': not problems` (`:142`), with no linkage between verdict and count in the `ok` condition (`:149`). Demonstrated this session by calling the module's `evaluate()` in memory with five `unverified` premises, one valid capture pointer and one 2026-10-22 source row each: exit 0, `premises_verified: 5`, `findings: []`. [obs] This is exactly the attack the round context names ("a premise counted with verdict unverified"), and the context's own rule text ("A premise counts only if its verdict is in the set", a set that includes `unverified`) licenses it, so the counting rule itself must be amended, not only the code. Required: counted verdicts are the decided set `cleared|still-holds|changed`; an `unverified` verdict must make the premise not count (or a separate `premises_unverified` field must exist and fail `ok`). Add a selftest case for it; the current 19 cases (all PASS, exit 0, run this session [obs]) have none.

2. HIGH — evidence substrings can be generic. The only quality gate is `len(needle.strip()) >= 3` (`:131`); there is no uniqueness requirement and no boilerplate rejection. Attack pointers that pass today: a `### ` section header line (for example `l1-4/capture.txt:29` with contains `### sync-db-mtime`), or `exit=0` on any of the roughly twenty exit lines in the capture (for example `l1-4/capture.txt:59`), or `-03` on any dated line. Such pointers "verify" a premise while carrying no measured value. Required: reject needles beginning `###` or beginning/equals `exit=` (the capture's boilerplate), and require the needle to occur exactly once in the pinned file. Note the intended consequence: the pending-count output line is the bare `3` (`l1-4/capture.txt:47`), so P1's count pointer must become the unique command-echo line `:46` — which is the honest intent of the rule. [obs on capture bytes; inf on the fix]

3. MEDIUM-HIGH — source status and relevance are unchecked. `source_dates()` reads only the `opened` cell (`:60-70`), and the per-premise check is only presence plus date substring (`:137-141`).
