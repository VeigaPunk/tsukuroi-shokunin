54. **Named values in a summary file are recoverable from the retained bytes they summarize (R24-SUMMARY-RECALL):** a summary or limit file may name a value — a key, count, site or version — only when the retained bytes it summarizes contain that name; otherwise the name must carry the label `author recollection, not recoverable from retained events` and must never be presented as measured. A name the retained events keep only as `__unknown_argument__` is not evidence the name never existed, and an author-written list beside the retained events is not original-trace proof; the label accompanies the summary without widening the frozen grammar, dropping the incomplete seat or rewriting the status/exit code. Falsified by: a summary naming a key that is absent from the retained event bytes, with no author-recollection label. Lesson: `corpus/lessons/round-23.md` § Mistakes R23-EDIT-AUTHORITY and § Falsifier decisions (extra field, including `replace_all`, remains could-not-evaluate); outside `corpus/lessons/round-23-verifier-spotcheck.md:52`. Failing example: `.ufo/waves/round-23/measure/post-falsify/falsify-limit.json:8-15` lists `replace_all` in `schema_original_keys` and `schema_scope`, while the retained falsify events at `.ufo/waves/round-23/falsify/events.json:14064` carry the unknown key only as `__unknown_argument__` and `grep -c 'replace_all' events.json` returns 0.

55. **A host-state premise used by a gate or prompt carries its capture time and recheck command, and goes stale after a package transaction (R24-PREMISE-STALE):** every premise about live host state — a pending-upgrade count, an installed version, a hook-path fact — that a gate, checklist or prompt consumes must state when it was captured and the exact command that re-measures it, and it goes stale immediately after a package transaction or sync-metadata change; a stale premise must be re-measured or explicitly marked historical, never reused as a current reading. A probe returning zero rows is not a full-upgrade proof, and a dated snapshot is not current state for a later timestamp. Falsified by: a premise with no capture time and no recheck command, or a number still quoted as current after a package transaction that the same repo's capture contradicts. Lesson: `corpus/lessons/round-23.md` § Mistakes R23-QUALITY-TREND (stale-premise/calibration); `corpus/lessons/round-17.md` § Mistakes R17-TYPE-BLIND; the invalidation rule already at `corpus/knowledge/partial-upgrade-recheck-r15.md:3`. Failing example: the `413` pending-upgrade numeral (`corpus/knowledge/partial-upgrade-recheck-r15.md:14`, restated at `corpus/knowledge/host-health-report-r3.md:591` and `print-safety-note.md:510`) stayed current-reading for two days after the 2026-10-20 09:15 sync/upgrade (`.ufo/waves/round-24/capture/l1/capture.txt:132`), while the round-24 capture measures three pending rows (`capture.txt:39-48`); `SKILL.md:99` asserts "`pacman -Qu` → empty here, rc=1" with no capture time on the value, and `corpus/README.md:38` still calls a mkinitcpio 42 upgrade "Pending" though `mkinitcpio 42.2-1` is installed (`capture.txt:63`).
