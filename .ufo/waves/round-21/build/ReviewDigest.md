# ReviewDigest — challenge to the round-21 review binding schema

Axes named: calibration (evidence pinning), operability (gate discriminating power), depth (what the predicate actually binds). Scope: review of pinned snapshot `corpus/QUALITY.md` (sha256 aabd157d…) against the `tsukuroi-review-snapshots-v1` manifest and the dispatched `check-review-snapshots.py` gate contract; no execution.

## Observations (source-anchored)

1. The C3 contract binds `(manifest sha256, report Reviewed-SHA256 line, report Predicate line, report Scope line)` and nothing else. ExecReview dispatch (`build/dispatch.json` ExecReview item) requires the gate to "compare SHA256(actual committed source bytes) to expected; require exact standalone report lines". No report field pins report content.
2. The expected digest is disclosed verbatim in every seat's dispatch item ("SHA256 aabd157d…" in my own item; identical pattern for all peers, `build/spec.json` items). A seat that never opens the file can emit a conforming receipt by echoing the prompt. The check therefore separates *declaration conformance* from *reading* — and cannot tell them apart. This is structurally the R20-C2-REFUSAL-ECHO failure (QUALITY39): an echo of a supplied value graded as evidence.
3. Same for `Predicate:`: the literal predicate string is given to the seat (`candidate-review-digest-predicate` in mine) and compared as an exact string. Echoing satisfies it; a wrong-but-plausible predicate is caught, a copied one is not. Predicate exactness is currently enforced as *string equality against the disclosed answer*, not as *independent restatement*.
4. The preregister already concedes the limit: `preregister.json:42` — "Declared digest binding, not proof of actual reading or actual command nonexecution." QUALITY38 (`snapshot/corpus/QUALITY.md:82`) requires the record, not the reading. The schema is honest about its weakness but the wave metric `pinned_reviews` will still count echo-only receipts as pinned, inflating `after` ("every delivered build/falsify review") without any reading having occurred.
5. The manifest pins `source` sha256 but not `report` sha256. The gate checks that a report *path* contains the required lines at check time; the body, verdict, and findings are unbound. Two reports at the same path across revisions, or a report whose findings describe different bytes than the pinned source, both satisfy the schema. R20-CANDIDATE-SNAPSHOT's coexistence rule (QUALITY38: "reports about different snapshots or predicates … cannot clear each other's findings") is only half mechanized: digest equality is checked, but nothing links the report's *claims* to the digest-identified bytes.
6. Manifest-before-output boundary is asserted, not enforced. The dispatch text says "Manifest persisted before reviews; chronology is demonstrated by committed preregistration/spec, not verified from arbitrary mutable timestamps." At gate time the gate can verify the manifest exists at `--revision`; it cannot verify the manifest predates the reports, because both live in the same commit. A manifest row added or edited after reading a report is indistinguishable from a preregistered one within a single commit. The boundary holds only if the manifest is committed in an ancestor commit of the reports — an ancestry check the drafted contract does not specify.
7. `sha256` in the manifest pins one blob. The review target is described by path (`source:`), but the snapshot tree itself is a mutable-worktree artifact: the gate compares manifest sha to "actual committed source bytes" at `--revision`, which is the right immutable-object discipline (matches QUALITY36/38), yet nothing binds which *snapshot file* the seat read — the seat could have read `corpus/QUALITY.md` at HEAD, at baseline, or the snapshot copy; all may differ, and the receipt is identical.

## Inferences (labeled)

- [inference] Minimum strengthening consistent with the existing contract: require each report to carry a content-derived locator from the pinned bytes — a ≤25-word verbatim quote plus stable heading (QUALITY21/32 already define this form for sibling anchors) — and have the gate re-extract it from the digest-identified blob. This turns the receipt from "digest declared" into "digest plus a fact only a reader of those bytes could supply cheaply." It is a proxy for attention, not proof of comprehension; a seat could still quote without understanding. That residual is honest.
- [inference] Predicate exactness should mean: the predicate token is drawn from the manifest row (registry-closed set, no free text) AND the report applies it to the digest-identified source (predicate string adjacent to the Reviewed-SHA256 line for that source — already satisfied by line format — but the gate should reject a predicate echoed without the source's name/path appearing in the report body). The current contract catches wrong predicates, not vacuous ones.
- [inference] Manifest-before-output becomes checkable if the gate requires the manifest blob at the merge-base / first commit introducing it to equal the manifest at `--revision` (immutable bytes, ancestry-bound), rather than trusting "committed preregistration" narrative. Failing that, the limits line must keep its current wording; upgrading it to "reviews bound" would be an overclaim.
- [inference] `pinned_reviews` should be renamed or footnoted in output as `declared_reviews`; the current name already implies more than the gate measures.

## Residual risk / verification gaps

- Even with quote-locators, nothing proves the seat read beyond the quoted span; the proxy measures minimum contact, not coverage.
- The gate's "actual committed source bytes" comparison depends on the manifest `source` path mapping to a git blob at `--revision`; snapshot-copy drift between dispatch and commit is out of the draft's stated scope and remains a gap (whoever committed the snapshot is trusted).
- `Scope: executed=none` remains a declaration; per preregister limits, nonexecution is not verified. Parallel red from round-19/20 (`period-appended trailer` class, QUALITY31) is handled by REVIEW-SCOPE-MISMATCH only if the matcher is exact-literal — confirm in selftest that `Scope: executed=none.` (trailing period) fails, since the historical class was precisely that.
- Dead-seat handling: REVIEW-REPORT-MISSING correctly refuses silent omission, but `pinned_reviews` vs `total_reviews` must keep missing reports in the denominator's accounting, not just as findings, or the metric reads as cleaner than reality.

## Verdict on the challenge

The challenge stands: snapshot sha + report sha is a *binding of declared identity*, not evidence of reading — and in this dispatch the digest and predicate are pre-supplied, so the strongest honest claim is "the seat reproduced the issued receipt." Predicate exactness and immutable-byte binding are already partially designed (exact-line match, committed-blob comparison); the manifest-before-output boundary is the weakest leg and needs an ancestry/immutability check or an explicit retained limitation. This review recommends, does not admit (QUALITY: non-author).
