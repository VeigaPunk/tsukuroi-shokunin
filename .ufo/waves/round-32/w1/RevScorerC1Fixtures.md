## Findings

1. **[obs, medium — coverage gap] Coredump boot attribution is never negatively exercised.** All m planted entries carry boot 0's `_BOOT_ID` (scorer:372-386), and the census counts coredumps by `SYSLOG_IDENTIFIER` over a `-b -p err` stream (census:1342, 1359-1363) with no `_BOOT_ID` check — it trusts `journalctl -b`, and the stub ignores `-b`. The fixture never plants a coredump in boot -1 that a boot-0-only census must exclude, so the counter cannot distinguish a census that counts coredumps across all boots. The claim wording "m systemd-coredump entries in boot 0" is planted truthfully (all m are in boot 0), and this is not a shortcut keyed on fixture ids or labels, but on the live host the two implementations diverge and the fixture cannot see it. Identifier discrimination IS exercised: the `tsukuroi-only` / `journal-other-error` arm plants a boot-0 PRIORITY=3 non-coredump entry (scorer:408-421) whose base plane shows `coredump=0 other=1` (observed in both runs), so "any err entry" censuses fail.

2. **[obs, low] WINDOW_DAYS is day-coarse over mid-day boot bounds; fail-closed if it ever mattered.** Events are drawn from whole days 2026-10-11..14 (scorer:93, 202-208) while the fixture's boot bounds start mid-day (boot -1 first entry 2026-10-11 19:02:51), so a planted minute can predate the first journal entry (seed a1b2c3d4 s20 planted 2026-10-11 00:33 and the base census clustered it, `clusters=8[2026-10-11 00:33,...]`). This is harmless: the census's own window representation is date-granular (`window=boots=2 2026-10-11..2026-10-14`, census:1281-1283) and observed clusters are never window-filtered, so "n dated kill events in the retained window" holds at exactly the granularity the census itself uses. If a future census re-filtered by intra-day bounds, `verify_planted` (scorer:576-614, gated at 849-851) would raise a harness error (exit 2), never a wrong score.

3. **[obs, low — documented interpretation] The comparison set is only ADJ-04-mori HANDOFF lines; other stdout is free.** A HANDOFF line for another row or recipient is recorded (`other_handoff`) but never decides the verdict (scorer:68-70, 509-542), trailing `key=value` fields after `state=prepared` are accepted and never compared (scorer:98, 520, 526), and any stdout that is not a `PLANE ` line, the `TSUKUROI_CENSUS:` line or a `HANDOFF ` line is unconstrained (scorer:497-506). The docstring declares this reading rule explicitly. Consequence: a census that prints the required lines plus decoy HANDOFF lines for other rows, or arbitrary plain chatter, still routes. Conversely a decoy ADJ-04-mori line (any class/value/kind/state quadruple, wrong field order, or non-numeric value) breaks the exact set match (scorer:544-553, list comparison so duplicates also fail) and PLANE/rollup/rc changes break parity (scorer:855-858). The wave-1 "junk lines" control will land exactly on this boundary: junk in another row's HANDOFF shape or plain lines routes under this counter; junk in ADJ-04-mori shape does not.

4. **[obs, low] The hermeticity gate is token-based, and closes only with the static audit.** Per run the scorer requires all 8 probes to have hit the stub dispatcher (scorer:181-182, 617-641, gated per run at 824-832) plus three live-read tokens (fixture hostname, `root_dir=<fx>/root`, package sample `alpha,beta,gamma,delta`). That proves the main overrides were honored, not every read. The static audit closes it: every host path in the census sits behind a `TSUKUROI_*` override that `census_env` sets (scorer:447-478; census probe surface census:350-386 — /etc/pacman.conf:353, /var/lib/pacman:354, /sys/bus/pci/devices:367, /dev:368, /proc/sys/kernel/hostname:369, /proc/sys/kernel/dmesg_restrict:370, /sys/fs/cgroup:374, /proc/pressure/memory:376, /proc/meminfo:377, /proc/vmstat:378, /var/log/pacman.log:381, OFFLINE_DB derived from PACMAN_DB:382; grep of the blob found no literal host-path read in code outside these default assignments and comments). `TSUKUROI_MEM_SLICE` is unset by the scorer and defaults to `user.slice/user-1000.slice` (census:375), which is exactly the cgroup subtree the fixture builds (scorer:314-328). PATH is `stubdir:/usr/bin:/bin` with stubdir first (scorer:450), shadowing all 9 probe commands on this host; the remaining PATH commands (awk, sed, grep, stat, find, head, tail, tr, cut, sort, paste, sha256sum, cat) are stateless text tools over fixture paths. The only live-clock reads are `now=$(date +%s)` (census:1465, age arithmetic against fixture db mtimes set to now−1h, so 0d regardless of run date — scorer:285-292) and the `date -u` banner (census:2641), which `parse_output` never compares.

5. **[obs, info — positive] Fixture honesty per type checks out in detail.** (a) kill-events: distinct minute keys are guaranteed by the `used` set with the two declared baseline minutes excluded (scorer:93-94, 198-215); each event is planted in the census's declared three-line shape — kernel `Out of memory: Killed process`, attribution `The kernel OOM killer killed some processes in this unit.`, and `status=9/KILL` (scorer:356-370) — matching the census's grep keys (oom_reaper / OOM killer / status=9, census:1191, 1203, 1208 and stub census:1770-1777) and its own wave shape (census:2398-2414), so all five gated fields `clusters, C1_kernel, killed_process, C2_events, C3_events` equal n (scorer:579-589); clustering is on raw `YYYY-MM-DD HH:MM` string prefixes (census:557-560) with `-- Boot` separators counted out, so the mixed tz offsets (−03:00/+00:00/+02:00, scorer:212) can never collide and no timezone normalization exists in the oom arm. (b) coredumps: m JSON entries with the exact `"SYSLOG_IDENTIFIER":"systemd-coredump"` literal the census's awk counts (scorer:377-386; census:1359-1363). (c) cumulative-only: plants only `vmstat oom_kill` and/or cgroup `memory.events oom_kill` (scorer:391-402), leaving the window scans empty with rc=1 (scorer:342-347; census treats rc 1 as "0 entries", census:1192-1194) — no dated fact exists; expected set is empty. (d) the gate enforces the full planted shape, not just the cluster count: an under-planted fixture (e.g. attribution-only) would fail `C1_kernel != n` as a harness error.

6. **[obs, info — positive] Expected sets are hidden from the census.** `expected_set` exists only in scorer memory (scorer:555-561); the fixture tree, the environment and the stub dispatcher carry no expected values, type names or counts; scenario dirnames and host tokens are random (scorer:686-706); the calls log and dispatcher live outside the fixture directory (scorer:789-803). Empirically the base census printed zero HANDOFF lines in all 48 census runs. A rev census could read fixture files directly through the TSUKUROI_* paths instead of via probes and still pass hermeticity — indistinguishable from legitimate reading, and it would still have to count correctly to route, so it cannot produce a false routed.

7. **[obs, info — positive] The harness-error gate is correct and fails closed.** Per scenario: both base and rev runs must be hermetic (scorer:824-832), rev rc must be a census verdict code {0,1,2} (833-835) and a `TSUKUROI_CENSUS` line must exist (836-838); the base run must print exactly 6 PLANE lines (846-847) and `verify_planted` must find every planted fact on the base planes — all five oom fields == n, journal `coredump=` == m, and for planted cumulative counters `ledger=vmstat.oom_kill=<value>` (scorer:596-607) and drivers `C4_present >= 1` (608-613) — otherwise the row is a harness error and the run exits 2 (911-912). Export failure yields a summary with `harness_errors: 1`, exit 2 (765-774); budget exhaustion marks the row a harness error (779-787). A rev census that skips probes to hardcode output fails the hermetic gate (harness error), not a silent unrouted.

## Residual risk

- Finding 1 (coredump boot attribution) and finding 3 (non-ADJ-04-mori HANDOFF lines and non-contract stdout are free) bound what this counter can prove about a submitted census; both are inherent to the frozen predicate's wording as implemented and documented, not bugs in it.
- The scorer's dispatcher is its own copy of the census's fixture dispatcher, adapted to the measured host (dmesg restricted → `journalctl -k` ring fallback answered from `ring-err.json` / `journal-all.json`); behavior was confirmed deterministic across 48 runs, but the two dispatchers were not diffed line by line.
- `BASELINE_MINUTES` exclusion (scorer:93-94, 206) is belt-and-braces only: scored runs always point `TSUKUROI_OOM_BASELINE` at the fixture `obase` (single 2026-09-30 row), so the census's embedded r8 waves are never active during scoring. [inf]
