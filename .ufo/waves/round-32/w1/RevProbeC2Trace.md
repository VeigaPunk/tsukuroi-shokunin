## Findings

**M1 (medium) — `--only` that matches nothing reports success (exit 0, `leaking` 0).**
`probe-frozen-r32.py:360-361` skips every target not named by `--only`; nothing checks `ntargets` afterwards. A mistyped `--only` (e.g. `check-kernel-tain.py`) selects zero targets, the summary at `:411-414` prints `targets 0, pairs 0, leaking 0, harness_errors []`, and `:417` (`return 2 if errors else (1 if leaking else 0)`) exits 0 — the exact claimed end-state shape, with `targets: 0` in the receipt the only tell. The frozen claim command (SCORECARD row C2: `--revision <REV>` alone, no `--only`) is unaffected; the hazard is seat/spot-check usage. [obs from code; not executed]

**M2 (medium) — an envp parse failure silently becomes "no names present", which is the false-pass direction.**
`parse_trace` catches `(AssertionError, IndexError)` at `:163-167` and sets `argv, envp = [], []`, while the success test at `:169-172` still records the exec (so `git_execs` at `:224` counts it and parity holds). Any strace output-shape deviation on the argument lists therefore yields a successful exec record with an empty environment: `carriers` (`:303-318`) sees no names, parity holds, and the probe reports `leaking 0` — a clean pass for a leaking target. The `-v` flag at `:207` is load-bearing here: without it strace prints envp in the abbreviated `/* N vars */` form, which `parse_strings` (`:124-148`, requires the leading `[`) cannot read, and the failure would be exactly this silent shape. Nothing asserts that a successful exec record carried a decoded envp. Direction of error is safe for control runs (a broken trace gives `git_execs 0` → harness error at `:371-372`), but unsafe for the channel run of a leaking target. [obs; hardening suggestion recorded only — counter bytes are frozen]

**L1 (low) — a channel-run timeout is scored as a leak, and the timeout budget can overrun the receipt wrapper.**
`one_run` maps `TimeoutExpired` to `rc='timeout'` (`:217-219`); for the channel run, `parity(ca, r)` (`:388`, `:227-231`) then differs on `rc`, producing evidence and `leak=true` (`:402-407`). This is faithful to the frozen predicate's letter ("or the run breaks parity with control run A (exit code, …)"), so it errs toward blocking a claim, but a flaky load-induced timeout would implicate the target. Budget: worst case 3 runs × `TIMEOUT = 1200` (`:79`) = 3600 s > the receipt wrapper's `--timeout 2900`, so a hung run burns the wrapper; the receipt then records `timed_out` honestly. [obs]

**L2 (low) — `export_tree` never checks the `git archive` exit code (`:187-191`).**
A failed archive surfaces as a raw `tarfile.ReadError` traceback (loud, non-silent, and recorded by run-receipt as a counter crash), not the probe's own JSON `harness_error` + exit-2 contract (`:335-346`). Inconsistent, but not a swallow. [obs]

**Q1 — strace parsing of tricky names/values: sound. [obs]**
`parse_strings` (`:124-148`) scans char-by-char and keeps `\x` escape pairs intact (`:136-138`), so a value containing quotes (`\"`), backslashes (`\\`) or newlines (`\n` — strace always escapes control bytes, so trace lines stay single-line) cannot forge a string boundary; a value containing the text `", "` stays inside one string. Truncation of an over-long string by `-s 65536` (`:207`) only cuts content and is consumed via the `...` marker (`:143-145`); the leading `NAME=` is never cut for the injected names (≤ 20 chars + short values). Presence is `item.startswith(name + '=')` on the raw decoded-prefix text (`:312-314`): names are pure `[A-Za-z0-9_]` with a letter/`_` first byte (`:94-97`), contain no escapable bytes, and case is preserved verbatim, so lowercase/digit/underscore names match exactly. Empirical: both base runs decoded all 12 injected names out of 933 execs (receipts, `reached`). [obs]

**Q2 — random-name collision with a name the control or a tool needs: excluded by construction. [obs+inf]**
Controls run with no injected env at all (`:363-364`, no `extra_env`), so only the channel run carries names. The generator (`:241-261`) refuses `LC_`/`GIT_`/`XDG_`/`LD_`/`PYTHON` prefixes (`:98`), the exact names `PATH` `HOME` `LANG` `TZ` `TMPDIR` `USER` `LOGNAME` `TERM` `SHELL` `PWD` `IFS` (`:99-100`), the four fixed names, and — decisively — any name in `taken = set(os.environ) | set(hermetic_env('/h','/t')) | set(NAMED_INJECTED)` (`:382`), i.e. every name present in the channel run's own base environment, so an injected name can never overwrite or shadow a name the tool needs from the environment. Residual [inf]: a random draw could equal a convention name the target derives internally but that is absent from ambient (e.g. `SOURCE_DATE_EPOCH`), flipping tool output into a parity break; probability per run is ~8 names over a 2–20-char mixed-case alphabet — negligible. Values are random lowercase words (no `/`, `:235-238`) or inject-dir paths, so a value-keyed rule has nothing stable to key on (per the frozen predicate, presence is by NAME only). [obs]

**Q3 — "after the target's own first exec" is implemented correctly, including for re-exec. [obs]**
The probe launches the target as `[sys.executable, <tree>/tool, …]` under strace (`:207-208`), so the first execve in the trace is the target's own interpreter exec (the target file's `#!/usr/bin/env python3` shebang, `check-kernel-taint-base.py:1`, is irrelevant — python runs the file directly; there is no `/usr/bin/env` hop that would have made `execs[1]` a carrier of the injected ambient env). `carriers` examines `execs[1:]` (`:310`). Any later exec is a child exec and is examined: git children, git's own re-exec into `/usr/lib/git-core/git` (observed in both receipts), and a tool's own python re-exec — which, if it carried the injected names, is a genuine leak (the tool passed ambient env through), exactly what C2 forbids. Caveats [inf]: only *successful* execves are recorded (`:169-175`), and the anchor is the first successful execve — sound here because the probe execs an absolute interpreter path that cannot fail; fork-only children (no execve) and `execveat`-based spawns are outside the frozen channel (`trace=execve`, `:207`) by design, and the frozen predicate says "traced execve", so this is a scope property, not a defect.

**Q4 — bashenv/env marker detection: sound, and correctly non-decisive. [obs]**
`make_inject_dir` (`:264-282`) writes executable `#!/bin/sh` scripts printing `TSUKUROI_R32_BASHENV_RAN` / `TSUKUROI_R32_ENV_RAN` (`:101-102`) to stderr and appending to `bashenv.log`; the result record carries `bashenv_log_exists` / `bashenv_log_lines` (`:392-395`). The frozen verdict uses only `reached` and parity (`:404-407`), so a marker can neither create nor clear a leak: it is corroboration. Both base runs show `bashenv_log_exists: false`, `bashenv_log_lines: 0` — correct, because `check-kernel-taint.py` spawns only git children and git never invokes bash: `BASH_ENV` was carried (name-presence caught it) but never executed. Had any child run `sh`, the script would have executed and that same exec's envp would independently carry `BASH_ENV=` — no path where the marker fires without the name also being present. [obs]

**Q5 — harness error handling: no swallow on the frozen path; the two exceptions are M1 and M2. [obs]**
Checked and reported with exit 2: missing strace (`:344-346`), scratch inside the lane or inside a git repo (`:335-343`), unreadable revision (`:347-350`), clone failure (`.check_returncode()`, `:355`), control `rc != 0` (`:367-368`), control disagreement (`:369-370`), control started no git child (`:371-372`) — each short-circuits to `harness_error` + exit 2 (`:373-378`, `:417`). A missing or empty trace file gives `execs = []` (`:220`) → the control fails the git-child gate, so a broken strace cannot fake a pass. `stderr_tail` is retained (`:216`) for diagnosis. The unguarded spots are M1 (empty selection) and M2 (silent empty envp); `export_tree` (L2) fails loudly but out-of-contract.
