# ExecCounterC1Handoff — round-32 counter for the ADJ-04 mori handoff

New file `tools/score-census-handoff-r32.py` only; no existing lane file edited. Base `58cc2e0bfaa4580d47f6817537c8d5c82dbe9c92`, scored revision `--revision <REV>` (default repo HEAD), with `--lane` (default the lane) and `--scratch` selectable. Rows read: `PROVINCE.md` ADJ-04 and the round-19 OUT-005 anchor.

**Fixture mechanism.** The census reads every host surface through a `TSUKUROI_*` override; the scorer reproduces that mechanism itself rather than the census' own `--selftest`: per scenario it writes a fixture tree and a stub dispatcher, exports the census at REV *and* at the frozen base with read-only `git archive`, and runs both against the same fixture. The dispatcher is one `.dispatch` script plus a symlink per probe (`pacman`, `pacman-conf`, `systemctl`, `dmesg`, `journalctl`, `nvidia-smi`, `lsmod`, `expac`, `vercmp`), answering only from the fixture and logging every call. Each run gets a fresh minimal env: `PATH` = stub dir + `/usr/bin:/bin`, `LC_ALL=C`, private `HOME`/`TMPDIR`, only the `TSUKUROI_*` overrides the fixture needs. Hermeticity gate: the stub log must show every probe answered by the stub, and the output must carry the fixture hostname, root path and package sample — a live command or a live path fails all three. The live host is never written to or read by a probe; no `git`/`jj` write command ran in the lane or the fleet repo. No path, env var or stub name carries the scenario type, the expected HANDOFF set or n/m: the scenario directory is a random 16-hex name, and those values live only in scorer memory and on stdout.

**Scenarios.** 24 per run from a seed (fresh `os.urandom`, printed in the summary; `--seed` replays). Seven types — none, kill-events, coredumps, both, cumulative-only, cumulative+coredumps, tsukuroi-only — each at least twice, the remaining slots drawn at random; n/m in 1..9 with randomised timestamps, pids and process names. Planted facts: one dated kill event per distinct minute (kernel OOM + systemd attribution + SIGKILL lines, the census' own wave-A shape) so `clusters`/`C1_kernel`/`killed_process`/`C2_events`/`C3_events` all equal n; m distinct `systemd-coredump` JSON entries in boot 0 so the journal plane reads `coredump=m`; cumulative `vmstat.oom_kill>0` and/or a cgroup `memory.events` flag, visible as `ledger=vmstat.oom_kill=N` and/or `C4_present>=1`; tsukuroi-only keeps a failed user unit, package drift or a non-coredump boot error, with no kill event and no coredump.

**How the planted facts are verified.** Before any routing verdict the *base* census' PLANE lines are checked against what the scenario planted: the five oom-plane counters must equal n, journal `coredump` must equal m, and a planted cumulative counter must appear in `ledger=vmstat.oom_kill=` / `C4_present=`. A mismatch is a HARNESS ERROR (exit 2), never a silent pass — it proves the fixture does not plant what it claims. The base run is also checked for six PLANE lines, a `TSUKUROI_CENSUS` line, a 0/1/2 exit code and full hermeticity.

**Predicate** (verbatim in the tool docstring; `predicate_label=routed`): the census at REV prints exactly the required ADJ-04/mori HANDOFF set (class, value, kind, state compared exactly; trailing `key=value` fields after `state=prepared` accepted and never compared; a line with the fields out of the frozen order is malformed and never matches) and its PLANE lines, `TSUKUROI_CENSUS` line and exit code equal the base census on the same fixture. Exit 0 when routed == scenarios and no harness error, 1 otherwise, 2 on harness error.

**Evidence.** Acceptance at base (24 scenarios, seed `0bd01985828e1848`): `routed=13/24`, `harness_errors=0`, runtime 6.8 s, exit 1; routed types exactly none / cumulative-only / tsukuroi-only and zero HANDOFF lines printed anywhere; output in `ExecCounterC1Handoff/dev-run-base.jsonl`. Sandbox discrimination in my own dir under `/fast/scratch/hyaku/tsukuroi-r32/`, never the lane repo: a correct HANDOFF census variant routes 24/24 (exit 0); a variant double-counting the same event (C2+C3) routes 16/24; a variant emitting kill-events from the cumulative ledger routes 9/24 and also fails the cumulative-only scenarios. A revision predating the fixture surface fails the hermeticity gate → exit 2, not a false pass.

**Limits.** Scores the printed HANDOFF lines, not the evidence behind them, and does not implement the change being scored. Only ADJ-04/mori lines decide the verdict (any other HANDOFF line is recorded in `other_handoff`). The fixture is the census' own shape, not the live host: a surface the fixture does not model reads BLOCKED/unknown and is reported as a harness error rather than hidden. The retained-window bounds and the two baseline minutes are fixed fixture values; the channel db stamp is set one hour in the past so plane lines do not depend on the run date. 24 × 2 census runs ≈ 7 s (per-run timeout 120 s, whole-run budget 840 s, inside the 15-minute limit).

**Environment.** Host pacman transactions were paused, so nothing was installed: no package, `uv tool`, binary or npm install ran for this work.
