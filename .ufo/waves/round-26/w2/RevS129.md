2. SH4's S129 citation does not carry the claim. [defect] The SH4 citation (corpus/knowledge/storage-health-r26.md:65; corpus/knowledge/storage-health-r26.json:211-213; corpus/lessons/round-26.md:32) quotes line 133, "Show status of a running scrub for the filesystem identified by *path*". That sentence is about a running scrub. The SH4 claim is that no scrub record exists because /var/lib/btrfs is absent. The S129 sentence that carries that claim is at lines 136-138: "If no scrub is running, show statistics of the last finished or cancelled scrub" and "The status is read from the file located in /var/lib/btrfs." Neither is quoted in the lesson or the entry. Quote lines 136-138 for SH4. [obs]

3. Teaches cell says "only" without S129 support. [overreach] corpus/SOURCES.md:135 says "Scrub repairs damaged copies by default only for block group profiles with redundancy." S129 lines 78-80 say: "automatic repairs of damaged copies are performed by default for block group profiles with redundancy." No S129 sentence says repairs are limited to those profiles. A search of the S129 bytes for "only" finds only scheduler and read-only remarks (lines 85-124). The converse, that a single-copy profile cannot repair, belongs to S130. The same "only" also appears without a source number in SKILL.md line 2365: "Scrub repairs only by copying a verified good replica." Drop "only" from the teaches cell, or cite S130 for the converse. [obs]

4. Teaches cell says "at all" without S129 support. [overreach] corpus/SOURCES.md:135 says "scrub status is read from the file in /var/lib/btrfs, so a filesystem with no /var/lib/btrfs has no scrub statistics at all." S129 lines 136-138 limit the file to the statistics of the last finished or cancelled scrub when no scrub is running. S129 lines 144-146 say raw statistics are printed "as returned by the status ioctl". S129 says nothing about a filesystem with no /var/lib/btrfs. [inf] btrfs-progs v7.1 cmds/scrub.c, fetched from https://raw.githubusercontent.com/kdave/btrfs-progs/v7.1/cmds/scrub.c (sha256 48df2e2f468f7db79a3611ae2f3b1b794d330e8d02cc91f9ce386de8ed8f0801; not a registry row and not cited by the lane), defines the status file and progress socket under /var/lib/btrfs (lines 67-68), prints "no stats available" when there is no stats record (line 321), and uses BTRFS_IOC_SCRUB_PROGRESS only to test whether a scrub is running (lines 1190-1206 and 1946). So the claim may hold at runtime, but S129 does not establish it, and I did not run btrfs on the host to test it. Narrow the teaches cell to what S129 says, for example "statistics of the last finished or cancelled scrub are read from a file in /var/lib/btrfs when no scrub is running", and drop "at all". [inf]

The anchor's line list (76-80, 133-138, 165-201) does not reach line 12. Either cite S139 for that clause or remove "reads and verifies" from S129's scope. [obs]
