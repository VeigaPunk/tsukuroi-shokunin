## Findings

1. The C1 row rule is one paragraph at `SCORECARD.md:897` (read as raw bytes: `/fast/scratch/hyaku/tsuku26/ExecStorageChecker/repo/SCORECARD.md:895-897`). It names eight clauses: the id set (exactly SH1 to SH6, each once, a duplicate being an error and never a second count); the required fields (non-empty statement, a verdict from HEALTHY, DEGRADED, BLOCKED or UNVERIFIED, a non-empty action); the source rules (a registry row, status `mined`, opened `2026-10-22`, `used-by` naming `corpus/knowledge/storage-health-r26.md`, at least one tier A); the quote rules (at most 25 words, a whitespace-normalised substring of the committed snapshot whose sha256 is in that source's anchor cell, the same text in the lesson `## Gate` table, a quote mismatch blocking the row rather than being only a finding); the capture-pointer rules (a line number and a token of at least 3 characters, the line unique in the capture, not a `### ` header, not a `$ ` command echo, not an `[exit ` line, containing the token); the SKILL rule (a table line whose first cell is exactly the row id inside `## Storage integrity — round 26`); and the exit rule (a missing capture, a capture with a different digest or a missing entry exits 2, never a pass).

2. The tool's exit code is derived from `verified_rows` alone, so exit 0 and `verified_rows == 6` always agree. Exit 2 is reserved for the could-not-evaluate class: `SH-CAPTURE-MISSING`, `SH-CAPTURE-DIGEST-MISMATCH`, `SH-ENTRY-MISSING`, `SH-ENTRY-MALFORMED`, `SH-ENTRY-SCHEMA`, `SH-ENTRY-MD-MISSING`, `SH-SOURCES-MISSING`, `SH-LESSON-MISSING`, plus the `_revision` binding refusals (`E-REVISION-INVALID`, `E-REVISION-NOT-LANDED`, `E-REVISION-NOT-PUSHED`, `E-BRANCH-INVALID`, `E-BRANCH-MISSING`, `E-GIT-FAILED`) which the shared module raises. The capture digest is verified before anything else is read, so a tampered capture cannot be counted.

3. The lesson `## Gate` table is parsed by header names, not by position: the column whose name contains `located quote` and the column named `source` are located in the header row and used to index the body. The located quote is read from the raw line, not from a pipe-split cell, so a quote that itself contains a pipe is read whole. Multiple located quotes in one cell (`"a"; "b"`) are all read. A line that names no source id, or a row whose quote cell cannot be read, becomes a finding (`SH-GATE-LINE-MALFORMED`) and never an exception; a lesson whose Gate table has no `Located quote` column at all becomes `SH-GATE-HEADER-MISSING`, which blocks. This is the round-25 routed defect 4 repair: the tool does not crash on a lesson prose line. I fuzzed the parser with 21 prose shapes (empty string, bare pipes, an unclosed quote, a quote containing a pipe, backticks, escaped quotes, a NUL byte, a row naming no id, a row with a two-digit id, a row with an empty quote cell) and every shape returned a result rather than raising.

4. The snapshot rule is implemented literally. For each quote's source S###, the snapshot is found by `git ls-tree` under `.ufo/waves/round-26/sources/` and must be exactly one file named `S###` with an optional extension directly in that directory; zero or more than one is `SH-SNAPSHOT-MISSING` or `SH-SNAPSHOT-AMBIGUOUS`. The file's sha256 must appear in that source's anchor cell in `corpus/SOURCES.md` (`SH-SNAPSHOT-DIGEST-NOT-IN-ANCHOR`), and the whitespace-normalised quote must be a substring of the whitespace-normalised snapshot text (`SH-QUOTE-NOT-IN-SNAPSHOT`). The quote word count is the whitespace-split count, capped at 25 (`SH-QUOTE-TOO-LONG`).

5. The SKILL rule is scoped to the section. The section runs from the `## ` heading whose title matches `Storage integrity … round 26` to the next `## ` heading; a `### ` sub-heading stays inside it. Inside that section, a row counts only when the first cell of the table line is exactly the row id. A row placed after the section heading ended is `SH-SKILL-ROW-MISSING`, and a SKILL.md with no such section is `SH-SKILL-SECTION-MISSING`.

6. A duplicate row id is treated as an error, never a second count, and it blocks the whole entry: the id is withdrawn from the countable set and `SH-ROW-ID-DUPLICATE` is a global finding, so `verified_rows` is 0 rather than 5 or 6. I chose the global block after reading the wave-1 mutation plan (`/home/vgpnk/Projects/shokunin/tsukuroi-shokunin/.ufo/waves/round-26/w1/MutStoragePlan.md`), which states that a row-id defect is a global block under the round-25 convention and predicts `verified_rows` 0.

7. The quote and pointer key names are read on their merits, in both namings: a quote is `text` first and `quote` second, its source is `source`, `source_id` then `id`; a pointer token is `token`, `contains` then `text`. The assignment names `quotes[].text`, and the round-25 entry in `corpus/knowledge/memory-pressure-r25.json` uses `quote`, so the checker accepts either. The same applies to the capture pin (`capture.path`, `capture.sha256`): a pin that names a different path or a different digest is `SH-CAPTURE-PIN-PATH` or `SH-CAPTURE-PIN-DIGEST` and blocks.

8. The selftest is hermetic and builds its fixtures with `git init --initial-branch=master` in a temporary directory with no remote. It runs 41 cases and prints one JSON object: 1 passing fixture (`clean-pass`, exit 0, `verified_rows` 6, no findings) and 40 failing fixtures, each asserting an exit code, the `verified_rows` value and the exact set of blocking finding ids. The failing fixtures cover every clause the assignment names — duplicate id (`SH-ROW-ID-DUPLICATE`, two shapes), missing verdict (`SH-VERDICT-MISSING`), a bad verdict word (`SH-VERDICT-INVALID`), source not mined (`SH-SOURCE-STATUS-NOT-MINED`), a wrong opened date (`SH-SOURCE-OPENED-WRONG`), a missing `used-by` (`SH-SOURCE-USED-BY-MISSING`), no tier A (`SH-SOURCE-TIER-MISSING`), a quote over 25 words (`SH-QUOTE-TOO-LONG`), a quote not in the snapshot (`SH-QUOTE-NOT-IN-SNAPSHOT`), a snapshot digest not in the anchor (`SH-SNAPSHOT-DIGEST-NOT-IN-ANCHOR`), a missing Gate quote (`SH-GATE-QUOTE-MISSING`), a changed capture digest (`SH-CAPTURE-DIGEST-MISMATCH`), a pointer on a header (`SH-CAPTURE-POINTER-HEADER`), on a command echo (`SH-CAPTURE-POINTER-ECHO`), on an `[exit ` line (`SH-CAPTURE-POINTER-EXIT`) and on a duplicate line (`SH-CAPTURE-POINTER-NOT-UNIQUE`), a SKILL row missing and a SKILL row outside the section (both `SH-SKILL-ROW-MISSING`), and a lesson prose line that would have crashed the round-25 checker (`lesson-prose-line-replaces-gate-row`, exit 1, `SH-GATE-QUOTE-MISSING`; its sibling `lesson-prose-line-no-crash` shows the same prose shape leaves a sound entry at exit 0). The remaining failing cases cover the entry, entry markdown, lesson, registry and capture missing classes, a malformed entry, a malformed Gate row, a missing or ambiguous snapshot, an absent SKILL section, an absent Gate header, a declared capture-digest mismatch and the empty statement, action and pointer fields.
