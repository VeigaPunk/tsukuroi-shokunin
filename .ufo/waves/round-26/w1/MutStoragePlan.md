4. Two harness defects were found and fixed during that self-test, both caught by the runner itself rather than by reading. 5. Three catalogue expectations were corrected against the harness output, because the first draft over-claimed exact counts. A row-id defect (SHM01, SHM02, SHM04) is a global block under the round-25 convention, so `verified_rows` is 0, not 5; a source edit whose target sources are shared with another row (SHM10, SHM11, SHM17, SHM18) can take more than one row down, so the expectation is a range of 0 to 5; and a renamed SKILL section (SHM35) has no exit code fixed by the rule, which names only the capture and the entry as exit 2, so exit 1 is expected and exit 2 is tolerated. The kill criterion for every mutant stays "the detector does not report verified_rows 6 with exit 0".

6. The runner never writes to the lane. It opens the lane only through `git archive`, and it records the sha256 of every lane file the catalogue touches before and after the run; the fixture run reported `lane digests unchanged: True`, and `git status --porcelain` in the lane after the work shows only untracked wave-1 files, no modification to a tracked file.

## Pre-conditions for the mutation wave (for the L1)

1. The detector `tools/check-storage-health.py` must be committed before the mutation wave runs; the runner uses the sandbox copy of the tool, so the tool is measured at the same revision as the data.
2. The committed snapshots must be inside the revision. The source seats have written `.ufo/waves/round-26/sources/S128.rst` to `S135.txt` in the working tree at the time of writing, but the directory is still untracked (`git status --porcelain` shows `?? .ufo/waves/round-26/sources/`). `git archive` carries only tracked files, so a mutation run against a revision that does not include them would make SHM17 inapplicable and would change every quote verdict.
3. The entry, the lesson and the registry rows must all be in the measured revision; the runner reads them from the archive, never from the working tree.
4. If the real detector does not accept `--repo`, the runner detects that from its `--help` output and falls back to running the sandbox copy with the working directory set to the sandbox, which is what the round-25 tool needs.
