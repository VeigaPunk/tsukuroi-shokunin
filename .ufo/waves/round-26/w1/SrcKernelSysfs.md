9. [obs] **Limit on SH1's second clause.** This file cannot, by itself, establish that the sysfs file and the `btrfs device stats` query "report the same counters": `fs/btrfs/sysfs.c` contains no reference to the ioctl at all (`grep -n 'ioctl' S133.c` → no hit). Evidence: `grep -n 'ioctl' S133.c` → no hit; btrfs-progs `cmds/device.c` fetched at tag v7.1 (HTTP 200, 29049 bytes, sha256 `26754fdcfb17fe8f337922e714930dbe69f13c021e656cc7a01a39af0bb2a56f`), saved under `.ufo/waves/round-26/w1/SrcKernelSysfs/`.

10. [obs] **Wording limit for the entry.** The printed names differ between the two surfaces: the kernel sysfs file prints `write_errs`, `read_errs`, `flush_errs`, while the `btrfs device stats` rendering prints `write_io_errs`, `read_io_errs`, `flush_io_errs` (finding 9). The kernel source fixes only the sysfs names; the ioctl names are user-space labels. Any row wording that says the two surfaces print "the same names" would be wrong; "the same underlying counters, printed under different labels" is what the sources support. Evidence: snapshot lines 2089-2091 against the frozen capture lines 40-42 and 112-114.

11. [obs] **What each counter counts is not in this file.** `fs/btrfs/sysfs.c` names the counters but does not define them; the semantics live in `include/uapi/linux/btrfs.h` at tag v7.2, `enum btrfs_dev_stat_values` (lines 735-752): `BTRFS_DEV_STAT_WRITE_ERRS, /* EIO or EREMOTEIO from lower layers */`, the same comment for `READ_ERRS` and `FLUSH_ERRS`, `BTRFS_DEV_STAT_CORRUPTION_ERRS` "checksum error, bytenr error or contents is illegal ... the block was damaged during read or write, or written to wrong location or read from wrong location", and `BTRFS_DEV_STAT_GENERATION_ERRS` "an indication that blocks have not been written". The header is a supporting read here (sha256 `89b9b77ae8881623e03b8b78475078c0f530a1a5985e85bb48f7b001ed8990b9`), saved under `.ufo/waves/round-26/w1/SrcKernelSysfs/`; the user-facing wording of the same meanings is S128's `btrfs-device(8)`. Evidence: `curl` of `https://raw.githubusercontent.com/torvalds/linux/v7.2/include/uapi/linux/btrfs.h` → HTTP 200, 39971 bytes; `awk` over lines 735-752.

12. [obs] **A limit worth stating in the row.** The attribute is not always five numbers: lines 2080-2081 read `if (!device->dev_stats_valid)` / `return sysfs_emit(buf, "invalid\n");`, so before the per-device stats are loaded the file prints the single word `invalid`. The row should say the file prints the five counters "once the per-device stats are valid", and the `invalid` case is a separate, documented state, not a zero. Evidence: snapshot lines 2080-2081.
