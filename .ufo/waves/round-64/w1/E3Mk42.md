## The decisive finding (why MK3 refutes)

The r1 note read the hook correctly but missed the image side of the same contract. mkinitcpio v42
does not merely move the mountpoint — it **keeps `/new_root` as a relative symlink to `sysroot`**:

- `probes/mk42/m2i-functions-v41-vs-v42.txt` — v41 `functions:1188` creates a *directory*
  `new_root`; v42 `functions:1212-1213` creates `$buildroot/sysroot` and
  `ln -s "sysroot" "$buildroot/new_root"`. The installed `/usr/lib/initcpio/functions` is
  byte-identical to upstream v42 (`sha256 8ccfad02…777d`).
- `probes/mk42/m2g-findmnt-symlink-follow.txt` — `findmnt --mountpoint` resolves through the
  symlink (`new_root -> /boot` → `vfat`, rc=0), while a dangling target returns rc=1. So the hook's
  `findmnt … || return 0` fires only when the symlink is missing, and it is not.
- `probes/mk42/m2s-chroot-final-verdict.txt` — end-to-end, in a chroot whose root **is** the image
  layout (`/sysroot` directory + relative `new_root -> sysroot`), installed hook bytes copied
  verbatim, only the two btrfs query answers stubbed: the line-7 probe returns `btrfs`, the hook
  reaches `[OverlayFS setup] OverlayFS mounted on /new_root`, and afterwards **real** `findmnt`
  reads `/sysroot FSTYPE = overlay`, contents `[marker]`, writable through `/new_root`.
- `probes/mk42/m2m-init-latehook-order.txt` — v42 `init` mounts root at `/sysroot` (line 67) and
  runs `$LATEHOOKS` at line 71, i.e. *after* the mount; the propose order is right.

This matches upstream's stated purpose, already in the registry as S057/S095
(`corpus/SOURCES.md:63,:101`): "/new_root will be kept as a symlink to /sysroot". The r1 note's
[inf] predated a boot on the v42 chain, and its own falsifier ("the hook mounts OverlayFS on the
root") is what the emulation exhibits.

## Why the boot-level state stays `unk` (and why marker absence is not evidence)

`probes/mk42/m8e-marker-sweep-clean.txt` — `OverlayFS setup` appears **0** times in all three
retained boots (44 615 / 34 505 / 137 460 journal lines). That is *not* evidence of a no-op: the
host was never in a snapshot. `probes/mk42/m8g-not-in-a-snapshot.txt` records the host saying so
itself — `limine-snapper-restore[2628]: You are not in a snapshot.` (boot 0) and
`limine-snapper-restore[2666]: You are not in a snapshot.` (boot -1); boots 0 and -1 also carry
`rootflags=subvol=@` (`m7c`, `m7d`). With a writable root subvolume the hook's line-16
`*/snapshot*` guard returns early for an entirely different reason, so the marker cannot appear
either way. The honest label is `unk`, with the operator discriminator named (boot a read-only
snapshot) — never a lane action.

the receipts rather than silently dropped: the chroot loader path (`rc 127`), `/proc` access in a

that exposed the third one; `m2q-chroot-verbatim-hook.txt` ends with a v1..v7 provenance block.
