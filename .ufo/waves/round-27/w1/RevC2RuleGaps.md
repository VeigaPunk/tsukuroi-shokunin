# RevC2RuleGaps — review of the round-27 C2 row rule

Verdict: partly holds. The C2 rule (SCORECARD.md:1002) stops forged digests, wrong ids, over-long quotes, quotes absent from the pinned snapshot or the lane file, null lane sides on non-LANE-GAP rows and a missing PROVINCE id. It does not check that a row is a real mori pointer, that its class follows from the pointed text, or that the published PROVINCE table says what the register says. The committed draft already passes the checker with six of six rows (read-only replay at 5583d75c: anchored_rows 6, sibling-verified, status PASS), so the after-value is reachable without the checks that would make it mean what it says.

Revision facts [obs]: lane HEAD was 75784ea when I listed history and 5583d75c when I replayed the checker, so the lane moved during this review. Mori HEAD is b97b2e3f; the pinned entry differs from it (`git diff --stat ef9dbee HEAD`: 36 insertions, 9 deletions), so the pin is still correct but the live text has moved.

## Findings, most severe first

1. **The inbound vocabulary does not implement QUALITY 32 (rule and checker).** QUALITY 32 requires each inbound sibling pointer to carry a found_line and a RESOLVES, DRIFTED or UNRESOLVABLE class (corpus/QUALITY.md:55-56). The rule's classes are INBOUND-RESOLVES, INBOUND-DRIFTED, AGREES, CONFLICTS and LANE-GAP (SCORECARD.md:1002; tools/check-adjacency-overlap.py:46). The register has no found_line and no UNRESOLVABLE (corpus/knowledge/adjacency-mori-oom-r27.json:12-106). A dangling pointer therefore cannot be recorded as dangling; it can be recorded as LANE-GAP with a null lane side, which the checker accepts (check-adjacency-overlap.py:154-156) without any evidence. Blocked by the rule: no. Refinement: add UNRESOLVABLE to the inbound classes; add found_line to each inbound row; derive the inbound class from the pointed text at the revision, as the round-19 checker does (tools/check-adjacency-anchors.py:741-757, which uses census target ranges and found_line); keep LANE-GAP for true absence only, with recorded evidence (finding 5).

2. **The lane side need not be the file mori points at (overlap may not be real).** The checker accepts any lane_path and any lane_quote of at most 25 words found anywhere in that file at the revision (check-adjacency-overlap.py:157-162). Nothing ties lane_path to a pointer in mori's pinned text. The pinned snapshot names tsukuroi's file explicitly only at line 1 and at lines 256-258 (path and commit 157ee255). OV1's sibling quote sits at line 143, where no path appears; the link to the file exists only in the bullet at 256-258, which OV1 does not cite. Blocked by the rule: no. Refinement: a census of mori's sentences that name tsukuroi or a tsukuroi path, taken from the pinned bytes by a fixed grep and committed before the register; each row cites one census site; lane_path must equal the path that site names; the lane quote must sit inside that path or section.

3. **The row set is not the pointer set; six rows can be reached with topical overlaps.** The claim says "inbound pointers into this lane replayed"; the register's own text says "each place where the two lanes' entries meet" (corpus/knowledge/adjacency-mori-oom-r27.md:9). The pinned snapshot has four distinct tsukuroi reference sites: line 1 (source row, explicit URL pinned to 157ee255); lines 143-144 (the named "sibling lane captured" unit list, no path); lines 153-154 ("tsukuroi's ground (`PROVINCE.md` adjacency row)", no commit); lines 256-258 (path plus commit 157ee255). The draft anchors two of them (OV1 at line 143, OV2 at line 153). The explicit commit-pinned bullet at 256-258 and the line-1 source row have no row. OV3 (quote at 146), OV4 (145), OV5 (128) and OV6 (196) quote mori's own sentences and name no tsukuroi path; they are topical overlaps. The checker only checks the id set (check-adjacency-overlap.py:7-8). Blocked by the rule: no. Refinement: define the mechanical count as one census site plus one proposition, and report topical overlaps as a separate, uncounted list. Under that definition the census yields four sites, so six counted rows would need several propositions from the same site. That is a decision for the L1 before counting. I did not change the after-value; if the census yields fewer than six, the honest result is a miss.

4. **Line 1 cannot be anchored, so a census would drop it silently.** Line 1 sits above the first heading. The checker's heading test takes the nearest `#` line above quote_line (check-adjacency-overlap.py:142-144), so no row can anchor a quote on line 1. Blocked by the rule: no. Refinement: the census records each site as anchored or unanchorable with a reason; an unanchorable site is never omitted from the count.

5. **Named-reference rows mix two pointers (OV2).** OV2's sibling quote points at "the PROVINCE.md adjacency row" (snapshot lines 153-154). Its lane quote, "The existing census reports those signals; fleet correlation belongs to mori", sits in the Core section at PROVINCE.md:32, not in the adjacency table (rows at PROVINCE.md:46-52; ADJ-04 is at line 49). Its action rests on mori's own PROVINCE.md line 66, which lies outside the pinned entry (mori working tree, not pinned). Mori's working-tree PROVINCE line 288 points at tsukuroi PROVINCE.md:30-33 for that routing sentence, which is a different mori pointer. The checker only confirms that each quote appears somewhere in its file. Blocked by the rule: no. Refinement: the lane side of a named reference must be found inside the section the reference names; claims that rest on other sibling files are excluded from the count and listed as observations.

6. **LANE-GAP needs no evidence (OV6).** OV6 has a null lane side and class LANE-GAP (register lines 101-103), which the checker accepts without any search (check-adjacency-overlap.py:154-156). Its action cites a git grep at db9eecfa that is not recorded or rerun. I ran a read-only grep of corpus, PROVINCE.md and SKILL.md for `oomd_ooms|oomd_kill|user.oomd`; the only hits are in the register itself [obs], so OV6 agrees with the lane today. A future file with those names would not change the count. Blocked by the rule: no. Refinement: a LANE-GAP row records the search pattern, paths and commit; the checker reruns the search at the revision and fails on any hit outside the register.

7. **The published PROVINCE table is not checked against the register.** The publication test is that the id is the first cell of a table row in the section (check-adjacency-overlap.py:66-76, 94-95; rule clause A7). The committed table (PROVINCE.md:182-189) gives its pointers as bare line numbers, for example "lane lines 201-202", "lane line 382" and mori "PROVINCE.md:66", with no quote, commit or digest. QUALITY 32 states that a bare `path:N-M` is not a locator (corpus/QUALITY.md:56-57). Nothing compares the class or owner columns with the register, so the two can disagree. Blocked by the rule: no. Refinement: each published row carries id, class, owner, the exact lane path and a quote hash equal to the register's; the checker compares them and rejects bare line ranges.

8. **Quote locator slack.** The window test covers lines quote_line through quote_line + 2 (check-adjacency-overlap.py:151-152), so a quote may begin two lines after the claimed line [inf from the code]. For example, "are cited here, not absorbed (F8)." begins on snapshot line 258; a row with quote_line 256 would pass the window test. The rule also does not require the quote to be unique in the pinned bytes. Blocked by the rule: partly. Refinement: the normalised quote must begin on quote_line; a quote that occurs more than once needs an occurrence index.

9. **The heading test accepts non-headings (latent).** The rule takes the nearest line that starts with `#` (SCORECARD.md:1002; check-adjacency-overlap.py:142). A line such as `#tag` or a comment inside a code fence would qualify. The snapshot has eight `#` lines, all ATX headings (lines 6, 8, 26, 186, 204, 232, 254, 269), and no code fences [obs], so nothing passes through this gap today. Refinement: use the round-19 ATX test and section containment (tools/check-adjacency-anchors.py:42 and the `_heading_section_contains` function at :357).

10. **The sibling path is pinned only in code, and only for one path.** The digest pin applies only when sibling_path equals the entry path (check-adjacency-overlap.py:127-128). A row naming any other path is checked only against the digest it supplies itself. Blocked by the rule: only while no second snapshot is committed. Refinement: the rule itself pins sibling_path and sibling_commit to the entry, and the checker rejects any other value.

11. **The sibling check fails open when mori is absent.** If mori-shokunin is not present, the checker reports sibling-unavailable and the rows still count (check-adjacency-overlap.py:129-133; docstring lines 24-26). The snapshot bytes are pinned by PIN_SHA256 (line 44), so the snapshot cannot change silently. The live bytes at ef9dbee are then unchecked. Blocked by the rule: no. Refinement: a count made with sibling-unavailable is reported as snapshot-only, never as sibling-verified, and the rule states that the measurement runs with the sibling present.

12. **A committed C2 notice adopts mori's position in a lane file.** Commit 75784ea appends to corpus/knowledge/memory-pressure-r25.md:402 a notice that says "read the exception as withdrawn for this host and follow mori's F7; this lane does not restate it". The same sentence restates mori's claim that the delegation "does not exist in the installed earlyoom 1.9.0". The OV5 action says the notice "points at mori's F7 without restating it" (register lines 89), and the PROVINCE section says rows are "reported, never absorbed". Nothing in the rule compares action text with lane writes, and the declaration does not authorise C2 to write lane files. Blocked by the rule: no. Refinement: C2 writes only its own files (register, its .md, its PROVINCE section); a lane notice is a separate item that the register lists by line, and the checker confirms those lines exist.

13. **AGREES and CONFLICTS have no boundary rule.** OV3 is AGREES although its action says mori omits the lane's ancestor-kill clause (memory-pressure-r25.md:202-203). OV4 is CONFLICTS although its action says mori drops the OOMRules= qualifier (lines 387-390). Both are the same kind of omission, with different classes. Blocked by the rule: no. Refinement: define AGREES as "no contradiction and no omitted qualifier the lane states", add a value for an omitted qualifier (or a separate PARTIAL class), and require a recorded qualifier field for that class. Adding a class value does not change the count.

14. **Owner is not checked against class or action.** OV4 has owner tsukuroi while its action is "report to mori"; OV2 has owner mori while its action says the lane edits nothing. The checker only tests that the owner is one of three strings (check-adjacency-overlap.py:47, 169-170). Blocked by the rule: no. Refinement: owner follows a fixed rule per class (for example, DRIFTED goes to the owner of the side that moved; CONFLICTS goes to contested unless one side holds the ground), and the checker enforces it.

15. **The separability sentence may become false.** SCORECARD.md:1004 says C1 changes no file that C2 reads. The C1 row declares a "new PROVINCE frontier area" (SCORECARD.md:995), and C2 reads PROVINCE.md (OV2's lane side and its own section). At HEAD, PROVINCE.md differs from the claim base only by the 13-line C2 section (`git diff --stat 3beab8dd -- PROVINCE.md`). [inf] If C1 adds its frontier area, the sentence is false at file level even if the sections stay apart. Refinement: state separability at hunk level and have the checker confirm that no C1 hunk overlaps the C2 section.

16. **The checker's selftests do not cover these gaps.** The 17 selftest cases (check-adjacency-overlap.py:210-270) cover a duplicate id, digest mismatch, heading not nearest, quote outside window, quote too long, lane quote missing, null lane not gap, invalid class, owner, action, commit, a missing PROVINCE row or section, a missing row and sibling unavailable then mismatch. They do not cover UNRESOLVABLE, a quote beginning two lines late, a LANE-GAP search hit, a second sibling path, bare-range PROVINCE rows, class or owner mismatch against PROVINCE, or a lane notice. Refinement: one fixture per finding above that the rule must refuse.

## Refinements, and what each does to the count

- Findings 1, 2, 5 and 6 can lower the draft count. OV2 (two pointers) and OV6 (unrerun search) are the most exposed, and OV3 to OV5 are topical rows that a pointer census would remove. A stricter rule could land below six. That result is an honest miss to report, not a reason to loosen the rule or to change the target of six.
- Findings 3 and 4 need an L1 decision before counting: what a row is (one census site plus one proposition, or one topical overlap). The after-value stays six as declared.
- Findings 7 to 16 are publication, vocabulary and test-coverage changes. They do not change which rows exist, so they leave the count unchanged unless a row fails the new check.

## Residual risk and unknowns

- [unk] Whether the L1 will measure at a later revision, after mori's entry moves again. The pinned count does not follow mori's live text.
- [inf] AGREES and CONFLICTS are judgments that no checker can mechanise; the refinements only bind them to recorded qualifiers and to text the row names.
- [unk] Whether mori's live text at b97b2e3f still supports OV1 to OV6. I did not check this; it is outside the pinned count.
- I did not run the official measurement. The replay at 5583d75c is a read-only check of what the rule currently accepts, not verification of the lane's count.
