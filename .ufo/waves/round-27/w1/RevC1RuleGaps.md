# RevC1RuleGaps — C1 row rule review against round-26 lessons and QUALITY 60-66

Verdict: holds — the C1 row rule closes the concrete failure modes round 26 actually hit (Gate column offset, duplicate ids, digest-free snapshots, un-25-worded quotes, absent SKILL row), but a row can still pass with evidence that is real yet irrelevant: a generic quote, a capture pointer on an unrelated unique line, an id-only SKILL row, or a statement that never touches its own links; seven refinements below tighten these without changing the declared after-value of 6.

The rule under review is the paragraph at `SCORECARD.md:999-1000` (declaration commit `db9eecfa876a865f799aa56856a780d299b4f067`). Its clauses, numbered for reference: (R-ids) entry JSON holds exactly KT1..KT6 once each; (R-fields) non-empty statement, verdict from HEALTHY/DEGRADED/BLOCKED/UNVERIFIED, an action; (R-src) every cited source a SOURCES row, status mined, opened 2026-10-22, used-by naming `corpus/knowledge/kernel-taint-r27.md`, at least one tier A; (R-quote) at least one quote of at most 25 words, whitespace-normalised substring of the committed snapshot whose sha256 is in that source's anchor cell, and equal to a located-quote cell of a Gate row for that source (header-position reading, one outer quote/backtick pair stripped); (R-cap) at least one capture pointer to a non-`### `/`$ `/`[exit ` line, occurring once, containing a token of at least 3 characters; (R-skill) id is the first cell of a table row inside `## Kernel taint — round 27` in SKILL.md.

## Part 1 — weak-evidence routes the rule as written blocks

These are the routes round 26's lessons actually recorded; each is closed by the text quoted above. Listed so the reviewer of record can see they were checked, not skipped.

1. Duplicate or missing row ids — blocked by R-ids ("a duplicate is an error, never a second count"). [obs] Rule text, SCORECARD.md:999.
2. Quote longer than 25 words, or fabricated/paraphrased (not a substring of the snapshot), or a snapshot whose bytes do not hash to the anchor digest — blocked by R-quote. This closes the round-26 snapshot-discipline class (round-26.md Gate: every quote "checked by the L1 as a whitespace-normalised substring of the committed snapshot"). [obs]
3. Quote that no Gate row for that source carries — blocked by R-quote's equality arm; and the R26-GATE-COLUMN-OFFSET failure (an unquoted cell not found) is closed at rule level by the header-position reading plus the one-pair quote/backtick strip (SCORECARD.md:999; QUALITY 64; routed defect 3). [obs]
4. Cited source not mined, wrong opened date, used-by not naming the entry, or no tier-A source — blocked by R-src (QUALITY 61's sister conditions). [obs]
5. Capture pointer on a `### ` heading, a `$ ` command line, an `[exit ` marker, or a repeated line — blocked by R-cap. [obs] Measured on the frozen capture (`capture.txt`, sha256 `88d02d98…841`, 138 lines, 57 non-excluded lines): `Dual MIT/GPL` x4 (lines 52, 71, 90, 109), `615.78.08` x6, `DKMS module signing key` x4, vermagic lines x4 — all fail the once-only clause; `12288` (line 11), `module_taint nvidia OE` (line 16), the two journal lines (135-136) and each `error: No package owns …` line are unique and pass that clause. A 1-2 character token (e.g. the bare `N` at line 21) is blocked by the ≥3 rule. [obs]
6. Missing statement, action, or out-of-vocabulary verdict; missing SKILL table row in the section — blocked by R-fields and R-skill. [obs]
7. Stale or self-referent measurement — not part of this row rule but covered elsewhere: the counting command is pinned to the measured commit with data from `<REV>` (QUALITY 57), and ordinal self-agreement is QUALITY 62/65 territory with the fix assigned to ExecSelfAssessQ65 (routed defect 2). No gap in C1's row rule here. [obs]

## Part 2 — weak-evidence routes the rule as written does NOT block

8. **Generic-word quote (umbrella: the truth gap, disclosed).** R-quote requires the quote to exist in a real, digest-pinned snapshot and in a Gate row; it never requires the quote to be about the row's claim. A 2-word fragment like "the kernel" taken from an unrelated paragraph of a genuine snapshot satisfies every clause. This is the concrete mechanism behind the spot-check's ruling on the predecessor: "the rule checks evidence links and a non-empty statement, not whether the statement is true. The report says this itself" (`corpus/lessons/round-26-verifier-spotcheck.md:44`). Not blocked by the rule as written; disclosed as the claim's semantics, so the refinements below must sharpen the links, not claim truth-checking. [obs]
9. **Quote-source binding is ambiguous in the rule text.** R-src constrains "every source it cites", but R-quote never says the quote's `S###` must be among the row's cited sources. The predecessor's independent recount (c1_indep.py in the same spot-check) looked quotes up with `src.get(q["source"], {})` and checked the quote's source for neither mined status nor used-by — a quote from a queued or rejected source that happens to have an anchor digest and a Gate row would pass. The round-27 rule text can be read either way; the new checker decides. Not blocked under the predecessor's accepted reading. [obs]
10. **Capture pointer to an irrelevant unique line.** R-cap binds the pointer to the capture file, never to the row's question. A KT5 row (is a taint flag cleared) may point at line 124 `nvidia-open-dkms 615.78.08-1` with token `dkms` (unique, non-excluded, 4 chars) — passes. A KT1 row (integer encoding) may point at line 132, the error line `cat: /proc/sys/kernel/panic_on_taint: No such file or directory` — unique, non-excluded, passes, and it is an absence/error line whose evidential direction the rule cannot read. Nothing requires the token to appear in the statement, nor the line to sit in the row's relevant capture section (### tainted, per-module-taint, sig_enforce, kernel-journal-taint). Not blocked. [obs]
11. **Token can be a fragment of a word.** R-cap says "contains the pointer's token"; there is no word boundary, so a 3-4 character fragment inside a longer word matches. Low impact given the uniqueness clause, but free to harden. Not blocked. [obs]
12. **SKILL row with only the id.** R-skill needs the id as the first cell of a table row in the section; `| KT1 | | | |` passes, and if the section carries two tables (round 26's section also held error patterns SE1-SE4), the id may sit in the wrong table and still count. This weakness is inherited verbatim from the predecessor: the round-26 recount checked only `r["id"] in skill_ids`, and ExecMemCheckerHarden's round-26 hardening likewise added only "the id in the first cell of a table line inside the round-25 section" (round-26.md, routed defect 4 section). Not blocked. [obs]
13. **Vacuous statement and action.** R-fields asks non-empty only; "yes" as statement and "read dmesg" as action pass while carrying no content, and the action's text is never checked against the round's host-action bounds (an action line teaching a sysctl write would count, though executing it is forbidden). Not blocked; row-truth is the spot-check's job by design, per finding 8. [obs]
14. **UNVERIFIED rows count toward `verified_rows`.** The vocabulary admits UNVERIFIED, so a row that attests it could not verify still counts as a verified row (the linking is verified, not the content). Disclosed in the predecessor's ruling and consistent with round 26's SH6 split verdict being counted. Not a new defect; recorded so nobody reads 6/6 as 6 truths. [obs]
15. **The Markdown entry is unbound.** The rule counts the JSON only; SOURCES used-by names the `.md`, but nothing requires `kernel-taint-r27.md` to exist or to agree with the JSON rows. This is exactly the class of routed defect 1: round 26's corrections landed in the `.md` while `storage-health-r26.json` kept the withdrawn SH2/SH4/SH6 wording with no marker (`round-26-verifier-spotcheck.md:52`, routed defect 1). Not blocked. [obs]
16. **Gate location cell unchecked.** R-quote compares texts; the located-quote cell's *location* (file line) is never re-derived, so a wrong line number passes the rule. Round 26's one real slip (S129 quote at snapshot line 192 recorded as 190) was caught by human review, not by any rule (`round-26-verifier-spotcheck.md`, discernment table row 5). Not blocked. [obs]
17. **used-by names only the Markdown entry.** Inherited from round 26: "the round-26 rows' used-by cells name only the Markdown entry, not the JSON" (`corpus/lessons/round-26.md:137`). R-src inherits the same one-path test. Not blocked; already recorded as owed with superseding rows, so this is a note, not a new ask. [obs]
18. **QUALITY 66 breadth is not mechanical.** A statement keeping one of two source branches passes R-fields; only the scribe specs and wave-2 review enforce the every-branch rule. Round 26 recorded three recurrences (S128 "only", S135 trigger, S136 ancestor case). Not blocked by the rule as written, and I do not ask the counting gate to parse prose; the refinement below is a cheap tripwire only. [obs]

## Part 3 — refinements that tighten without changing the after-value

Each refinement keeps the declared target (6 verified rows, exit 0) reachable by honest data, because every one is satisfiable against the frozen capture and the round-26 precedent (rows carried 3-6 quotes and 1-4 pointers each, spot-check C1 section). Recommend landing them in the rule text and checker before ExecTaintChecker pins the tool, and proving each with a red selftest mutant (QUALITY 64 style).

19. **Bind each quote to a cited source (finding 9).** One clause: "the quote's source is one of the sources the row cites". Real rows quote their own sources, so the after-value is untouched; the checker gains the mined/used-by/tier-A checks for quote sources it inherited without.
20. **Bind each capture token to the row's statement (finding 10).** Require the pointer's token to occur in the row's own statement text (whitespace-normalised). Feasibility on the real capture: KT1 token `12288` (line 11), KT2 `out-of-tree` (lines 135-136), KT3 `sig_enforce` (line 21) or `CONFIG_MODULE_SIG_FORCE` (line 28), KT4 `module_taint` (lines 14-17), KT5 `panic_on_taint` (line 132), KT6 `taint` (lines 135-136) — all ≥3 chars, all unique lines, all words the honest statements will contain because the questions themselves name them. Red case: the `dkms`-token pointer of finding 10 fails.
21. **Word-boundary token match (finding 11).** Token must match on non-alphanumeric boundaries. Pure hardening; no honest pointer regresses.
22. **SKILL row must carry a non-empty cell besides the id, and the section lookup must be line-anchored at its first occurrence (finding 12).** Real SKILL rows state a command, so the after-value holds; `| KT1 | | |` and an id in the section's error-pattern table fail.
23. **Bind the Markdown companion (finding 15).** Checker requires `kernel-taint-r27.md` to exist, its row-id set to equal the JSON's (each id once on both sides), and every appended correction bullet in the `.md` to name an id present in the JSON. This lands routed defect 1's lesson as a gate instead of a repair; with a correctly landed entry it changes nothing.
24. **Gate location near-check (finding 16).** The quote must occur in the snapshot within ±2 lines of the Gate row's location cell. Tolerance chosen from round 26's one real slip (off by exactly 2); honest Gate rows pass, invented locations fail. Validate the tolerance against round 27's actual Gate rows at integration before pinning.
25. **Optional tripwire for QUALITY 66 (finding 18).** Checker warns (does not block) when a statement contains "only", "otherwise" or "exactly" and no quote cited by that row contains the same word. Keeps the counting gate out of prose parsing while making the round 26 recurrence class visible at measure time.
