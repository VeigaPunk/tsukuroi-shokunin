2. [obs] An irrelevant capture pointer counts. 9. [obs] Tool bug: an unhashable id crashes the counter with exit 1, which the docstring reserves for "any declared row fails". The cause is `counts[key] = counts.get(key, 0) + 1` (tool line 582). By contrast, an unhashable source item is handled correctly: exit 1, 5, KT-SOURCE-MISSING (line 20). A crash is reported as an ordinary FAIL instead of CANNOT_EVALUATE (exit 2), so a runner that reads only the exit code cannot tell them apart. This path is identical in `tools/check-storage-health.py`; the diff shows only renames there [inf from diff]. It cannot inflate the count. Correction: treat a non-string id as KT-ROW-SHAPE before counting.

10. [obs] The tool is stricter than the declared rule on "at least one". A row with one good quote and one bad quote fails: exit 1, 5, KT-QUOTE-NOT-IN-SNAPSHOT and KT-GATE-QUOTE-MISSING (line 14). A row with one good pointer and one pointer on a `### ` line fails: exit 1, 5, KT-CAPTURE-POINTER-HEADER (line 15). The declared rule says "at least one quote" and "at least one capture pointer" (SCORECARD.md:1000), but every per-quote finding (tool lines 694-722) and every per-pointer finding (tool lines 733-736) is blocking. The KT-CAPTURE-POINTER-UNUSABLE path (line 739) shows "at least one" was the intent for pointers. This error is on the safe side: it can only refuse a count, and the measured 6 still holds because every real quote and pointer passes. It is still a divergence between the declared rule and the counting command. Correction: either restate the rule as "every quote and every pointer", or make per-item findings non-blocking when at least one item passes. The first choice is the smaller change and keeps the stricter behaviour.

11. [obs] No Gate cell shape can carry a quote that contains a pipe. The cause: a raw pipe splits the cell (selftest 37 expects this), and an escaped pipe survives as `\|` in `split_cells` output, so the cell never equals the entry text. This is a gap the declared rule leaves open, because "equals the located-quote cell" has no unescaping step. It does not affect round 27, since no KT quote contains a pipe [obs], but it rules out many kernel C lines. Correction for a later round: unescape `\|` to `|` in the cell before comparing.
