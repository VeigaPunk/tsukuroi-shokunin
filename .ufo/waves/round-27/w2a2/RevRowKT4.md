8. "set together with the kernel-wide bit when the module causes a taint" and "names which loaded module caused which letter" overstate the cited source in both directions — a QUALITY 66 every-branch violation (`corpus/QUALITY.md:133`) [obs]. The same file the row quotes contains three branches the sentence erases:
   - S143.c:1251-1255 — a module that only *uses GPL-only symbols of* a proprietary module gets `set_bit(TAINT_PROPRIETARY_MODULE, &mod->taints)` with no matching kernel-wide `add_taint` at that point; the file then names an inheritor, not the causer.
   - S143.c:2616-2620 — ndiswrapper gets the kernel-wide bit via plain `add_taint` with an explicit comment "Don't use add_taint_module()", so a kernel-caused-by-module taint can appear with no per-module name.
   - S143.c:747 — `add_taint(TAINT_FORCED_RMMOD, …)` on a forced unload is kernel-wide only; like W, D and L it is a letter no module file can name, which directly bounds "which the kernel-wide number cannot do".
   Additionally `last_unloaded_module.taints` (S143.c:639-641, 873, 3974-3975) records taints of a module that is no longer loaded, so "which loaded module" misses that the letters can outlive the load.
   Corrected wording for the statement: "Each loaded module keeps its own taint bits in `mod->taints`. When a module causes a taint the kernel normally sets the same bit on the module and on the kernel-wide mask (`add_taint_module`, S143 lines 194-198), but the two records are not locked together: a module that only inherits another module's proprietary taint gets its own bit set without adding to the mask (S143 line 1254), and a kernel-wide taint can be set without marking any module (forced unload, S143 line 747; the ndiswrapper exception, S143 lines 2616-2620). `/sys/module/<name>/taint` prints the module's own bits as letters, read-only (mode 0444). The file names which loaded module carries which module-attributed letter — information the bare number lacks — but event taints such as W, D or L and the kernel-wide-only branches above appear in no module's file." For the host's actual letters O and E nothing changes.

A sibling seat found the identical defect (`.ufo/waves/round-27/w2a2/RevSkillKernelTaint.md` finding 1, and the L1's uncommitted SKILL note already carries the guard); this is an independent re-verification. Corrected command: `for f in /sys/module/*/taint; do [ -e "$f" ] || continue; t=$(cat "$f"); [ -n "$t" ] && echo "${f%/taint} $t"; done` (output identical, exit 0; also quote `$f`).
