## Findings, most severe first

1. The declaration clause "holds exactly the ids OV1 to OV6, each once" is implemented loosely: surplus rows neither count nor fail the run. [obs] The declaration (/home/vgpnk/Projects/shokunin/tsukuroi-shokunin/SCORECARD.md:1000) requires the register to hold exactly the six ids. The code only checks membership in the fixed id tuple and per-id uniqueness (tools/check-adjacency-overlap.py:105-108), and the anchored count at :178 iterates only OV1 to OV6, so a seventh row with an unknown id, or a non-dict junk element in `rows`, is silently ignored. Probe evidence (probe at /fast/scratch/hyaku/tsuku27a2/RerunC2/probe.py, run exit 0): a fixture register with OV1 to OV6 plus `{"id": "OV9", ...}` evaluated to exit 0, anchored_rows 6, status PASS; the same six plus a bare string element also evaluated to exit 0, anchored_rows 6. Impact [inf]: widening only — a future register could carry junk while still passing six of six, but no row outside the six ids can ever be counted, so the declared after-value of 6 cannot be inflated through this gap. A related sub-gap: a non-dict element is skipped at :101-102 without any diagnostic appearing in the JSON output.

2. The tool's own documented exit contract promises exit 2 when "the register or the snapshot cannot be read", but the code exits 2 only for register and revision problems; an unreadable snapshot yields exit 1. [obs] The promise is at tools/check-adjacency-overlap.py:28-29; the only exit-2 returns are revision-invalid (:82), register-missing (:86) and register-unreadable (the except branch around :88-92). Probe evidence: a fixture repo whose committed snapshot file was removed and recommitted evaluated to exit 1, anchored_rows 0, with per-row reason `snapshot-missing` and sibling_check `sibling-unavailable`. The declaration text itself (SCORECARD.md:1000) specifies no exit codes for C2, so this diverges from the tool's docstring rather than from SCORECARD; the docstring is part of the committed tool, so I record it as a clause the tool does not implement.

3. Boundary behaviour the declaration does not cover: a sibling repository that is present but cannot serve the pinned commit is treated as a byte mismatch, not as sibling-unavailable. [obs] At tools/check-adjacency-overlap.py:129-133 any `git cat-file -p <pin>:<path>` failure (non-zero exit or differing bytes) appends `sibling-bytes-differ` and sets sibling-mismatch, which zeroes the count at :179-180. Probe evidence: a siblings-root containing an empty `git init` mori-shokunin gave exit 1, anchored_rows 0, sibling_check `sibling-mismatch`, every row `sibling-bytes-differ`. [inf] This is fail-closed and safe, but it means an incomplete sibling checkout (for example a shallow clone lacking ef9dbee1) fails the whole count instead of degrading to the declared snapshot-only path. The declaration (SCORECARD.md:1000) distinguishes only present-must-equal from absent-still-counts.

4. Register metadata precision: for OV1, OV2, OV3, OV4 and OV5 the register's `quote_line` sits one line above the line where the quoted text physically starts.
