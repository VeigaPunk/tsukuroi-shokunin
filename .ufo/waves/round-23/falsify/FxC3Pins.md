## Attacked claim

**C3 (preregister.json, calibration axis).** `metric: unexplained_cohorts`, `before: 2`,
`target: 0`, `command: python3 tools/check-path-reconciliation.py --revision <REV>`, scope:

Sub-claims actually attacked here:

- **C3-a "frozen digests"** — the six r22 cohort files plus the outside census source are
  digest-pinned and tamper-evident.
- **C3-b ledger↔input binding** — `inputs_sha256` binds the ledger to the inputs it was
  derived from.
- **C3-c missing vs tampered** — the two failure modes are distinguished and fail closed.
- **C3-d `--emit-ledger` cannot launder tampered inputs** into an accepted ledger.
- **C3-e one canonical runtime / same identity** — one derivation implementation, one set of
  authoritative input paths, no silently divergent duplicate.

## Axes named (godspeed)

1. *Pinning strength* — is a pinned artefact actually load-bearing, or decorative?
2. *Laundering path* — can an unpinned/tampered input be converted into an accepted artifact?
3. *Fail-closed integrity* — does every anomaly exit non-zero with an accurate diagnostic?
4. *Anchor independence* — is the certified ground truth anchored outside the artefact that
   certifies it?
5. *Contract honesty* — do exit codes, payloads and recorded evidence match the docstring and
   the published claim?

## Findings by severity

### S1 — HIGH — the certified ground truth is anchored only inside the file that certifies it; a coordinated rewrite of the frozen cohort passes with exit 0

Evidence (candidate/tools/check-path-reconciliation.py):

- `:194-208` `evaluate()` verifies each pinned file against the digest **declared in the same
  pins file** (`pins['inputs']`, read at `:200`; digest compare at `:205`).
- `:215-216` the ledger is bound to the pins *bytes* (`inputs_sha256 == sha256(pins_raw)`),
  i.e. the ledger and the pin are regenerated together, never independently.
- `:177-182` `expected['rough_as_reported']` / `expected['lane_retained']` are compared only
  against values recomputed from the very files the pins describe.
- `:235-238` `build_ledger()` derives the ledger from the same `files` map.
- The independent copy of the outside ground truth exists — `preregister.json`
  `outside_round22.path_counts_as_reported` = rough {build 25, falsify 33} / lane {build 23,
  falsify 29} — and `frozen/reconciliation-inputs.json` `expected` reproduces it verbatim.
  **The checker never reads preregister.json**, so the two copies can diverge silently.

Concrete falsifier (static, no execution required): in one commit, (1) delete seat *S* from
`.ufo/waves/round-23/snapshot/r22/build/events.json`, its entry in `bindings.json` and its
`SCOPE-PATH-DENIED` findings in `audit.json`; (2) update those three digests in
`frozen/reconciliation-inputs.json`; (3) set `expected.build.{rough_as_reported,lane_retained}`
to the newly derived totals; (4) commit the ledger regenerated by `--emit-ledger`.
`check-path-reconciliation.py --revision <new-rev>` then returns **exit 0, status PASS,
unexplained_cohorts 0**, for a cohort that no longer contains the events the outside census
counted. Nothing in the PASS payload names the outside numbers it supposedly reconciled
(`:225-232` publishes derived totals only; `expected` never appears in the output).

Bounded limit of this finding (honest scope): every **single-file** tamper is caught — see
"What held" below. Only the coordinated seven-file rewrite escapes, and it requires commit
access; it is visible in the diff but **not machine-detectable by this checker**.

Smallest in-scope remedy: have `evaluate()` cross-check `pins['expected']` against the
preregistered outside counts (`preregister.json` → `outside_round22.path_counts_as_reported`)
read at the same bound revision, and fail closed with a distinct id (e.g.
`RECONCILIATION-EXPECTED-DRIFT`). That is the only remedy in this list that gives the four
outside numbers an anchor outside the file being certified. It does not re-run the outside
census (forbidden) and implies no runtime enforcement.

### S2 — HIGH — `--emit-ledger` regenerates a ledger from unpinned inputs and exits 0; it never performs the digest check

Evidence: `main()` at `:365-373` — `files = {path: git_read(binding.sha, path) for path in
strict(pins_raw)['inputs']}` then `if args.emit_ledger: print(json.dumps(build_ledger(pins_raw,
files), …)); return 0`. `build_ledger` (`:235-238`) calls `derive()` on those raw bytes and
never consults `pins['inputs']`; the only digest comparison in the program lives in
`evaluate()` (`:201-206`), which the emit path bypasses.

Consequence (answers the assignment question directly): **yes, the ledger can be regenerated
from tampered inputs and still pass — but only if the pins digest for the tampered file is
updated in the same commit.** Concretely:
- tampered cohort file + untouched pins → `--emit-ledger` prints a ledger for the tampered
  bytes and exits 0 with no `SNAPSHOT-TAMPERED`; committing that ledger alone then fails
  closed at `:206` (exit 2, `SNAPSHOT-TAMPERED`);
- tampered cohort file + updated pins digest + regenerated ledger → exit 0, PASS (see S1).

So the emit path is exactly the laundering step the checker's own docstring does not mention
(`:358` help text: *"print the recomputed ledger from inputs at --revision"*). No selftest case
exercises it: `selftest()` (`:251-349`) calls `evaluate()` only, never `main()`'s emit branch.

Smallest in-scope remedy: run the same pins-digest verification used by `evaluate()` before
printing in the emit branch, and exit 2 with `SNAPSHOT-TAMPERED` / `SNAPSHOT-MISSING` instead
of emitting a ledger; add one selftest case asserting the emit path refuses tampered inputs.

### S3 — MEDIUM — the pinned path set is self-selected and unchecked

`:200` iterates `pins['inputs'].items()`; `derive()` reads hardcoded paths
`files[snap+wave+'/{events,bindings,audit}.json']` (`:238`, and the cohort loop at `:220-224`).
Nothing requires the six cohort files (or the census) to be listed.

- Remove `.ufo/waves/round-23/sources/r22-rough-census.txt` from `pins['inputs']` → the
  verdict is unchanged (**PASS**); the census pin is self-removable and its removal is invisible.
- Remove one of the six cohort paths from `pins['inputs']` → `KeyError` is raised inside
  `evaluate()`'s cohort loop, which `evaluate()` does not catch → propagates to `main()`
  `:379-381` → exit 2 with the **mislabeled** id `RECONCILIATION-READ` / site `revision`. A
  pins-scope defect is reported as a revision read failure.

Smallest in-scope remedy: assert the required input-path set is present in `pins['inputs']`
and report a distinct id (e.g. `RECONCILIATION-PINS-SCOPE`), exit 2.

### S4 — MEDIUM — the census digest is a dead pin, and the census file cannot carry the outside numbers

`grep` over the tool shows the census path appears only in the selftest fixture (`:269`) and
in the pins map; its bytes are never passed to `derive()`, `rough_event()`, `canonical_event()`
or any comparison — they are only hashed. `sources/r22-rough-census.txt` contains the outside
**script** only, with no recorded output, so no amount of parsing could confirm 25/33. The
honest "never executed from it" statement (`:32`) is satisfied, but the pin buys
tamper-detection of bytes that are irrelevant to the verdict, while the actual outside ground
truth (25/33) is anchored nowhere machine-checkable except `pins['expected']` (S1).

Smallest in-scope remedy: either drop the decorative digest from the pins file, or make the
census load-bearing (see S5).

### S5 — MEDIUM — the outside census's per-category breakdown is never pinned or compared; re-authoring fidelity is checked only in aggregate on one column

`sources/r22-rough-census.txt` prints `print(w, dict(f), sum(f.values()), 'seats', len(seats))`
— a per-category dictionary (`path`/`exec`/`unknown`) *plus* a category sum. The tool's totals
(`:159-168`) keep only `rough_path`, `canonical_path`, `retained_path`, `events`; `pins['expected']`
records only `rough_as_reported` and `lane_retained`. The tool's own `exec`/`unknown`
categories (`rough_event`, `:61-73`) are never totalled, so a re-authored-rule divergence that
preserves the path total but reclassifies exec/unknown events is invisible. C3's "exhaustive
… explanation" therefore covers the path axis only, not the full outside category vector.

Smallest in-scope remedy: extend `expected` with the outside per-category counts and compare
the tool's per-category totals against them (add `exec`/`unknown` to `totals`).

### S6 — LOW — the unit of the outside counts is undeclared

`expected['rough_as_reported']` carries no unit/basis label. The census prints both a
per-event path count and a category sum, and the tool compares against the per-event path
count only (`:177`). A reader of `path-reconciliation.json` cannot tell that 25/33 are
per-event path counts rather than the census's `sum(f.values())`. Remedy: add an explicit
`unit`/`basis` field to `expected` and echo it into the ledger and knowledge record.

### S7 — LOW — the exit-code contract is violated for argparse terminations

`:359-362`: `except SystemExit as exc: return 0 if exc.code == 0 else 2`. `--help` therefore
exits **0** with help text on stdout and no JSON payload, and a missing/duplicate
`--revision` exits 2 with **no payload at all** (the payload print at `:382` is skipped by the
early return). A CI gate that reads the exit code alone treats `--help` as a pass, contradicting
the documented contract "Exit 0 every fixed cohort explained". Remedy: on any argparse
termination print a JSON payload (`status: CANNOT_EVALUATE` / `USAGE`) and return 2.

### S8 — LOW (coverage gap) — no selftest or mutation pins the properties this attack depends on

`pins_for()` (`:271-273`) computes the pins digests **from the very fixture files** it later
checks, so the suite cannot express a pins-vs-files disagreement except the single
`snapshot-tampered` case (`:319-320`). There is no case for a pins-scope shrink (S3), for the
emit path (S2), or for expected drift (S1). The l1-mutation record
(`candidate/.ufo/waves/round-23/measure/l1-mutation.json`, author-side) lists 10 mutants for
this tool — including the digest comparison (mutant 2) and the ledger-mismatch check
(mutant 1) — but none for the `rough_as_reported` comparison (`:177`), none for the pins-scope,
none for the emit path.

## Bounded search — what held (no falsifier found)

- **Single-file tamper of any of the six cohort files at the bound revision** → exit 2
  `SNAPSHOT-TAMPERED` (`:205-206`); the digest check runs before `derive()` and before the
  ledger comparison, so no derived value can be produced from an unpinned file.
- **Weakening the lane audit alone** (deleting or renaming one `SCOPE-PATH-DENIED` finding)
  is caught even if its digest is updated: `canonical_path` is recomputed from events+bindings
  and must equal `retained_path` (`:181`) → `RECONCILIATION-CANONICAL-MISMATCH`, exit 1. The
  audit cannot be quietly weakened without also weakening the event/binding data.
- **Hand-editing the committed ledger** (any row, forged disposition, dropped/duplicated/
  reordered row, wrong totals block) → `RECONCILIATION-LEDGER-MISMATCH` (`:189`), exit 1. The
  comparison is whole-object equality against a fresh re-derivation, not a spot check, so the
  ledger cannot drift from the code that produced it.
- **A ledger built from different pins bytes** → `RECONCILIATION-SCHEMA` (`:215`), exit 1.
- **Missing vs tampered are distinguished**: `SNAPSHOT-MISSING` (`:204`) vs `SNAPSHOT-TAMPERED`
  (`:206`), both exit 2 with `unexplained_cohorts: null`. (Caveat: missing is only detectable
  for paths the pins still declare — S3.)
- **Duplicate JSON keys** in pins or ledger are rejected by `strict()`/`unique()` (`:43-53`)
  → `RECONCILIATION-PINS` / `RECONCILIATION-SCHEMA`, exit 2 / exit 1.
- **One canonical runtime / same identity (C3-e)**: `build_ledger` (`:235`) and `evaluate`
  (`:222`) both call the same `derive()` (`:111`); there is no second counting implementation.
  The only duplication is the deliberate re-authoring of the outside rule, whose source cell is
  never executed (`:32`; census bytes never reach `derive`). Rough (per-event) and canonical
  (per-component) counts remain mutually independent, which is the ledger's declared subject.
  Runtime input paths are repo-root-relative and unique: `git_read` (`:241-249`) resolves
  `rev:path` against the repository root, so the duplicate copies under
  `.ufo/waves/round-23/candidate/` are inert at runtime — but see the verification gap below.
- **Ledger schema drift is not tolerated**: object equality at `:189` includes the totals key
  set, so a ledger produced by an older code version is rejected rather than silently accepted.

## Verification gaps (stated, not worked around)

1. `executed=none`: every finding above is a static reading of the declared files. The tool was
   not run, no digest was computed, and no digest was independently validated (the reviewed
   SHA256 is a supplied declaration).
2. `tools/_revision.py` is outside this seat's declared read scope, so the revision-binding
   trust root is unverified. **S1's severity depends on it**: if `_revision.bind` restricts
   `--revision` to a pre-registered/approved commit or an ancestor of the branch tip, the
   coordinated rewrite cannot be evaluated at a tampered tip and S1 degrades from a pinning
   hole to a robustness/reporting defect. This should be resolved by the seat that owns
   `_revision.py` before S1 is ranked.
3. The committed ledger `.ufo/waves/round-23/path-reconciliation.json` and its candidate copy
   `candidate/.ufo/waves/round-23/path-reconciliation.json` are outside this seat's declared
   read paths, so I could not verify that the committed ledger equals the current derivation,
   nor whether the two copies are byte-identical. The runtime path is unique (root-relative),
   but a divergence between the duplicate copies would be publishable as evidence while never
   being checked — a same-identity gap for the published artifact, not for the checker.
4. `frozen/reconciliation-inputs.json` digests were not compared with the working-tree files
   (out of scope; digests are supplied declarations). Every tamper claim above is about the
   *committed* tree at the bound revision, which is what `git_read` inspects.
5. Whether the outside figures 25/33 are the census's `f['path']` or its `sum(f.values())`
   could not be settled from the declared files: `sources/r22-rough-census.txt` carries the
   script only, with no recorded output. The tool compares against the per-event path count
   (`:177`), so if the preregistered figures were the category sums, the rough check would be
   comparing different columns. Reported as the unit risk S6, not as a proven defect.

## Bottom line

The single-file pinning layer is sound: digest mismatch → exit 2 `SNAPSHOT-TAMPERED`, missing →
exit 2 `SNAPSHOT-MISSING`, ledger edit → exit 1 `RECONCILIATION-LEDGER-MISMATCH`, audit
weakening → exit 1 `RECONCILIATION-CANONICAL-MISMATCH`, and one shared `derive()` serves both
the emitter and the checker. Two holes remain, and both are in the *anchor* rather than in the
comparisons: the certified ground truth lives inside the same file that certifies it and is
never cross-checked against the preregistered outside observation (S1), and the ledger-emit
path performs no pinning at all (S2). R1+R2 are cheap and strictly harden the tool; R3 is the
one that makes the outside anchor independent of the artifact it certifies.
