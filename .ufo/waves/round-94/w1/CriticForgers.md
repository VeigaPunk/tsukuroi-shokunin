## 1. Docstring-only independent implementation (f1)

`f1-docstring.py` (sha256 `4f8d6f280f5b30486381651a6d2389b63803b9f86e3fbbdcce4587edd96641e8`) was written from the battery's module docstring — R1–R10, V1, V2, V3/V4, U1 and the GATE OUTPUT CONTRACT — with no import of the battery or the gate, a fresh parser and its own internal structure (`parse_version`, `probe_version`, `split_key`, `parse_pin`, `evaluate`). Its `parse_limine_version` implements the 1–9-digit bound and the not-word-char suffix guard exactly as the docstring's V2/V3 text states them: `parse_version` accepts `X.Y.Z` with 1–9 digits per component (leading zeros normalized by `int()`, anything else refused rc 64), and `probe_version` runs `limine --version` and takes the first `X.Y.Z` immediately following `limine` (case-insensitive, optional `v`, `(?![\w.-])` suffix guard so `12.9.6-rc1`/`12.9.6.1` are probe failures), stdout only. It also carries the r94 default: `--limine-version` defaults to `auto`, so ERA-DEFAULT (flag omitted) probes the real `limine` in the sandbox (12.9.4, era A). It **reads 98/98 `met`, 392 cases, 0 error rows** (`f1.json`, `f1b.json`), with `REFUSAL-VERSIONS-10DIGIT` 4/4 and `AUTO-PROBE-SHAPES` 4/4.

So f1 certifies the 1–9-digit bound and the suffix guard as written in the docstring: a docstring-faithful implementer does reproduce them. The 98/98 does *not* mean the docstring fully specifies the landed gate. The independent gate differs from the landed gate on at least one clause the battery never samples, and still reads `met`:

| # | clause | independent (docstring-literal) | landed gate | family that samples it |
|---|---|---|---|---|
| F1-1 | R5 ESP containment for `..` out of `--esp` | `boot():/../outside.bin#<b2>` → `OK`, `HEALTHY`, rc 0 (hashes a file outside the ESP) | `LP-UNRESOLVED`, `CANNOT-EVALUATE`, rc 2 | **none** |

F1-1 is measured (`amb/traversal.conf`, sha256 `c791b2f8…ece62`, `amb/outside.bin`, sha256 `95d01052…9d3194`): the docstring-faithful gate hashes a file outside the ESP and calls the config `HEALTHY`; the landed gate refuses with `LP-UNRESOLVED`. R5's text ("no regular file at ESP/path") never states the containment, and the "Not modelled" list does not name it. This is a specification gap, not a bend: the instrument was not touched. (Carried from r93; still open in r94.)

Smallest safe correction: add the containment clause to R5 (a path whose `realpath` leaves `--esp` is `LP-UNRESOLVED`; a lane hardening, not a Limine rule) **and** one TRAVERSAL family, or list it explicitly under "Not modelled". As written, a gate that follows `..` outside the ESP can be certified `met`.

Note on inference: the docstring never states the numeric 1–9 bound inside R1–R10/V1–V4/U1 (the only occurrences of "digit/bound/cap" are in the C1 claim paragraph: "the 9-digit component cap", "refusal bound `<= 10`"). f1's `> 9` cut is inferred from that claim wording — a length check, not a value check, because V2 refuses a component above the published bound even when `int()` normalization would make it digit-identical, while `12.09.4` normalizes to `12.9.4`. A docstring reader who inferred `<= 10` would fail `REFUSAL-VERSIONS-10DIGIT` 4/4 (accepting `1234567890.0.0`); the landed gate's `len(p) <= 9` and f1's agree.

## 2. Source-reading forger (f2)

`f2-source-reader.py` (sha256 `885804d2a1f24a3b2599341ca03c894cbc3010590088a89b2cb917df2f7e6492`) is the r93 f6 precedent adapted to r94: `probe_limine_version()` never executes `limine --version`; it reads `<cwd>/bin/limine` source and applies the V4 grammar to its text (`exit 1` → failure; first `Limine X.Y.Z` whose next character is not a word char, `-` or `.` wins; stdout lines only, so the `>&2` copy never wins). It reads **98/98 `met`, 392 cases, 0 error rows** (`f2.json`, `f2b.json`), with `REFUSAL-VERSIONS-10DIGIT` 4/4, `AUTO-PROBE-SHAPES` 4/4, `AUTO-ERA-A` 4/4, `AUTO-ERA-B` 4/4, `AUTO-PROBE-FAIL` 4/4, `ERA-DEFAULT` 4/4.

Yes, it still reads 98/98. The families it defeats: none in the roster — it defeats the *mechanism* clause of V3/V4 ("runs `limine --version`"), which no family in the roster observes. The r94 hardening that was supposed to close it (decoy line `# Limine 12.9.2 (fixture metadata)` before the echo) did not land in the battery's `build()`: the shapes fake is `echo "Limine 12.9.6-rc1"` plus a stderr copy, and the era fakes are `echo "Limine <version>"` — the literal source still carries the answer. f2's upgrade (suffix guard + stdout-only lines applied to source text) is exactly what lets it pass the new `AUTO-PROBE-SHAPES` family without executing anything.

Clause that would kill it: an execution receipt — a writable marker the fake touches when executed (r93 CriticForgers §3 correction 2, still open), or a fake whose source is *not* the answer (e.g. a decoy version line before the echo, or `printf` assembled at runtime). The decoy-line hardening alone (correction 1) would kill f2's first-`X.Y.Z` source reader but not a reader that parses the echo line specifically.

## Verdict
My evidence **supports** C1's family-level discrimination for `REFUSAL-VERSIONS-10DIGIT` (f1 98/98, 4/4 on the family; a `<= 10` gate fails it) and `AUTO-PROBE-SHAPES` (f1/f2 rc-64 4/4; a lenient probe fails it), and C2's result-level probe families (`AUTO-ERA-A`/`AUTO-ERA-B` kill f3's hardcoded era 4/4, `ERA-DEFAULT` passes f1's real probe 4/4), and reproduces the landed gate's 98/98 `met` baseline (392 cases, 0 error rows). It **falsifies** two statements attached to C2/the battery docstring: (i) that the battery certifies the gate "runs `limine --version`" — `f2`, which only reads `<cwd>/bin/limine` source, reads `met` 98/98, so V3/V4 certifies the observable result, not the mechanism; (ii) that "Fixtures carry no answer" for the AUTO families — the fake's literal source encodes the expected version/refusal, and the r94 `AUTO-PROBE-SHAPES` fake (`echo "Limine 12.9.6-rc1"` + stderr copy) is still readable as source. It also shows the documented R5 does not cover the landed gate's ESP-containment hardening: a docstring-faithful gate escapes `--esp` and still reads `met` (`amb/traversal.conf` → `OK`/`HEALTHY` independent vs `LP-UNRESOLVED`/rc 2 gate).
