## C1 — one observed root case, then the general invariant

**Baseline gap.** `probe_packages()` reads `pacman -Qq/-Qkk/-Qm` and pacman configuration, emits its evidence in `PKG_NOTE`, and degrades for sampled drift, foreign-baseline changes, or pins (`tools/tsukuroi-census.sh:529-685`). It does not inspect `/`; [inference from the baseline code] the census therefore has 0 root-metadata findings, with the requested goal being one measured finding. The source note reports `pacman -Qo /` → `No package owns /` and a filesystem-mtree sweep → 0 root-directory entries, then infers that `pacman -Qkk` has no root-mode baseline (`corpus/knowledge/snapper-eacces-mechanism.md:13`). This is the precise unowned-metadata seam; it is not a claim that all package checks are blind.

**Concrete case.** The existing note records `stat -c '%a %U:%G' /` → `555 root:root`, and `getfacl -p /` → owner/group/other have `r-x` only (`snapper-eacces-mechanism.md:9`). It also records the service as `User=root`, bounded to `CAP_SYS_ADMIN`, and eight `errno:13` journal matches (`:10-11`). This supports a root owner-write-absent finding and a plausible DAC contribution, but the note labels causation inference, not syscall proof (`:14`). It does **not** show a read-only mount. The one observed value `0555` must not become a hard-coded predicate.

**Generalized C1 contract.** Append stable numeric root metadata evidence to the existing `PLANE packages` note (preferred: this is where the unowned `-Qkk` gap belongs), e.g. `root_mode=... root_uid=... root_gid=...` plus a separately explicit owner-write state. Keep this as one of the existing six planes: `main()` currently emits six `PLANE` lines and six rollup keys (`tools/tsukuroi-census.sh:2377-2393`); do not add a seventh plane or change the rollup shape. `root_mode` should be interpreted by the owner-write bit, not by matching literal `555`: `0755` has owner write and is not this finding; `0555` lacks it and must make packages `DEGRADED`; another mode with owner-write absent should behave the same. UID/GID are observations, not an unstated new pass/fail policy or proof of package ownership. A failed metadata read must never print a healthy-looking default: represent `root metadata=unknown` explicitly and worsen the assessable packages plane, or use `BLOCKED`; both satisfy the dispatch contract. Do not label owner-write absence “read-only filesystem.”

The existing fixture convention is suitable: a bounded path override belongs with the host-path overrides (`:286-300,326-330`); each hermetic `check()` asserts exit, aggregate verdict, requested evidence, and fixture immutability (`:1750-1809`). Coverage should distinguish the requested `0755`, `0555`, and metadata-unreadable states. To catch literal-value overfit, also exercise a different mode with the owner-write bit clear (or, at minimum, assert the bit rule rather than `mode == 0555`). Make the unreadable case exercise the metadata-probe failure path, not merely assume that a missing path proves permission denial. Keep package-root observation independent of `pacman -Qkk` rc and existing package drift.
