## 1. Primary Source Examination: Canonical man HTML (`systemd.exec.5`)

Reopened upstream URL: `https://man.archlinux.org/man/systemd.exec.5` (native HTML rendering generated by `archmanweb` using `mandoc`).

### A. Heading Hierarchy vs. Option Elements
- **Section Heading (`.Sh`)**:
  `<section class="Sh"><h1 class="Sh" id='SANDBOXING'><a class='permalink' href='#SANDBOXING'>SANDBOXING</a></h1>`
  `archmanweb`/`mandoc` attaches element IDs and permalink anchor tags exclusively to top-level section headers (`<h1 class="Sh" id="...">`).
- **Option Labels within Section**:
  `<p class="Pp"><i>ProtectSystem=</i></p>`
  Option headers inside sections are formatted as paragraph tags containing italicized text (`<i>ProtectSystem=</i>`). They lack native `id="..."` attributes, lack `<a class='permalink'>` tags, and lack native fragment identifiers in the generated HTML.
- **Option Body**:
  `<div class="Bd-indent">Takes a boolean argument or the special values &quot;full&quot; or &quot;strict&quot;. ...</div>`
  Contains the definition immediately following the option paragraph.

### B. The Fragment Anchor Divergence
- Multiple subagents/reports in round 14 and round 15 attempted to construct or expect a native fragment `#ProtectSystem=`.
- Inspection of the raw HTML source confirms that no `<a name="ProtectSystem=">` or `<... id="ProtectSystem=">` exists in the DOM. The only native URL fragment resolving to an element ID in this section is `#SANDBOXING`.
- Therefore, asserting a native URL anchor `#ProtectSystem=` is technically ungrounded against the archmanweb markup, though external tools or URI conventions occasionally synthesize informal fragment notation.

### C. Source Revision & Footer vs. Host Runtime Distinction
- **Footer Metadata**:
  `<table class="foot"><tr><td class="foot-date"></td><td class="foot-os">systemd 262.1</td></tr></table>`
  The footer explicitly states `systemd 262.1`.
- **Sidebar Package Information**:
  `<dd><a href="https://www.archlinux.org/packages/core/x86_64/systemd/">core/systemd</a></dd><dd>262.1-1</dd>`
- **Distinction from Host State**:
  The man page footer (`systemd 262.1`) specifies the version of the documentation artifact published in Arch [core]. It does not represent host runtime state (where `pacman -Q systemd` measures `261.2-1`). Documentation sources must cite the footer version (`systemd 262.1`) as the document's revision boundary, keeping it strictly decoupled from local host packages or operational state.

## 2. Instability of Reader Line Numbers

Prior round records demonstrate that line numbers are non-canonical presentation artifacts:
1. **Round 14 Citation**: `source-scope-correction-r14.md:32` cited "rendered lines 1266-1267" for S044.
2. **Round 14 Verifier Spot-Check**: In `round-14-verifier-spotcheck.md:233-239`, the non-author verifier found that in its reader, lines 1266-1267 corresponded to the `AF_UNIX` socket limitation sentence, while `ProtectSystem=` was at line 1270 and the definition at 1272-1273.
3. **Plain Text (`.txt`) Reader**: In `https://man.archlinux.org/man/systemd.exec.5.en.txt`, `SANDBOXING` begins at line 1372 and `ProtectSystem=` definition appears at lines 1401-1402.
4. **Raw HTML DOM**: In `systemd.exec.5.html`, `ProtectSystem=` begins at line 1359.
5. **Mechanism of Instability**: Line coordinates vary based on:
   - Viewer window dimensions and column reflow width (e.g. 80 columns vs 100 columns vs terminal width).
   - Format engine (`mandoc -Tutf8`, `groff`, lynx/w3m text dumping, archmanweb HTML templates).
   - Header/footer margins, navbar inclusions, and CSS box styling.

Relying on bare line numbers introduces spurious verification failures and phantom discrepancies.

## 3. Recommended Stable Anchor Conventions

To ensure reproducible, resilient cross-round locators across the corpus:

1. **Structural Path Locator (Primary)**:
   Always cite the path from manual volume to section to option label:
   `systemd.exec(5) > SANDBOXING > ProtectSystem=`
   (alternatively: `systemd.exec(5) § ProtectSystem= (under SANDBOXING)`).
2. **Omit Native HTML Fragment Assertions for Sub-Section Options**:
   Because mandoc only creates element IDs for section headings (`#SANDBOXING`), do not assert `#ProtectSystem=` as an existing DOM fragment. If a section-level URI anchor is cited, use `https://man.archlinux.org/man/systemd.exec.5#SANDBOXING`.
3. **Explicit Footer/Revision Citation**:
   Always couple the URL with the documented footer version:
   `footer systemd 262.1, opened 2026-10-20`.
   Explicitly maintain the distinction between doc revision and installed package revision.
4. **Verbatim Anchor Quote (Invariance Core)**:
   Anchor the definition using the exact, whitespace-normalized first definition sentence (≤25 words):
   > "Takes a boolean argument or the special values \"full\" or \"strict\"." (11 words)
5. **Retirement / Qualification of Line Numbers**:
   Completely retire bare line numbers in active knowledge entries (`source-locator-clarification-r15.md` / `.json`). Where historical line numbers must be cited (e.g. in supersession notices referencing r14), label them explicitly as `reader-dependent lines (unverified across alternate renderers)`.
